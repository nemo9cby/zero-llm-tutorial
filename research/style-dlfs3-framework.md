## 0. 速览：给主编的 10 条结论

1. **两级结构**：5 个阶段 × 60 个步骤。
   - 每步只增加**一种能力**，正文约 7 页，2–5 节。
   - 每步对应一个能独立运行的 `steps/stepNN.py`。
2. **步骤首尾高度模板化**：开头是"在上一个步骤……本步骤将……"，结尾是"本步骤到此结束。在下一个步骤，我们将……"。
   - 结尾常留下一个**遗留问题**，形成"问题→解决→新问题"的链条。
3. **讲概念的固定节拍**：设问（"什么是X？"）→ 类比或示意图 → 最小代码 → **运行结果框** → 推广或改进。
4. **验证写在叙述里**，主要有五种：
   - 金标准数值反复复现：3.297442541400256 在步骤 6–9 中出现了 5 次。
   - 与数值微分对照。
   - 用 assert 逐级回溯计算图。
   - unittest + 梯度检验（步骤10）。
   - 形状检查（步骤41）和计算图可视化（步骤25–26、35）。
5. **测试只讲一次**：步骤10 之后，作者明说"省略了测试相关的说明"。**网页版应反过来做：每步都有一个 ✓ 验证块。**
6. **两种旁注图标**：乌鸦表示补充或提示，蝎子表示注意、范围说明或术语约定。难点和"可以跳过"的地方都会明确标出。
7. **阶段收尾**：★★★★★★★★ 分隔线 + 阶段回顾 + 一篇专栏。专栏按字母 A–E 编号，内容偏历史、对比和展望。
8. **理论与实现拆成相邻步骤**：理论篇/实现篇、准备篇、手动计算/自动计算、(1)(2)(3) 连载，以此控制单步的认知负荷。
9. **语气**：用"我们"营造同行感；短句；常用"具体来说/换言之/准确来说"；幽默很轻。新术语用**粗体加英文括注**。
10. **本书没讲 LLM 的核心概念**：embedding、word2vec、attention、seq2seq、LayerNorm、Transformer、强化学习都不在书里。但它们的**可微积木几乎都有**：get_item、matmul、softmax、sum/broadcast、Dropout、RNN/LSTM。所以很适合作为"如果你读过 DLFS3，你已经会写 X 的反向传播"的锚点，详见 §5。

### 2.1 粒度统计（据 PDF 书签计算）

  - 理论型步骤图很多：步骤5 有 5 张，步骤15 有 8 张，步骤29 有 5 张以上。
  - 实现型步骤图很少：步骤44 没有图，步骤52 只有 1 张截图。
- **起点极小**：步骤1 只有 3 行代码。前言（p.xx）："各步骤的内容都是独立完成的，代码可以实际运行。在本书中，我们会通过这种增量开发的方式来逐步创建DeZero，一边运行代码一边加深理解。"
- **结构的来历**（后记 p.474/P497）："大约在开始写作三个月之后，我意识到只能以渐进的方式一边开发一边讲解。"作者还提到写作时在拼装一套 70 期的 Robi 双足机器人周刊。这种"每期装一个零件"的形态，就是 60 步结构的原型。

### 2.2 单步骨架（以步骤6 为例，p27–31）
1. **标题**：直接写能力名，如"手动进行反向传播"。
2. **导语（1–3 句）**：承接上一步，说明本步目标。"上一个步骤介绍了反向传播的机制。本步骤将扩展现有的Variable类和Function类，实现通过反向传播来求导的功能。"
3. **x.1–x.3 逐个扩展类**：每段代码都带文件标签 `steps/step06.py`，新增的代码用阴影标出。
4. **x.4 把功能跑通**：先给出计算图（图6-2），再给代码，最后是"运行结果"框 `3.297442541400256`。
5. **验证**："顺带一提，步骤4的数值微分的结果是3.2974426293330694，这两个结果几乎一样。"
6. **收尾，并引出遗留问题**："但是反向传播的顺序C→B→A是通过编码手动指定的。在下一个步骤，我们会把这项工作自动化。"

各步骤收尾句的变体，原样摘录：
- "这种用法很别扭。在下一个步骤，我们将改进目前的实现……"（步骤11）
- "不过，当前的DeZero还存在一个问题。在下一个步骤，我们将解决这个问题。"（步骤13）
- "本步骤到此结束。这个步骤是整本书中比较难的一个部分。"（步骤16）
- "以上就是本步骤的内容。"（步骤39、45）

### 2.7 可直接借用的"步骤协议"（供网页版每页遵守）
1. **一步一能力**：标题即能力名，导语一句话说清"上一步留下了什么问题，这一步解决什么"。
2. **一步一文件**：对应 dlfs6 的 `chNN/NN_xxx.py`，页面上给出 `uv run chNN/NN_xxx.py`。
3. **一步一个 ✓**：至少一项可复现检查（金标准数值、形状断言、gradcheck、与 PyTorch 对照、或 Modal/RunPod 实测），而且检查本身可以点开运行。
4. **一步一个钩子**：结尾点名遗留问题，接到下一步。
5. **理论与实现分步**：一页里理论和代码都很重时，就拆成相邻两页，标上"理论篇/实现篇"。

## 4. 语言与语气

- **人称**：
  - 主语以**"我们"**为主，营造"一起造框架"的旅程感："下面我们来实现……""我们马上要接触到Define-by-Run的核心了"。
  - 交代写作选择时用**"笔者"**："笔者将在步骤25介绍如何安装Graphviz"。
  - 对读者称**"大家""读者""感兴趣的读者"**。可选内容一律用"感兴趣的读者可以参考……"。
- **句子节奏**：
  - 短句和中句为主，每段 2–4 句。
  - 一句只推进一个事实，大量使用承接词："具体来说""换言之""也就是说""因此""另外""顺带一提""准确来说"。
  - 几乎不用排比或修辞性长句。
- **设问**：
  - 节首用"什么是X？"（变量、函数、导数、迭代器、Dropout）。
  - 转折处用"为什么……呢？答案是……"。
  - 换视角时用"那么从变量的角度来看，函数是什么样的呢？"
  - 设问之后马上作答，不留悬空。
- **精确的谦逊**：反复限定说法，例如"（在一定程度上）""准确来说""更准确地说，这个实现大概率是正确的"。这种语气与"可验证"目标高度契合。我们的教程应保留这种限定词习惯。
- **类比与意象**：
  - 箱子 / 魔法箱子 / 透明箱子（变量）。
  - "父母"、creator（函数创造变量）。
  - "辈分"、generation（拓扑顺序）。
  - "重要人物"（反向传播时对谁求导）。
  - 乐高积木（层的组合，专栏D）。
  - 香蕉形的山谷（Rosenbrock 等高线）。
  - 式子"大爆炸"（符号微分的表达式膨胀）。
  - 速度与摩擦（Momentum）。

  类比总是为了给对象建立心智模型，而不是装饰。
- **幽默**：轻而克制，多是自嘲或吐槽繁琐：
  - "所以我们让Python来做这些无聊的事情吧"（p32）
  - "（虽然可以写成y = Square()(x)，但观感很差）"（p43）
  - "不过大家也知道我每次都会预测错"（后记，谈写作进度）
- **情绪调动**：
  - "让人惊讶的是，有了这两个类，我们就为自动微分打好了基础。"
  - "这一点很有趣"
  - "理解了这个步骤的内容，大家就能很快感受到DeZero的威力了"
  - 阶段末用"下面就进入……吧！"

  情绪调动集中在**阶段导语、阶段收尾和难点之后**，正文里很少。
- **术语引入**：
  - 首次出现时**粗体 + 中文 + 英文括注**，例如：
    - **反向传播（back propagation）**
    - **梯度检验（gradient checking）**
    - 数值微分（numerical differentiation）
    - 可微分编程（differentiable programming）
    - 玩具数据集（toy datasets）
    - 基于时间的反向传播（Backpropagation Through Time, BPTT）
    - 符号式编程（symbolic programming）
  - 缩写当场展开：ndim = number of dimensions，grad = gradient，eps = epsilon，matmul = matrix multiply，im2col = image to column，Mul = Multiply。
  - 换用新叫法时会正式宣布（步骤37 把"张量的导数"改称"梯度"）。
  - 代码标识符一律用等宽字体（`Variable`、`backward`），不翻译。
- **手把手的程度**：很高。
  - 命令行写全（`python -m unittest discover tests`、`pip install cupy`），交代目录结构和每个文件的去处。
  - 但**不重复已讲过的东西**：用"省略"和"兼作复习"控制篇幅。
  - 测试也只教一次，之后交给读者自己写。
- **结构性口头禅**（可直接移植成我们的模板句）：
  - 导语："在上一个步骤……本步骤将……"
  - 收尾："本步骤到此结束。在下一个步骤，我们将……"
  - 阶段收尾："以上就是第N阶段的内容。"
  - 可选内容："感兴趣的读者可以……"
  - 难点："这是本书的难点之一……实际运行代码后，就会理解得越来越透彻。"

## 7. 对本教程的落地建议（摘要）

1. **采用"阶段 / 步骤"两级结构**：每步大约 1500–2500 字加代码（相当于原书约 7 页），一步一个 dlfs6 脚本，一步一个 ✓。
2. **每个阶段设金标准**：固定 seed 的 attention 输出摘要、分词器 round-trip、初始 loss ≈ ln(V)、KV cache 开与关时生成结果一致等。每步顶部显示"金标准仍成立"。
3. **把步骤10 的测试一课提前并常驻**：第一阶段就教 gradcheck 与形状断言，之后每个新算子页都有"gradcheck"按钮（浏览器内 float64），GPU 算子给出 Modal 命令和记录结果。
4. **理论篇与实现篇分页**；"手算 → 自动"成对出现，例如先手推 2×2 attention 的梯度，再用 autograd 核对。
5. **难度和可跳过要明说**：用徽章标出，补充内容默认折叠；专栏放在阶段末。
6. **"如果你读过…"统一组件**：精确到"DLFS3 步骤47.3 / DLFS1 §6.1 / CS336 Lecture N"，同时注明"不读也能继续"。
7. **GPU 部分沿用步骤52 的写法**：同一份代码在 CPU/GPU 间切换（`device`），给出标注硬件的实测对照表，并有云端复跑说明（原书用 Colab，我们换成 Modal/RunPod/Lambda，本地用 3060 Ti 8GB）。
