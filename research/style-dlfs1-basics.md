## 0. 一页结论

1. **核心教学单元是一个闭环**：先抛出动机问句，再给能心算的最小数值例子，在 Python 解释器里一行行运行（输出紧跟在输入下面），从输出里"读出"性质，最后封装成函数或类，回到 MNIST 主线。每个新概念通常在 2–4 页内走完这一圈。
2. **先失败、后修正**是辨识度最高的手法：softmax 先溢出成 `nan` 再减最大值；数值微分先写"不好的实现示例"；学习率先给过大、过小两个反例；权重先问"能不能全设成 0"，再用对称更新说明为什么不行。这和我们"处处可最小化验证"的要求天然契合，因为每一次失败本身就是一条可运行的断言。
3. **日常故事先于抽象**：反向传播从"太郎买 2 个苹果、消费税 10%"讲起。导数先以白话出现（"苹果涨 1 日元，总价涨 2.2 日元"），链式法则随后才登场。
4. **数学按需出场，出场后立刻注释**：每个公式后面紧跟一句"这里，X 表示……"。重推导有三种处理：移进附录（Softmax-with-Loss）、省略但给出自己推导的钥匙（Affine 层靠"形状必须对齐"反推）、只给直观说明并坦白"并不完全正确"（Adam）。
5. **一条贯穿全书的主线**：MNIST 识别精度从 93.52%（第 3 章，加载现成权重做推理）一路走到 98.96%（第 7 章 CNN）和 99.38%（第 8 章深层 CNN）。第 3 章就公开立下"把精度提高到 99% 以上"的目标；与此同时，`common/` 库逐章增长、只增不改。
6. **版式极简**：只有两种图标提示框，乌鸦表示"提示/补充"（正文约 57 处），蝎子表示"警告"（约 11 处）；故事和定义用楷体缩进段；每章以带框的"本章所学的内容"收尾。**全书没有带标题的专栏，也几乎没有章末习题。**
7. **语气**：主语几乎总是"我们"（正文出现 409 次，"你"只有 4 次）。平均句长约 41 个汉字。正文有 63 个问句，感叹句只有 16 个，而且都留给"跑通了"的那一刻。
8. **对 LLM 教程的直接价值**：softmax 的溢出对策可以接到 attention 的缩放与 `-inf` 掩码；标签索引版交叉熵 `y[np.arange(N), t]` 正是 next-token loss；`y − t` 就是 logits 的梯度；层的 forward/backward 加 OrderedDict 是 autograd 和 `nn.Module` 的前身；He 初始化和 Batch Norm 对应 GPT 的初始化与 LayerNorm/RMSNorm；ResNet 的快捷结构对应残差流；8.3 节的 GPU、分布式和半精度，则对应我们要在 Modal/RunPod 上跑的混合精度实验。

### P01 章节骨架：开篇缺口 → 各节闭环 → 小结段 → "本章所学的内容"
- **描述**：每章分四块。①开篇 1–3 段：承接上一章并制造一个缺口（常用"好消息/坏消息"，或"上一章……但是……"），给出本章路线图，预告下一章；②若干节，每节内部按 P02 的闭环推进；③"X.Y 小结"用一段话回顾，并指向下一章；④带边框的"本章所学的内容"，列 5–7 条陈述句。
- **出处**：所有章。典型例子：第 3 章开篇 p.37，第 5 章开篇 p.121。
- **例句**：「关于感知机，既有好消息，也有坏消息。」（p.37）
- **Web 改编**：每章页面固定四个组件：`ChapterOpener`（"上一章留下的问题"卡片加可点击的路线图）→ 各节 → `SectionRecap` → `Takeaways`。`Takeaways` 的每一条都链接到一个可运行的验证单元，页面上提供"全部验证"按钮。

### P02 概念引入的闭环：问句 → 最小例子 → REPL → 观察 → 归纳 → 封装
- **描述**：新概念几乎总按同一顺序展开：先提出具体问题；给出能心算的最小数值；在解释器里逐行运行，输出紧跟其后；从输出中归纳性质；最后写成函数或类，供后文复用。公式要么在最小例子之后出现，要么出现后立刻用代码"照抄"一遍。
- **出处**：softmax（3.5.1–3.5.3，p.64–68）。顺序是：式 (3.10) → `exp_a`、`sum_exp_a`、`y` 三步 REPL → 定义 `softmax()` → 溢出 → 修正 → "输出总和为 1，所以可以解释为概率" → "函数单调，所以推理时可以省略"。
- **例句**：「这个Python实现是完全依照式（3.10）进行的，所以不需要特别的解释。」（p.65）
- **Web 改编**：做成"概念卡"组件。上半部分是问题和最小数值；下半部分是可编辑的 REPL（Pyodide 或纯 JS），预置 3–6 行代码；"观察"段落里的每条性质都配一个断言按钮（如 `assert abs(sum(y)-1) < 1e-9`）。读者改了输入，断言会实时重算。

### P03 先失败，后修正（"不好的实现示例"）
- **描述**：故意先写朴素或错误的版本，让读者亲眼看到失败（`nan`、`inf`、发散、对称），再解释原因、给出修正。失败大多用真实输出呈现；唯一的例外是"权重全为 0"，只用文字论证（我们的网页版应该补一个可运行的反例）。
- **出处**：
  - softmax 溢出成 `array([nan, nan, nan])`（p.66–67）；
  - 数值微分的"不好的实现示例"：h=10e-50 会被舍入成 0（`np.float32(1e-50)` → 0.0），前向差分也要改成中心差分（p.94–96）；
  - 学习率取 10.0 时发散，取 1e-10 时几乎不动（p.106）；
  - 权重全设为 0 导致对称更新（p.176–177）；
  - 权重 std=1 时，sigmoid 激活值被挤到 0 和 1 两端（p.178）；
  - 阶跃函数先只支持标量，后改成支持数组（p.43）；
  - 刻意制造过拟合：只取 300 个训练样本，用 7 层网络（p.189）。
- **例句**：「乍一看这个实现没有问题，但是实际上这段代码有两处需要改进的地方。」（p.95）
- **Web 改编**：设计"先跑红、再跑绿"的双按钮单元：先点"运行朴素版"，看到红色的 NaN 或发散；再点"运行修正版"，看到绿色的正确结果。LLM 教程里可以照此设计：attention 不除以 √d 导致 softmax 饱和、fp16 下 logits 溢出、忘加因果掩码导致"偷看未来"、未缩放的残差导致激活爆炸。

- 正文有 63 个问句，用法有三种：做节标题（P15）、开段引出动机（"为什么……呢？"）、出拼图题（第 2 章"请思考一下……这里给大家一个提示"）。
- 感叹句只有 16 个，全部留给兑现时刻，例如「感知机的运行原理只有这些！」（p.22）、「果然和我们预想的输出一样！」（p.25）、「神经网络的确在学习！」（p.116）。

**类比与幽默**
- 类比的清单见 P05。幽默很克制，属于会心一笑的类型："性情古怪的探险家"；回答"幸福指数是 10.23"会把人吓一跳；"变色龙演员"；前言里那句"还需要快乐以外的其他什么理由吗？"。没有段子，也没有网络用语。

**术语怎么引入**
- 首次出现时用粗体中文加英文括注，如"激活函数（activation function）""梯度消失（gradient vanishing）""过拟合（over fitting）"。
- 有些术语直接保留英文：mini-batch、epoch、one-hot、Affine、Dropout、Batch Norm、im2col、SGD。
- 缩写一定讲清来源，例如："SGD来源于随机梯度下降法的英文名称的首字母"；"AdaGrad的Ada来自英文单词Adaptive"；im2col 是 "image to column" 的缩写。
- 同义词会主动对齐，例如"本书中，'神经元'和'节点'两个术语的含义相同"。

**手把手程度**
- NumPy 和代码细节讲得很细：`np.random.choice`、`argmax(axis=1)`、`reshape(-1)`、`transpose`、`OrderedDict`、`lambda` 都会停下来解释，还会补充 Python 的边角知识（pickle、`sys.path.append(os.pardir)`）。
- 数学讲到中等深度：每个公式配一行注释，导数从马拉松讲起。
- 理论证明讲得很少：一律延后、省略或给出引用。
- 实验结论总带一句"结果会随超参数和网络结构而变"之类的提醒，不把单次实验当定律。

**译本特征（改编时要注意）**
- 全书有 15 处"——译者注"，用来解释日本的文化事物或补充数学背景，例如"方向导数 = cos(θ) × 梯度"，以及 epoch 的一般做法应是"先打乱数据再顺序切批"。
- 例子里带有日本语境：日元、10% 消费税、人名"太郎"、竹筒敲石、木屐、关东地区的收视率。中文网页版可以本地化，或者保留原样并加悬停注。
- 中文版代码有几处排印错误，网页版必须以可运行的源码为准，**不要从 PDF 转录**。例如 p.114 的 `one_hot_ laobel`；p.225 的 `weitght_int_std`；p.226 写成 `self.last_layer = softmaxwithloss()`，后文却用 `self.lastLayer`；p.147 把图 5-25 误写成"图2-25"。

## 7. 给本项目的落地建议（摘要）

1. **把 P01 和 P02 定为全站模板**：章节四段式加概念闭环，每个闭环的"观察"一步都必须带一条可运行断言。
2. **一条主线，一个仪表盘**（P10）：全程用同一份小语料和同一个验证集指标，代码库只增不改，结构上对齐 dlfs6 的 ch01（分词）→ ch02（attention/GPT-2）→ ch03（预训练/SFT/GRPO）→ ch05（RoPE/RMSNorm/SwiGLU/KV cache）→ ch06（AdamW/调度/混合精度/DPO）。
3. **每章至少一个"先跑红再跑绿"**（P03），至少一个"梯度确认"式的交叉验证（P17）。
4. **故事题本地化**（P04）：保留斋藤"能心算"的尺度，换成中文读者熟悉的场景。
5. **callout 只用四种外加"验证"**（P11），保持稀疏。
6. **用"如果你读过"组件接上 DLFS1 的锚点**（§4）：本书没讲的概念（autograd、word2vec/attention、策略梯度）统一指向 DLFS2/3/4 的档案，不要在这里臆造页码。
7. **在斋藤止步的地方继续往前走**：他写"不进行 GPU 实现"，我们的 GPU 部分要能在 Modal/RunPod/Lambda 上真跑，同时保留他的坦白态度（P19），写明耗时、费用、随机波动和"直观/精确"标签。
8. **不要从 PDF 转录代码**：中文版有排印错误，且有 `np.int` 这类过时 API；一律以能在 uv 环境里跑通的源码为准。
