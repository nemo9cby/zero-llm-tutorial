CS336 对照总表

斯坦福 CS336 与本书走的是同一条路：从分词器、Transformer，一直到强化学习后训练。这一页把两边的部件逐个对应起来，再把 DLFS6 的代码接到 CS336 作业 1 的公开测试上，看看能通过多少、差在哪里。

斯坦福大学的 CS336《从零开始的语言建模》（Language Modeling from Scratch，Tatsunori Hashimoto 与 Percy Liang 主讲）是与本书路线最接近的公开课程。两者的路线几乎一样：先写分词器，再搭 Transformer，然后训练、评估，最后做对齐。不同的是分量。CS336 有 5 个大作业，要求学生连 nn.Linear 和 softmax 都自己写；DLFS6 则放手使用 PyTorch 的现成部件，只把关键的几样亲手实现一遍，换来三个用单张显卡就能训练出来的机器人：CodeBot 在消费级显卡上 42 分钟就能预训练完，StoryBot 在一张 H100 上只要 16 分钟，WebBot 则要一张 H100 跑约 10.4 小时（验证 X.1-d）。

对照下来，最让人意外的是两者靠得有多近。StoryBot 的模型形状、数据和 token 预算都与 CS336 作业 1（下文简称 A1）的 TinyStories 实验相同，连数据文件都逐字节相同；把 A1 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 10^{-5}。所以这一页不只是一张链接表，还有一次实打实的“对拍”。

本页先给出逐组件的对照表（X.1），然后把 DLFS6 的代码接到 A1 的 48 个测试上，逐项看结果（X.2）；接着整理两边在设计上的取舍，以及每个取舍带来的后果（X.3）；最后记录课程从 2025 到 2026 年的变化（X.4），并给出读完本书之后在 CS336 里接着读什么（X.5）。

注关于 CS336 的作业规则

CS336 2026 年的每个作业仓库都附有写给 AI 助手的规则：只做助教，不替学生写答案。本页只用课程公开的测试去衡量 DLFS6 自己的代码，不提供任何作业题的解答。需要说明的是，BPE 与分词器这两部分不涉及 torch.nn：DLFS6 第 4 章的代码加上本页的修改和适配层，就能通过 A1 的 BPE 测试。正在修 CS336 的同学，请按课程的规定独立完成作业，不要使用这里的代码。文中关于 CS336 的事实都取自课程网站与作业仓库（链接见各节），查证日期为 2026-10-11。

X.1 逐组件对照表

先确认一件事：StoryBot 的预训练与 A1 的 TinyStories 实验，模型形状、数据和 token 预算都相同。下表是 A1 讲义规定的那几项，以及 ch06/05_pretrain.py 里的取值：

超参数 A1 的 TinyStories 实验 ch06/05_pretrain.py
词表 10,000 vocab_size = 10000
上下文 256 context_len = 256
残差流宽度 d_model 512 embed_dim = 512
头数 16 n_head = 16
层数 4 n_layer = 4
FFN 中间层 d_ff 1344 ff_dim = 1344
RoPE θ 10,000 theta = 10000
训练的 token 总数 327,680,000 40,000 步 × 32 × 256

A1 没有规定的是训练的细节。讲义只给出 token 总数，学习率、warmup、batch 大小、AdamW 的其他超参数与 weight decay，都要学生自己“反复试验，找到合适的默认值”。DLFS6 选的是最大学习率 1e-3、warmup 200 步、batch 32、torch.optim.AdamW 的默认值，学习率按线性衰减到 0（D2Z）；A1 的测试则要求 cosine 调度。初始化等其他差别见 X.3。

A1 还为只有 CPU 或 Apple 芯片的同学准备了一个“低资源”版本（A1 讲义 v26.0.3 的 §7.2）：token 总数减到 4,000 万，验证 loss 的达标线放宽到 2.00。课程组自己在 M4 Max 上的参考运行是 32 × 5,000 × 256 = 4,096 万个 token，第 5,000 步的验证 loss 是 1.80。DLFS6 在第 5,000 步保存的 checkpoint（model_iter_5000.pt）恰好能拿来对照：循环变量 i 从 0 数起，保存发生在第 i = 5000 次更新之后，所以它其实更新了 5,001 次，比课程组的参考运行只多 8,192 个 token（0.02%），比 4,000 万的预算多 2.4%。不过它是 D2Z 中途的快照，学习率还在峰值的 88%：

A1 的低资源提示还建议，训练步数缩短时，让学习率调度恰好在最后一步衰减完。所以拿第 5,000 步的 checkpoint 去比 A1 的低资源达标线，条件并不对等，只能作参考。

    step = next(s for s in rep["steps"] if s["script"] == script)
    return step["seconds"], rep["host"]["gpu"]

with open("data/runs/webbot-probe/timing.json", encoding="utf-8") as f:

DLFS6（本教程的小节） CS336 差异
ch01/01–02 字符、字节分词（1.1–1.2） L1；A1 §2.1–2.2 思路相同；CS336 多问了 chr(0) 和逐字节解码的陷阱
ch01/03 BPE 训练（1.3） L1 的 train_bpe；A1 run_train_bpe 平票规则不同：第 1 章取字典里先出现的那一对，第 4 章起比较 token id，A1 比较 bytes（X.2）
ch01/04–05 编解码、特殊 token（1.4–1.5） A1 get_tokenizer DLFS6 的 merge 以 id 对为键，只支持一个特殊 token；CS336 以 bytes 为键，支持多个、可以重叠的特殊 token
ch01/06 预分词（1.6） A1 的正则 PAT 同一个正则字符串
ch01/08–09 评估、编码为 uint16（1.8–1.9） A1 tokenizer_experiments 相同的问题：压缩率、为什么用 uint16
ch02/01–03 软字典、公式、缩放（2.1–2.3） A1 §3 的 softmax 与 Attention DLFS6 从直觉讲起；CS336 默认你已经懂 Attention
ch02/06–08 掩码、多头（2.6–2.8） A1 run_scaled_dot_product_attention、run_multihead_self_attention DLFS6 多了 dropout
ch02/09–10 Transformer 块、GPT-2（2.9–2.10） A1 run_transformer_block、run_transformer_lm（作对照） CodeBot 是 GPT-2 式（LayerNorm、GELU、可学习的位置 embedding、权重共享、bias、dropout），A1 是 Llama 式
ch03/01 预训练（3.1） A1 的数据加载、训练循环 DLFS6 学习率固定、没有 warmup 和梯度裁剪、没有验证集
ch03/02 文本生成（3.2） A1 decoding（温度与 top-p） 仓库里只实现了温度
ch03/03 SFT（3.3） 2025 年 A5 的 SFT；2026 年 A5 的 tokenize_prompt_and_output；补充作业的 SFT 同样是 Alpaca 模板；loss 的归一化方式不同
ch03/09 GRPO（3.5–3.9） 2026 年 A5 的 GRPO 系列；L16 见 X.3

X.2 把 DLFS6 接到 A1 的测试上

A1 的测试是固定的，学生只需要填写 tests/adapters.py 里的 21 个“适配函数”：测试调用它们，它们再调用学生自己的实现。大多数测试是快照测试：用固定的权重和输入算一遍，与课程参考实现保存下来的输出比较，容差逐项写在测试里，比如 RoPE 是 atol=1e-5，整个语言模型是 atol=1e-4, rtol=1e-2。

既然两边的模型形状相同，我们就把 DLFS6 接上去试试。具体做法是写一个适配文件，让每个适配函数调用 DLFS6 里扮演同一角色的代码，分四种情况：

  • DLFS6 自写：DLFS6 亲手实现的部分，比如 StoryBot 的 RoPE、SwiGLU、Attention、整个 GPT，第 6 章的 AdamW 和 get_batch，第 4 章的 BPE 训练与编码。
  • PyTorch 内置：DLFS6 直接调用 PyTorch 的部分，比如 nn.Linear、F.softmax、F.cross_entropy、梯度裁剪。A1 不允许这样做，所以这几项“通过”只说明接口对得上。
  • 设计不同：DLFS6 有对应的东西，但刻意做得不一样，比如学习率调度。
  • 无对应：DLFS6 没有这项功能，比如保存优化器状态的 checkpoint、流式编码、可以重叠的特殊 token。

权重只改名字，不改数值；分词器只在 DLFS6 内部的 id 与 GPT-2 的 id 之间做一次翻译。然后在临时目录里运行 A1 的测试（commit a158843，2026-04-07），整个过程不改动 A1 的任何文件。我们跑了两个版本：DLFS6 原样，以及加上三处小修改的版本。下面是结果，点开每一行可以看到实测误差、失败信息和解释。

三处小修改

RMSNorm 的 eps。StoryBot 的模型写的是 nn.RMSNorm(embed_dim)，不传 eps 时 PyTorch 在 float32 下用 1.19\times10^{-7}，而 A1 的参考实现用 10^{-5}。在单位尺度的输入上，这点差别微不足道：单独测 RMSNorm 只差 1.7\times10^{-5}，单个 Transformer 块差 9.2\times10^{-5}，都在容差之内。可是经过 3 层再加上最后一层 RMSNorm，误差积累到 4.6\times10^{-4}，有几个接近 0 的 logits 超出了 atol=1e-4。改成 nn.RMSNorm(embed_dim, eps=1e-5) 之后，误差降到 1.05\times10^{-5}，缩小了 40 多倍。也就是说，除了这一个 eps，StoryBot 与 CS336 的参考模型计算的是同一个函数。eps 对小激活的影响有多大，可以看勘误页的验证 Z.5-e。

BPE 的平票规则。两个字节对出现次数相同时，选哪一个？DLFS6 比较的是 token 的 id（(count, id0, id1) 最大者），A1 规定比较字节串的字典序。合并产生的 id 按创建的先后编号，与字节串的大小顺序无关，所以两条规则迟早会分叉。下面用一个很小的语料演示：

from collections import Counter

def train(docs, n_merges, rule):
    seqs = [list(d.encode()) for d in docs]
    vocab = {i: bytes([i]) for i in range(256)}
    learned = []
    for new_id in range(256, 256 + n_merges):
        counts = Counter(p for s in seqs for p in zip(s, s[1:]))
        if rule == "dlfs6":
            best = max(counts, key=lambda p: (counts[p], p[0], p[1]))                 # 比较 id
        else:
            best = max(counts, key=lambda p: (counts[p], vocab[p[0]], vocab[p[1]]))   # 比较 bytes
        vocab[new_id] = vocab[best[0]] + vocab[best[1]]
        learned.append(vocab[new_id].decode())
        merged = []
        for s in seqs:
            out, i = [], 0
            while i < len(s):
                if i + 1 < len(s) and (s[i], s[i + 1]) == best:
                    out.append(new_id); i += 2
                else:
                    out.append(s[i]); i += 1
            merged.append(out)
        seqs = merged
    return learned

docs = ["zzq"] * 3 + ["zz"] * 3 + ["aaq"] * 3 + ["aa"] * 2
print("按 id   ：", train(docs, 3, "dlfs6"))
print("按 bytes：", train(docs, 3, "cs336"))
assert train(docs, 3, "dlfs6")[2] == "aaq" and train(docs, 3, "cs336")[2] == "zzq"

def get_lr(it, max_lr, warmup_iters, max_iters):              # ch06/03_lr_scheduler.py
    if it < warmup_iters:
        return max_lr * (it / warmup_iters)
    if it < max_iters:
        progress = (it - warmup_iters) / (max_iters - warmup_iters)
        return max_lr * (1.0 - progress)
    return 0.0

这不是错误，而是一个有依据的选择：把学习率线性衰减到 0 的做法有专门的研究（Bergsma 等，2025，arXiv:2502.15938）。从代码上看，D2Z 的 get_lr 只需要最大学习率、warmup 步数和总步数，不必再决定 min_lr 与 cosine 的周期。

checkpoint。A1 要求保存模型、优化器状态和迭代次数，恢复后能精确地接着训练；DLFS6 的 GPT.save 只保存权重和构造参数，够用来生成和继续微调，但不能精确续训。

流式编码。A1 要求分词器提供 encode_iterable，在 1MB 的内存限制下逐行编码大文件。DLFS6 换了一条路：把大文件切块，多进程编码，缓存到磁盘，最后拼成 uint16 的 memmap（4.7 节）。

可以重叠的特殊 token。A1 要求同时支持 <|endoftext|> 与 <|endoftext|><|endoftext|>，并优先匹配更长的那个；DLFS6 只有一个结束 token。

另外，分词器测试里所有 *_matches_tiktoken 的测试，除了流式的那一项，全都通过了：DLFS6 第 4 章按 rank 合并的编码器，配上一层 id 翻译，在 A1 的全部样例文本上与 tiktoken 的 GPT-2 编码逐 id 相同。

def test_cs336_storybot_initial_logit_scale(dlfs6_path):

    ~ ln V + sigma^2 / 2. The loss is the expectation over a uniformly random target, taken exactly for every row
    (logsumexp minus the row mean), not a sampled cross-entropy: no sampling noise, so a tight tolerance holds."""
    from storybot.model import GPT

    for seed in (0, 1, 2):
        torch.manual_seed(seed)
        m = GPT(10000, 256, 512, 16, 4, 1344).eval()
        ids = torch.randint(0, 10000, (4, 64))
        with torch.no_grad():
            logits = m(ids)
        sigma = logits.std().item()
        ce = (torch.logsumexp(logits, -1) - logits.mean(-1)).mean().item()

def adam(grad_fn, w, steps=200, lr=1e-2, b1=0.9, b2=0.999, eps=1e-8):
    m, v = np.zeros_like(w), np.zeros_like(w)
    for t in range(1, steps + 1):
        g = grad_fn(w)
        m, v = b1 * m + (1 - b1) * g, b2 * v + (1 - b2) * g * g
        w = w - lr * (m / (1 - b1**t)) / (np.sqrt(v / (1 - b2**t)) + eps)
    return w

rng = np.random.default_rng(0)
A, b = rng.normal(size=(20, 5)), rng.normal(size=20)
grad = lambda w: A.T @ (A @ w - b)                 # 0.5·||Aw − b||² 的梯度
w0 = np.zeros(5)
w_full, w_small = adam(grad, w0), adam(lambda w: grad(w) / 512, w0)

第四，DPO 在训练开始时的 loss 恰好是 \ln 2，两边都一样。DPO 的 loss 是

L = -\log\sigma\Big(\beta\big[\big(\log\pi_\theta(y_w\mid x) - \log\pi_\text{ref}(y_w\mid x)\big) - \big(\log\pi_\theta(y_l\mid x) - \log\pi_\text{ref}(y_l\mid x)\big)\big]\Big)

这里，x 是提示，y_w 与 y_l 分别是更好的回答（chosen）和更差的回答（rejected），\pi_\theta 是正在训练的策略，\pi_\text{ref} 是参考模型，\beta 控制偏离参考模型的代价，两边都取 0.1。训练开始时策略就是参考模型，两个圆括号都是 0，\sigma(0) = 0.5，于是 L = -\log 0.5 = \ln 2 \approx 0.6931。如果策略把更好回答的对数概率提高了 5 nats，方括号里是 5，乘上 β 是 0.5，L = \log(1 + e^{-0.5}) \approx 0.474。这个 loss 的推导见附录 E。

验证 X.3-eπ = π_ref 时，DPO 的 loss = ln 2 ≈ 0.6931；更好的回答多 5 nats 时降到 0.474

def dpo_loss(policy, ref):
    z = beta * ((policy["chosen"] - ref["chosen"]) - (policy["rejected"] - ref["rejected"]))
    return z, np.log1p(np.exp(-z))                         # −log σ(z)

把 DLFS6 接到 CS336 A1 的测试上，结果比预想的还要整齐：除去 2 个只在 Linux 上运行的内存测试和 1 个取决于机器负载的速度测试，原样通过 35 个；失败的 10 个里，5 个只差一处小修改（RMSNorm 的 eps、BPE 的平票规则、get_batch 的上界），改完全部通过；另外 5 个是刻意的设计差异或者 DLFS6 没有的功能。最有分量的结论是：把 CS336 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 10^{-5}；而按书原样训练出来的 StoryBot，也通过了 A1 的验收线。一本书、一门课，用不同的方式写出了同一个模型。
