斯坦福大学的 CS336《从零开始的语言建模》（Language Modeling from Scratch，Tatsunori Hashimoto 与 Percy Liang 主讲）是与本书路线最接近的公开课程。两者的路线几乎一样：先写分词器，再搭 Transformer，然后训练、评估，最后做对齐。不同的是分量。CS336 有 5 个大作业，要求学生连 `nn.Linear` 和 `softmax` 都自己写；DLFS6 则放手使用 PyTorch 的现成部件，只把关键的几样亲手实现一遍，换来三个用单张显卡就能训练出来的机器人：CodeBot 在消费级显卡上 42 分钟就能预训练完，StoryBot 在一张 H100 上只要 16 分钟，WebBot 则要一张 H100 跑约 10.4 小时（[验证 X.1-d](#v-X.1-d)）。

对照下来，最让人意外的是两者靠得有多近。StoryBot 的模型形状、数据和 token 预算都与 CS336 作业 1（下文简称 A1）的 TinyStories 实验相同，连数据文件都逐字节相同；把 A1 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 $10^{-5}$。所以这一页不只是一张链接表，还有一次实打实的“对拍”。

本页先给出逐组件的对照表（X.1），然后把 DLFS6 的代码接到 A1 的 48 个测试上，逐项看结果（X.2）；接着整理两边在设计上的取舍，以及每个取舍带来的后果（X.3）；最后记录课程从 2025 到 2026 年的变化（X.4），并给出读完本书之后在 CS336 里接着读什么（X.5）。

## X.1 逐组件对照表

先确认一件事：StoryBot 的预训练与 A1 的 TinyStories 实验，模型形状、数据和 token 预算都相同。下表是 A1 讲义规定的那几项，以及 `ch06/05_pretrain.py` 里的取值：

| 超参数 | A1 的 TinyStories 实验 | `ch06/05_pretrain.py` |
|---|---|---|
| 词表 | 10,000 | `vocab_size = 10000` |
| 上下文 | 256 | `context_len = 256` |
| 残差流宽度 | `d_model` 512 | `embed_dim = 512` |
| 头数 | 16 | `n_head = 16` |
| 层数 | 4 | `n_layer = 4` |
| FFN 中间层 | `d_ff` 1344 | `ff_dim = 1344` |
| RoPE θ | 10,000 | `theta = 10000` |
| 训练的 token 总数 | 327,680,000 | 40,000 步 × 32 × 256 |

A1 没有规定的是训练的细节。讲义只给出 token 总数，学习率、warmup、batch 大小、AdamW 的其他超参数与 weight decay，都要学生自己“反复试验，找到合适的默认值”。DLFS6 选的是最大学习率 1e-3、warmup 200 步、batch 32、`torch.optim.AdamW` 的默认值，学习率按线性衰减到 0（D2Z）；A1 的测试则要求 cosine 调度。初始化等其他差别见 X.3。

A1 还为只有 CPU 或 Apple 芯片的同学准备了一个“低资源”版本（[A1 讲义](https://github.com/stanford-cs336/assignment1-basics) v26.0.3 的 §7.2）：token 总数减到 4,000 万，验证 loss 的达标线放宽到 2.00。助教自己在 M4 Max 上的参考运行是 32 × 5,000 × 256 = 4,096 万个 token，第 5,000 步的验证 loss 是 1.80。DLFS6 在第 5,000 步保存的 checkpoint（`model_iter_5000.pt`）恰好能拿来对照：循环变量 `i` 从 0 数起，保存发生在第 `i = 5000` 次更新之后，所以它其实更新了 5,001 次，比助教的参考运行只多 8,192 个 token（0.02%），比 4,000 万的预算多 2.4%。不过它是 D2Z 中途的快照，学习率还在峰值的 88%：

```verify id=X.1-a title="StoryBot 的 token 预算 = A1 的完整预算；第 5,000 步的 checkpoint 与助教的低资源参考运行只差 0.02%，学习率却还在峰值的 88%"
iters, batch, ctx = 40_000, 32, 256              # ch06/05_pretrain.py
print(f"完整预训练：{iters:,} × {batch} × {ctx} = {iters * batch * ctx:,} 个 token")
print(f"model_iter_5000.pt：i = 0 … 5000，共 5,001 次更新 × {batch} × {ctx} = {5_001 * batch * ctx:,} 个 token")
print(f"A1 的低资源预算 {40_000_000:,} 个 token（达标线 2.00）；"
      f"助教的参考运行 32 × 5,000 × 256 = {5_000 * 32 * 256:,}（第 5,000 步 1.80）")
assert iters * batch * ctx == 327_680_000         # A1: TinyStories LM, 327,680,000 tokens
assert 5_000 * 32 * 256 == 40_960_000             # A1 §7.2：助教在 M4 Max 上的参考运行（预算本身是 40,000,000）
assert 5_001 * batch * ctx - 40_960_000 == 8_192 and 8_192 / 40_960_000 < 3e-4
assert round(5_001 * batch * ctx / 40_000_000 - 1, 3) == 0.024   # 比 4,000 万的预算多 2.4%

max_lr, warmup = 1e-3, 200
lr_5000 = max_lr * (1 - (5_000 - warmup) / (iters - warmup))   # ch06/05 的 get_lr
print(f"第 5,000 步的学习率：{lr_5000:.2e}，是峰值的 {lr_5000 / max_lr:.0%}")
assert abs(lr_5000 / max_lr - 0.88) < 0.01

E, L, ff, V = 512, 4, 1344, 10_000
block = 4 * E * E + 3 * E * ff + 2 * E            # Attention 4 个 E×E，SwiGLU 3 个 E×ff，两个 RMSNorm
non_embedding = L * block + E + V * E             # 加上最后的 RMSNorm 与不共享的输出层
print(f"不含输入 embedding 的参数：{non_embedding:,}（A1 写的是“约 17M non-embedding params”）")
assert non_embedding == 17_576_448
```

A1 的低资源提示还建议，训练步数缩短时，让学习率调度恰好在最后一步衰减完。所以拿第 5,000 步的 checkpoint 去比 A1 的低资源达标线，条件并不对等，只能作参考。

那么，StoryBot 达到 A1 的验收标准了吗？A1 要求完整预算下验证 loss 不超过 1.45，低资源预算下不超过 2.00。我们在 Modal 的一张 H100 上原样运行了 `ch06/05_pretrain.py`（运行记录 storybot-h100，16 分钟，1.17 美元）。在完整的验证集上，第 40,000 步的 loss 是 1.304，低于 1.45；第 5,000 步是 1.662，也低于 2.00。完整的曲线和原作者 checkpoint 的数字见 [6.5 节](ch06.html#s6-5)。

```verify id=X.1-b title="运行记录：完整验证集上，第 40,000 步 1.304 ≤ 1.45，第 5,000 步 1.662 ≤ 2.00" files=data/runs/storybot-h100/report.json,data/runs/storybot-h100/05_pretrain.metrics.jsonl

with open("data/runs/storybot-h100/report.json", encoding="utf-8") as f:
    report = json.load(f)
step = report["steps"][0]
with open("data/runs/storybot-h100/05_pretrain.metrics.jsonl", encoding="utf-8") as f:
    rows = [json.loads(line) for line in f]
before = [r["val_loss"] for r in rows if r["it"] <= 5_000][-1]     # 第 4,500 步的那次评估
val_5000 = next(r["val_loss"] for r in rows if r["it"] > 5_000)    # 第 5,000 步评估之后，进度条显示的新值
final = step["final"]["val_loss"]
print(f"{step['script']}：{step['seconds'] / 60:.0f} 分钟，{report['cost_usd']} 美元，补丁 {len(step.get('patches', []))} 处")

assert step["exit_code"] == 0 and not step.get("patches") and val_5000 != before
assert (round(val_5000, 3), round(final, 3)) == (1.662, 1.304)
assert val_5000 <= 2.00 and final <= 1.45
```

开头说的三个机器人的训练时间，也都来自运行记录。WebBot 没有跑完整的预训练，它的时间是用 200 步计时探针推算的：训练按稳定之后的每步用时算，再加上每 1,000 步一次的全量评估，一共 101 次，每次的用时也从探针的日志里读（推算方法见 [9.7 节](ch09.html#s9-7)）：

```verify id=X.1-d title="CodeBot 在 RTX 3060 Ti 上 42 分钟；StoryBot 在 H100 上 16 分钟；WebBot 在 H100 上约 10.4 小时（推算）" files=data/runs/codebot-3060ti/report.json,data/runs/storybot-h100/report.json,data/runs/webbot-probe/timing.json,data/runs/webbot-probe/01_pretrain.log.txt
import json
import re

def seconds(run_id, script):
    with open(f"data/runs/{run_id}/report.json", encoding="utf-8") as f:
        rep = json.load(f)
    step = next(s for s in rep["steps"] if s["script"] == script)
    return step["seconds"], rep["host"]["gpu"]

with open("data/runs/webbot-probe/timing.json", encoding="utf-8") as f:
    timing = json.load(f)
per_step = timing["steady_s_per_step_20_200"]                    # 第 20–200 步的平均秒数
with open("data/runs/webbot-probe/01_pretrain.log.txt", encoding="utf-8") as f:
    rates = sorted(float(r) for n, r in re.findall(r"Evaluating:.*?(\d+)/1969 \[.*?([\d.]+)it/s\]", f.read())
                   if int(n) >= 100)                             # 评估进度条的速度（跳过开头的 100 个 batch）
eval_s = 1969 / rates[len(rates) // 2]                           # 一次全量评估：1,969 个 batch
# 第 1 步的 141 秒已含编译和第 0 步的评估；之后 99,999 步按稳定速度算，再加 100 次评估（共 101 次）
webbot_s = timing["first_step_s"] + 99_999 * per_step + 100 * eval_s
times = {"CodeBot 预训练": seconds("codebot-3060ti", "ch03/01_pretrain.py"),
         "StoryBot 预训练": seconds("storybot-h100", "ch06/05_pretrain.py"),
         "WebBot 预训练（推算）": (webbot_s, "NVIDIA H100 80GB HBM3")}
for name, (s, gpu) in times.items():
    print(f"{name}：{s / 60:5.0f} 分钟（{s / 3600:.1f} 小时），{gpu}")
print(f"WebBot 其中训练约 {100_000 * per_step / 3600:.1f} 小时，101 次评估约 {101 * eval_s / 3600:.1f} 小时")
assert round(times["CodeBot 预训练"][0] / 60) == 42 and round(times["StoryBot 预训练"][0] / 60) == 16
assert 10.2 < webbot_s / 3600 < 10.6 and 8.7 < 100_000 * per_step / 3600 < 8.9
```

## X.2 把 DLFS6 接到 A1 的测试上

A1 的测试是固定的，学生只需要填写 `tests/adapters.py` 里的 21 个“适配函数”：测试调用它们，它们再调用学生自己的实现。大多数测试是**快照测试**：用固定的权重和输入算一遍，与课程参考实现保存下来的输出比较，容差逐项写在测试里，比如 RoPE 是 `atol=1e-5`，整个语言模型是 `atol=1e-4, rtol=1e-2`。

既然两边的模型形状相同，我们就把 DLFS6 接上去试试。具体做法是写一个适配文件，让每个适配函数调用 DLFS6 里扮演同一角色的代码，分四种情况：

- **DLFS6 自写**：DLFS6 亲手实现的部分，比如 StoryBot 的 RoPE、SwiGLU、Attention、整个 GPT，第 6 章的 AdamW 和 `get_batch`，第 4 章的 BPE 训练与编码。
- **PyTorch 内置**：DLFS6 直接调用 PyTorch 的部分，比如 `nn.Linear`、`F.softmax`、`F.cross_entropy`、梯度裁剪。A1 不允许这样做，所以这几项“通过”只说明接口对得上。
- **设计不同**：DLFS6 有对应的东西，但刻意做得不一样，比如学习率调度。
- **无对应**：DLFS6 没有这项功能，比如保存优化器状态的 checkpoint、流式编码、可以重叠的特殊 token。

### 三处小修改

**RMSNorm 的 eps**。StoryBot 的模型写的是 `nn.RMSNorm(embed_dim)`，不传 eps 时 PyTorch 在 float32 下用 $1.19\times10^{-7}$，而 A1 的参考实现用 $10^{-5}$。在单位尺度的输入上，这点差别微不足道：单独测 RMSNorm 只差 $1.7\times10^{-5}$，单个 Transformer 块差 $9.2\times10^{-5}$，都在容差之内。可是经过 3 层再加上最后一层 RMSNorm，误差积累到 $4.6\times10^{-4}$，有几个接近 0 的 logits 超出了 `atol=1e-4`。改成 `nn.RMSNorm(embed_dim, eps=1e-5)` 之后，误差降到 $1.05\times10^{-5}$，缩小了 40 多倍。也就是说，**除了这一个 eps，StoryBot 与 CS336 的参考模型计算的是同一个函数**。eps 对小激活的影响有多大，可以看勘误页的[验证 Z.5-e](errata.html#v-Z.5-e)。

**BPE 的平票规则**。两个字节对出现次数相同时，选哪一个？DLFS6 比较的是 token 的 id（`(count, id0, id1)` 最大者），A1 规定比较字节串的字典序。合并产生的 id 按创建的先后编号，与字节串的大小顺序无关，所以两条规则迟早会分叉。下面用一个很小的语料演示：

```verify id=X.2-b title="同一个语料：按 id 比较选出 'aaq'，按 bytes 比较选出 'zzq'"
from collections import Counter

def train(docs, n_merges, rule):
    seqs = [list(d.encode()) for d in docs]
    vocab = {i: bytes([i]) for i in range(256)}
    learned = []
    for new_id in range(256, 256 + n_merges):
        counts = Counter(p for s in seqs for p in zip(s, s[1:]))
        if rule == "dlfs6":
            best = max(counts, key=lambda p: (counts[p], p[0], p[1]))                 # 比较 id
        else:
            best = max(counts, key=lambda p: (counts[p], vocab[p[0]], vocab[p[1]]))   # 比较 bytes
        vocab[new_id] = vocab[best[0]] + vocab[best[1]]
        learned.append(vocab[new_id].decode())
        merged = []
        for s in seqs:
            out, i = [], 0
            while i < len(s):
                if i + 1 < len(s) and (s[i], s[i + 1]) == best:
                    out.append(new_id); i += 2
                else:
                    out.append(s[i]); i += 1
            merged.append(out)
        seqs = merged
    return learned

docs = ["zzq"] * 3 + ["zz"] * 3 + ["aaq"] * 3 + ["aa"] * 2
print("按 id   ：", train(docs, 3, "dlfs6"))
print("按 bytes：", train(docs, 3, "cs336"))
assert train(docs, 3, "dlfs6")[2] == "aaq" and train(docs, 3, "cs336")[2] == "zzq"
```

第 3 步时 `('aa', 'q')` 与 `('zz', 'q')` 各出现 3 次。`'zz'` 先被合并，id 是 256；`'aa'` 后被合并，id 是 257。按 id 比较，257 更大，选 `'aaq'`；按 bytes 比较，`b'zz'` 大于 `b'aa'`，选 `'zzq'`。

在 A1 的 `corpus.en`（词表 500）上，DLFS6 第 4 章的训练器与参考答案的 243 条 merge 里有 170 条位置相同：前 92 条完全一致，从第 93 条（下标 92）开始分叉。在 5MB 的 TinyStories 样本上（词表 1000），前 34 条相同，从第 35 条（下标 34）开始分叉。两种规则没有对错，只是约定不同；但如果你想用 A1 的测试检查自己的实现，就得用 A1 的约定。

改法是让训练器记住每个 id 对应的字节串，比较时用字节串代替 id。在 `ch04/02_bpe_cache.py` 的 `train_bpe` 里，这是一处改动加上两行新增：

```python
    merge_rules = {}
    vocab_bytes = {i: bytes([i]) for i in range(256)}  # 新增：id → 字节串
    ...
        best_pair = max(pair_counts, key=lambda pair: (pair_counts[pair], vocab_bytes[pair[0]], vocab_bytes[pair[1]]))
        new_id = 256 + step
        merge_rules[best_pair] = new_id

```

第 63 行原来的 key 是 `(pair_counts[pair], pair[0], pair[1])`。只改这三行，`corpus.en` 上的 243 条和 TinyStories 样本上的 743 条 merge 就与参考答案全部一致。

**`get_batch` 的上界**。`torch.randint(len(data) - context_len - 1, ...)` 少了 1，最后一个合法的起点永远抽不到。A1 用 100 个 token、窗口 7 抽 32,000 次，要求起点 92 也出现，DLFS6 最大只到 91。把上界改成 `len(data) - context_len` 就能通过。这对训练没有可察觉的影响，细节见勘误 [E13](errata.html#e13)。

### 设计不同、没有对应的 5 项

**学习率调度**。DLFS6 先线性 warmup，再线性衰减到 0（D2Z）；A1 要的是 warmup 之后按 cosine 衰减到 `min_lr`，并在那里保持不变。用 A1 测试的参数（最大学习率 1，最小 0.1，warmup 7 步，cosine 周期 21 步）把两条曲线放在一起：

```verify id=X.2-c title="warmup 段完全相同；之后 D2Z 一路降到 0，cosine 停在 0.1" files=data/cs336/a1_results.json
import numpy as np

w = {t["test"]: t for t in rec["tests"]}["test_get_lr_cosine_schedule"]["as_shipped"]["worst"]   # rec 来自验证 X.2-a
d2z, cos = np.array(w["actual"]), np.array(w["desired"])        # 测试里记录下来的两条曲线

def get_lr(it, max_lr, warmup_iters, max_iters):              # ch06/03_lr_scheduler.py
    if it < warmup_iters:
        return max_lr * (it / warmup_iters)
    if it < max_iters:
        progress = (it - warmup_iters) / (max_iters - warmup_iters)
        return max_lr * (1.0 - progress)
    return 0.0

assert np.allclose(d2z, [get_lr(it, 1, 7, 21) for it in range(25)])
diff = np.abs(d2z - cos)
for it in (0, 7, 11, 14, 21, 24):
    print(f"it={it:2d}  D2Z {d2z[it]:.3f}   cosine {cos[it]:.3f}")
print(f"最大差 {diff.max():.3f}（it={diff.argmax()}）")
assert np.allclose(d2z[:8], cos[:8]) and abs(diff.max() - 0.116) < 1e-3
```

这不是错误，而是一个有依据的选择：把学习率线性衰减到 0 的做法有专门的研究（Bergsma 等，2025，[arXiv:2502.15938](https://arxiv.org/abs/2502.15938)）。从代码上看，D2Z 的 `get_lr` 只需要最大学习率、warmup 步数和总步数，不必再决定 `min_lr` 与 cosine 的周期。

**checkpoint**。A1 要求保存模型、优化器状态和迭代次数，恢复后能精确地接着训练；DLFS6 的 `GPT.save` 只保存权重和构造参数，够用来生成和继续微调，但不能精确续训。

**流式编码**。A1 要求分词器提供 `encode_iterable`，在 1MB 的内存限制下逐行编码大文件。DLFS6 换了一条路：把大文件切块，多进程编码，缓存到磁盘，最后拼成 uint16 的 memmap（[4.7 节](ch04.html#s4-7)）。

**可以重叠的特殊 token**。A1 要求同时支持 `<|endoftext|>` 与 `<|endoftext|><|endoftext|>`，并优先匹配更长的那个；DLFS6 只有一个结束 token。

另外，分词器测试里所有 `*_matches_tiktoken` 的测试，除了流式的那一项，全都通过了：DLFS6 第 4 章按 rank 合并的编码器，配上一层 id 翻译，在 A1 的全部样例文本上与 tiktoken 的 GPT-2 编码逐 id 相同。

几条后果值得用数字确认一下。第一，初始化不同，初始 loss 也不同。如果 logits 是均值为 0、标准差为 σ 的独立正态分布，那么初始的交叉熵约为 $\ln V + \sigma^2/2$，这里 $V$ 是词表大小。σ 可以手算：最后一层 RMSNorm 让每个向量的均方根都是 1，所以 logits 的标准差约等于 $\sqrt{d}$ 乘以输出层权重的标准差。DLFS6 的输出层是 N(0, 0.02)，σ ≈ √512 × 0.02 ≈ 0.45；CS336 的截断正态按 $2/(d_\text{in}+d_\text{out})$ 设方差，σ ≈ √512 × √(2/10512) ≈ 0.31。两者的起点差 $(0.453^2-0.312^2)/2 \approx 0.054$。下面的验证对每一行 logits 取“目标在词表上均匀随机”时交叉熵的期望，不再随机抽目标，所以抽样误差只有万分之几：

```verify id=X.3-a title="初始 loss ≈ ln V + σ²/2：DLFS6 的起点比 CS336 高约 0.054"
rng = np.random.default_rng(0)
V, d = 10_000, 512
sigmas = {"DLFS6": np.sqrt(d) * 0.02, "CS336": np.sqrt(d) * np.sqrt(2 / (d + V))}
print("logits 的标准差：", "，".join(f"{k} {v:.3f}" for k, v in sigmas.items()))
ce = {}
for name, sigma in sigmas.items():
    logits = rng.normal(0, sigma, size=(256, V))
    m = logits.max(axis=1, keepdims=True)
    lse = (m + np.log(np.exp(logits - m).sum(axis=1, keepdims=True)))[:, 0]
    ce[name] = (lse - logits.mean(axis=1)).mean()       # 目标在词表上均匀随机时，交叉熵的期望
    print(f"{name}：实测 {ce[name]:.4f}   ln V + σ²/2 = {np.log(V) + sigma**2 / 2:.4f}   ln V = {np.log(V):.4f}")
    assert abs(ce[name] - (np.log(V) + sigma**2 / 2)) < 2e-3   # 换种子的波动约 3e-4

print(f"两个起点之差：实测 {ce['DLFS6'] - ce['CS336']:.4f}，(σ₁² − σ₂²)/2 = {gap:.4f}")
assert abs((ce["DLFS6"] - ce["CS336"]) - gap) < 2e-3
```

第二，loss 的归一化。DLFS6 把所有回答 token 的目标加起来，除以回答的条数 N；CS336 A5 的常数归一化除以 B·L_max（L_max = 512）。两个分母都是常数，只差一个整体倍数，而 Adam 对梯度的整体缩放几乎不敏感：Adam 的更新量是“一阶矩 ÷ 二阶矩的平方根”，梯度整体放大或缩小 c 倍，分子分母同比变化，只有分母上的 eps 会留下一点痕迹（[6.1.3 节](ch06.html#s6-1-3)）。要注意的是，DLFS6 在 Adam 之前还做了梯度裁剪，裁剪的阈值是绝对的，梯度整体缩放会改变裁剪是否生效，所以在 DLFS6 里这只是近似成立：

```verify id=X.3-b title="常数归一化只差一个整体倍数：梯度除以 512 之后，Adam 的参数只差 1e-7 量级"
def adam(grad_fn, w, steps=200, lr=1e-2, b1=0.9, b2=0.999, eps=1e-8):
    m, v = np.zeros_like(w), np.zeros_like(w)
    for t in range(1, steps + 1):
        g = grad_fn(w)
        m, v = b1 * m + (1 - b1) * g, b2 * v + (1 - b2) * g * g
        w = w - lr * (m / (1 - b1**t)) / (np.sqrt(v / (1 - b2**t)) + eps)
    return w

rng = np.random.default_rng(0)
A, b = rng.normal(size=(20, 5)), rng.normal(size=20)
grad = lambda w: A.T @ (A @ w - b)                 # 0.5·||Aw − b||² 的梯度
w0 = np.zeros(5)
w_full, w_small = adam(grad, w0), adam(lambda w: grad(w) / 512, w0)
print(f"max |Δw| = {np.abs(w_full - w_small).max():.2e}，参数本身的量级 {np.abs(w_full).max():.2f}")
assert np.abs(w_full - w_small).max() < 1e-6
```

要分清的是，标准 GRPO 的按序列平均不是整体缩放：每条回答先除以自己的长度，再对回答平均。这改变了长回答和短回答之间的相对权重。拿一条 2 个 token 的回答和一条 10 个 token 的回答来看：

```verify id=X.3-c title="按序列平均改变了长短回答的相对权重：2 个 token 与 10 个 token 的回答相差 5 倍"
A = np.array([+1.0, -1.0])                   # 一条答对，一条答错
L = np.array([2, 10])                        # 回答的长度（token 数）
N, L_max = len(A), 512
by_N = np.repeat(A / N, L)                   # DLFS6：全部 token 求和 ÷ 回答条数
by_BL = np.repeat(A / (N * L_max), L)        # CS336 的常数归一化：÷ B·L_max
by_seq = np.repeat(A / (N * L), L)           # 标准 GRPO：每条回答先 ÷ 自己的长度
print("每个 token 的权重（÷N）      ：", np.round(by_N, 3))
print("每个 token 的权重（按序列平均）：", np.round(by_seq, 3))
print(f"÷N 与 ÷B·L_max 处处相差 {(by_N / by_BL).min():.0f} 倍；"
      f"÷N 与按序列平均之比从 {(by_N / by_seq).min():.0f} 到 {(by_N / by_seq).max():.0f}")
assert np.allclose(by_N / by_BL, L_max)                          # 只差一个整体倍数
assert (by_N / by_seq).min() == 2 and (by_N / by_seq).max() == 10   # 不是整体倍数：长短回答之间差 5 倍
```

÷N 与 ÷B·L_max 处处只差 512 倍，Adam 几乎看不出来；按序列平均之后，2 个 token 的回答里每个 token 的权重是 10 个 token 的回答的 5 倍。这不是一个整体倍数，Adam 抵消不了。Dr. GRPO 批评的长度偏差正是这一点（[3.7.3 节](ch03.html#s3-7-3)的专栏），CS336 A5 也让学生把这两种归一化放在一起比较。

第三，几种 GRPO 变体的区别，归根到底是“组内的奖励怎样变成 advantage”。DLFS6 只减去组均值；标准 GRPO 再除以组内标准差；RFT 不减均值，直接用奖励；MaxRL 除以组均值。同样三组奖励，四种做法给出的 advantage 很不一样：

```verify id=X.3-d title="同一组奖励，四种 advantage：DLFS6 的做法就是 Dr. GRPO"
groups = {"2/4 答对": [1, 1, 0, 0], "3/4 答对": [1, 1, 1, 0], "1/4 答对": [1, 0, 0, 0], "全错": [0, 0, 0, 0]}
eps = 1e-6
fmt = lambda a: "[" + ", ".join(f"{x:+.2f}" for x in a) + "]"
for name, r in groups.items():
    r = np.array(r, dtype=float)
    centered = r - r.mean()                                   # DLFS6 = Dr. GRPO
    grpo = centered / (r.std(ddof=1) + eps)                   # 标准 GRPO：除以无偏标准差
    rft = r                                                   # RFT：不减均值，答错的权重为 0
    maxrl = centered / (r.mean() + eps)                       # MaxRL：除以组均值
    print(f"{name}：DLFS6 {fmt(centered)}  GRPO {fmt(grpo)}  RFT {fmt(rft)}  MaxRL {fmt(maxrl)}")
    if centered.any():
        print(f"        除以标准差后放大 {grpo[0] / centered[0]:.2f} 倍")
assert np.allclose((np.array([1., 0, 0, 0]) - 0.25) / (0.5 + eps), [1.5, -0.5, -0.5, -0.5], atol=1e-5)
assert abs(1 / np.array([1., 1, 0, 0]).std(ddof=1) - 1.732) < 1e-3     # 2/4 组只放大 1.73 倍

amp = {}
for G in (4, 8, 16):                                          # 组越大，差别越明显
    one, half = np.eye(1, G)[0], np.repeat([1.0, 0.0], G // 2)
    amp[G] = (1 / one.std(ddof=1), 1 / half.std(ddof=1))
    print(f"G={G:2d}：只有 1 个答对的组放大 {amp[G][0]:.2f} 倍，一半答对的组放大 {amp[G][1]:.2f} 倍")
assert all(abs(amp[G][0] - np.sqrt(G)) < 1e-9 for G in amp) and all(amp[G][1] < 2 for G in amp)
```

除以标准差之后，“1/4 答对”和“3/4 答对”的组放大了 2 倍，“2/4 答对”的组只放大了 1.73 倍：越接近全对或全错的组，被放大得越多。组越大，这个差别越明显：只有 1 个答对的组放大 $\sqrt{G}$ 倍，G = 16 时是 4 倍，而一半答对的组始终不到 2 倍。Dr. GRPO 批评的正是这一点（[arXiv:2503.20783](https://arxiv.org/abs/2503.20783)）：除以标准差悄悄地给太容易和太难的题加了权。MaxRL（[arXiv:2602.02710](https://arxiv.org/abs/2602.02710)）则更偏向难题：“1/4 答对”那一组的正确回答得到了 +3。“全错”的组无论哪种做法都是 0，没有学习信号。CS336 2026 年的 A5 就是让学生在这几种设定之间做对照实验。DLFS6 的 `09_grpo.py` 恰好是其中的 Dr. GRPO（只减均值、按常数归一化）。

第四，DPO 在训练开始时的 loss 恰好是 $\ln 2$，两边都一样。DPO 的 loss 是

$$L = -\log\sigma\Big(\beta\big[\big(\log\pi_\theta(y_w\mid x) - \log\pi_\text{ref}(y_w\mid x)\big) - \big(\log\pi_\theta(y_l\mid x) - \log\pi_\text{ref}(y_l\mid x)\big)\big]\Big)$$

这里，$x$ 是提示，$y_w$ 与 $y_l$ 分别是更好的回答（chosen）和更差的回答（rejected），$\pi_\theta$ 是正在训练的策略，$\pi_\text{ref}$ 是参考模型，$\beta$ 控制偏离参考模型的代价，两边都取 0.1。训练开始时策略就是参考模型，两个圆括号都是 0，$\sigma(0) = 0.5$，于是 $L = -\log 0.5 = \ln 2 \approx 0.6931$。如果策略把更好回答的对数概率提高了 5 nats，方括号里是 5，乘上 β 是 0.5，$L = \log(1 + e^{-0.5}) \approx 0.474$。这个 loss 的推导见[附录 E](appendix-e.html)。

```verify id=X.3-e title="π = π_ref 时，DPO 的 loss = ln 2 ≈ 0.6931；更好的回答多 5 nats 时降到 0.474"

    z = beta * ((policy["chosen"] - ref["chosen"]) - (policy["rejected"] - ref["rejected"]))
    return z, np.log1p(np.exp(-z))                         # −log σ(z)

ref = {"chosen": -42.0, "rejected": -57.0}                 # 任意的序列对数概率
cases = {"策略 = 参考模型": dict(ref), "更好的回答 +5 nats": {"chosen": -37.0, "rejected": -57.0}}
for name, policy in cases.items():
    z, loss = dpo_loss(policy, ref)
    print(f"{name}：z = {z:.2f}，loss = {loss:.4f}")
assert abs(dpo_loss(cases["策略 = 参考模型"], ref)[1] - np.log(2)) < 1e-12
assert abs(dpo_loss(cases["更好的回答 +5 nats"], ref)[1] - 0.4741) < 1e-4
```

        ("max_context_len", "max_position_embeddings"), ("theta", "rope_theta")]
for name, c in models.items():
    print(name)
    print("   " + "，".join(f"{dl}={c[hf]:,}" for dl, hf in rows))
    print(f"   每头维数 {c['hidden_size'] // c['num_attention_heads']}，ff_dim / embed_dim = "
          f"{c['intermediate_size'] / c['hidden_size']:.2f}，embedding 与输出层共享权重：{c['tie_word_embeddings']}")
olmo, qwen = models["2026: OLMo-2-0425-1B"], models["2025: Qwen2.5-Math-1.5B"]
assert olmo["num_key_value_heads"] == olmo["num_attention_heads"] == 16          # 普通的多头 Attention
assert qwen["num_attention_heads"] // qwen["num_key_value_heads"] == 6           # GQA：6 个查询头共用一组 KV
assert olmo["hidden_size"] == 2048 and qwen["hidden_size"] == 1536
```

## 小结

把 DLFS6 接到 CS336 A1 的测试上，结果比预想的还要整齐：除去 2 个只在 Linux 上运行的内存测试和 1 个取决于机器负载的速度测试，原样通过 35 个；失败的 10 个里，5 个只差一处小修改（RMSNorm 的 eps、BPE 的平票规则、`get_batch` 的上界），改完全部通过；另外 5 个是刻意的设计差异或者 DLFS6 没有的功能。最有分量的结论是：把 CS336 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 $10^{-5}$；而按书原样训练出来的 StoryBot，也通过了 A1 的验收线。一本书、一门课，用不同的方式写出了同一个模型。

两者的差别主要在“教多深”和“允许用什么”。DLFS6 允许用 PyTorch 的现成部件，换来三个单卡就能训练的机器人（WebBot 需要 H100 级的卡）；CS336 要求一切从零写起，并在系统、数据、scaling law 和强化学习理论上走得更远。读完本书再去读 CS336，你会发现大部分概念都已经见过，剩下的就是把它们做得更快、更大、更严谨。

本章所学的内容：

- StoryBot 的模型形状、数据和 token 预算都与 A1 的 TinyStories 实验相同，token 预算都是 327,680,000（[验证 X.1-a](#v-X.1-a)）。
- 按书原样训练的 StoryBot 在完整验证集上第 5,000 步 1.662、第 40,000 步 1.304，都在 A1 的两条线以内（[验证 X.1-b](#v-X.1-b)）。
- 除速度测试外，DLFS6 原样通过 A1 的 35 个测试；三处小修改让另外 5 个测试也通过（[验证 X.2-a](#v-X.2-a)）。
- BPE 的平票规则按 id 比较还是按 bytes 比较，会学出不同的 merge（[验证 X.2-b](#v-X.2-b)）。
- 初始 loss 约为 ln V + σ²/2，所以初始化的尺度会抬高起点（[验证 X.3-a](#v-X.3-a)）。
- 按常数归一化只差一个整体倍数，Adam 几乎不受影响；按序列平均改变了长短回答的相对权重（[验证 X.3-b](#v-X.3-b)、[验证 X.3-c](#v-X.3-c)）。
- DLFS6 的 GRPO 只减组均值，等价于 Dr. GRPO；除以标准差会放大“几乎全对”或“几乎全错”的组（[验证 X.3-d](#v-X.3-d)）。
