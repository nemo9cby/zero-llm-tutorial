斯坦福大学的 CS336《从零开始的语言建模》（Language Modeling from Scratch，Tatsunori Hashimoto 与 Percy Liang 主讲）是最常被拿来与本书对照的课程。两者的路线几乎一样：先写分词器，再搭 Transformer，然后训练、评估，最后做对齐。不同的是分量。CS336 有 5 个大作业，要求学生连 `nn.Linear` 和 `softmax` 都自己写；DLFS6 则放手使用 PyTorch 的现成部件，只把关键的几样亲手实现一遍，换来三个能在一张消费级显卡上跑完的机器人。

对照下来，最让人意外的是两者靠得有多近。StoryBot 的预训练配置与 CS336 作业 1（下文简称 A1）的 TinyStories 实验一模一样，连数据文件都逐字节相同；把 A1 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 $10^{-5}$。所以这一页不只是一张链接表，还有一次实打实的“对拍”。

本页先给出逐组件的对照表（X.1），然后把 DLFS6 的代码接到 A1 的 48 个测试上，逐项看结果（X.2）；接着整理两边在设计上的取舍，以及每个取舍带来的后果（X.3）；最后记录课程从 2025 到 2026 年的变化（X.4），并给出读完本书之后在 CS336 里接着读什么（X.5）。

::: note 关于 CS336 的作业规则
CS336 2026 年的每个作业仓库都附有写给 AI 助手的规则：只做助教，不替学生写答案。本页尊重这一点：我们只用课程**公开的测试**去衡量 **DLFS6 自己的代码**，不提供任何作业题的解答。适配用的 `verify/cs336/adapters_dlfs6.py` 只是把 DLFS6 的类接到测试接口上；而且 DLFS6 用了 A1 明令禁止的 `torch.nn`，它本身也不能当作作业提交。文中关于 CS336 的事实都取自课程网站与作业仓库（链接见各节），查证日期为 2026-10-11。

## X.2 把 DLFS6 接到 A1 的测试上

A1 的测试是固定的，学生只需要填写 `tests/adapters.py` 里的 21 个“适配函数”：测试调用它们，它们再调用学生自己的实现。大多数测试是**快照测试**：用固定的权重和输入算一遍，与课程参考实现保存下来的输出比较，容差逐项写在测试里，比如 RoPE 是 `atol=1e-5`，整个语言模型是 `atol=1e-4, rtol=1e-2`。

既然 DLFS6 是照着同一份作业搭起来的，我们就把它接上去试试。具体做法是写一个适配文件，让每个适配函数调用 DLFS6 里扮演同一角色的代码，分四种情况：

- **DLFS6 自写**：DLFS6 亲手实现的部分，比如 StoryBot 的 RoPE、SwiGLU、注意力、整个 GPT，第 6 章的 AdamW 和 `get_batch`，第 4 章的 BPE 训练与编码。
- **PyTorch 内置**：DLFS6 直接调用 PyTorch 的部分，比如 `nn.Linear`、`F.softmax`、`F.cross_entropy`、梯度裁剪。A1 不允许这样做，所以这几项“通过”只说明接口对得上。
- **设计不同**：DLFS6 有对应的东西，但刻意做得不一样，比如学习率调度。
- **无对应**：DLFS6 没有这项功能，比如保存优化器状态的检查点。

权重只改名字，不改数值；分词器只在 DLFS6 内部的 id 与 GPT-2 的 id 之间做一次翻译。然后在临时目录里运行 A1 的测试（commit `a158843`，2026-04-07），整个过程不改动 A1 的任何文件。我们跑了两个版本：DLFS6 原样，以及加上三处一行修改的版本。下面是结果，点开每一行可以看到实测误差、失败信息和解释。

### 三处一行修改

**RMSNorm 的 eps**。StoryBot 的模型写的是 `nn.RMSNorm(embed_dim)`，不传 eps 时 PyTorch 在 float32 下用 $1.19\times10^{-7}$，而 A1 的参考实现用 $10^{-5}$。在单位尺度的输入上，这点差别微不足道：单独测 RMSNorm 只差 $1.7\times10^{-5}$，单个 Transformer 块差 $9.2\times10^{-5}$，都在容差之内。可是经过 3 层再加上最后一层 RMSNorm，误差积累到 $4.6\times10^{-4}$，有几个接近 0 的 logits 超出了 `atol=1e-4`。改成 `nn.RMSNorm(embed_dim, eps=1e-5)` 之后，误差降到 $1.05\times10^{-5}$，缩小了 40 多倍。也就是说，**除了这一个 eps，StoryBot 与 CS336 的参考模型计算的是同一个函数**。eps 对小激活的影响有多大，可以看勘误页的[验证 Z.5-d](errata.html#v-Z.5-d)。

**BPE 的平局规则**。两个字节对出现次数相同时，选哪一个？DLFS6 比较的是 token 的 id（`(count, id0, id1)` 最大者），A1 规定比较字节串的字典序。合并产生的 id 按创建的先后编号，与字节串的大小顺序无关，所以两条规则迟早会分叉。下面用一个很小的语料演示：

```verify id=X.2-b title="同一个语料：按 id 比较选出 'aaq'，按 bytes 比较选出 'zzq'"
from collections import Counter

def train(docs, n_merges, rule):
    seqs = [list(d.encode()) for d in docs]
    vocab = {i: bytes([i]) for i in range(256)}
    learned = []
    for new_id in range(256, 256 + n_merges):
        counts = Counter(p for s in seqs for p in zip(s, s[1:]))
        if rule == "dlfs6":
            best = max(counts, key=lambda p: (counts[p], p[0], p[1]))                 # 比较 id
        else:
            best = max(counts, key=lambda p: (counts[p], vocab[p[0]], vocab[p[1]]))   # 比较 bytes
        vocab[new_id] = vocab[best[0]] + vocab[best[1]]
        learned.append(vocab[new_id].decode())
        merged = []
        for s in seqs:
            out, i = [], 0
            while i < len(s):
                if i + 1 < len(s) and (s[i], s[i + 1]) == best:
                    out.append(new_id); i += 2
                else:
                    out.append(s[i]); i += 1
            merged.append(out)
        seqs = merged
    return learned

docs = ["zzq"] * 3 + ["zz"] * 3 + ["aaq"] * 3 + ["aa"] * 2
print("按 id   ：", train(docs, 3, "dlfs6"))
print("按 bytes：", train(docs, 3, "cs336"))
assert train(docs, 3, "dlfs6")[2] == "aaq" and train(docs, 3, "cs336")[2] == "zzq"
```

第 3 步时 `('aa', 'q')` 与 `('zz', 'q')` 各出现 3 次。`'zz'` 先被合并，id 是 256；`'aa'` 后被合并，id 是 257。按 id 比较，257 更大，选 `'aaq'`；按 bytes 比较，`b'zz'` 大于 `b'aa'`，选 `'zzq'`。在 A1 的 `corpus.en`（词表 500）上，DLFS6 第 4 章的训练器与参考答案的 243 条 merge 里有 170 条位置相同，从第 92 条开始分叉；只把 `max()` 的 key 换成字节串，243 条就全部一致。在 5MB 的 TinyStories 样本上（词表 1000），原样从第 34 条开始分叉，改完之后 743 条全部一致。两种规则没有对错，只是约定不同；但如果你想用 A1 的测试检查自己的实现，就得用 A1 的约定。改动的那一行是：

```python
# ch04/02_bpe_cache.py 第 63 行
best_pair = max(pair_counts, key=lambda pair: (pair_counts[pair], pair[0], pair[1]))
# 改为（id_bytes 把 token id 还原成字节串）

```

**`get_batch` 的上界**。`torch.randint(len(data) - context_len - 1, ...)` 少了 1，最后一个合法的起点永远抽不到。A1 用 100 个 token、窗口 7 抽 32,000 次，要求起点 92 也出现，DLFS6 最大只到 91。这对训练没有可察觉的影响，细节见勘误 [E13](errata.html#e13)。

### 设计不同、没有对应的 5 项

**学习率调度**。DLFS6 先线性 warmup，再线性衰减到 0（D2Z）；A1 要的是 warmup 之后按 cosine 衰减到 `min_lr`，并在那里保持不变。用 A1 测试的参数（最大学习率 1，最小 0.1，warmup 7 步，cosine 周期 21 步）把两条曲线放在一起：

```verify id=X.2-c title="warmup 段完全相同；之后 D2Z 一路降到 0，cosine 停在 0.1" files=data/cs336/a1_results.json
import numpy as np

w = {t["test"]: t for t in rec["tests"]}["test_get_lr_cosine_schedule"]["as_shipped"]["worst"]   # rec 来自验证 X.2-a
d2z, cos = np.array(w["actual"]), np.array(w["desired"])        # 测试里记录下来的两条曲线

def get_lr(it, max_lr, warmup_iters, max_iters):              # ch06/03_lr_scheduler.py
    if it < warmup_iters:
        return max_lr * (it / warmup_iters)
    if it < max_iters:
        progress = (it - warmup_iters) / (max_iters - warmup_iters)
        return max_lr * (1.0 - progress)
    return 0.0

assert np.allclose(d2z, [get_lr(it, 1, 7, 21) for it in range(25)])
diff = np.abs(d2z - cos)
for it in (0, 7, 11, 14, 21, 24):
    print(f"it={it:2d}  D2Z {d2z[it]:.3f}   cosine {cos[it]:.3f}")
print(f"最大差 {diff.max():.3f}（it={diff.argmax()}）")
assert np.allclose(d2z[:8], cos[:8]) and abs(diff.max() - 0.116) < 1e-3
```

这不是错误，而是一个有依据的选择：把学习率线性衰减到 0 的做法有专门的研究（Bergsma 等，2025，[arXiv:2502.15938](https://arxiv.org/abs/2502.15938)）。从代码上看，D2Z 的 `get_lr` 只需要最大学习率、warmup 步数和总步数，不必再决定 `min_lr` 与 cosine 的周期。

**检查点**。A1 要求保存模型、优化器状态和迭代次数，恢复后能精确地接着训练；DLFS6 的 `GPT.save` 只保存权重和构造参数，够用来生成和继续微调，但不能精确续训。

**流式编码**。A1 要求分词器提供 `encode_iterable`，在 1MB 的内存限制下逐行编码大文件。DLFS6 换了一条路：把大文件切块，多进程编码，缓存到磁盘，最后拼成 uint16 的 memmap（[4.7 节](ch04.html#s4-7)）。

**可以重叠的特殊 token**。A1 要求同时支持 `<|endoftext|>` 与 `<|endoftext|><|endoftext|>`，并优先匹配更长的那个；DLFS6 只有一个结束 token。

另外，分词器测试里所有 `*_matches_tiktoken` 的测试，除了流式的那一项，全都通过了：DLFS6 第 4 章按 rank 合并的编码器，配上一层 id 翻译，在 A1 的全部样例文本上与 tiktoken 的 GPT-2 编码逐 id 相同。

上一节的失败大多来自“约定不同”。这一节把两边所有值得一提的设计差异列在一起，并写出每个差异会带来什么后果。

几条后果值得用数字确认一下。第一，初始化不同，初始 loss 也不同。如果 logits 是均值为 0、标准差为 σ 的独立正态分布，那么初始的交叉熵约为 $\ln V + \sigma^2/2$，这里 $V$ 是词表大小。σ 可以手算：最后一层 RMSNorm 让每个向量的均方根都是 1，所以 logits 的标准差约等于 $\sqrt{d}$ 乘以输出层权重的标准差。DLFS6 的输出层是 N(0, 0.02)，σ ≈ √512 × 0.02 ≈ 0.45；CS336 的截断正态按 $2/(d_\text{in}+d_\text{out})$ 设方差，σ ≈ √512 × √(2/10512) ≈ 0.31：

```verify id=X.3-a title="初始 loss ≈ ln V + σ²/2：σ 越大，起点越高"
rng = np.random.default_rng(0)
V, d = 10_000, 512
sigmas = {"DLFS6": np.sqrt(d) * 0.02, "CS336": np.sqrt(d) * np.sqrt(2 / (d + V))}
print("logits 的标准差：", "，".join(f"{k} {v:.3f}" for k, v in sigmas.items()))
for sigma in sigmas.values():
    logits = rng.normal(0, sigma, size=(256, V))
    m = logits.max(axis=1, keepdims=True)
    lse = (m + np.log(np.exp(logits - m).sum(axis=1, keepdims=True)))[:, 0]
    targets = rng.integers(0, V, size=256)
    ce = (lse - logits[np.arange(256), targets]).mean()
    print(f"σ={sigma:.3f}: 实测 {ce:.4f}   ln V + σ²/2 = {np.log(V) + sigma**2 / 2:.4f}   ln V = {np.log(V):.4f}")
    assert abs(ce - (np.log(V) + sigma**2 / 2)) < 0.02
```


第二，GRPO 的 loss 除以一个常数（样本数）而不是 token 数，这在 Adam 下影响很小。Adam 的更新量是“一阶矩 ÷ 二阶矩的平方根”，梯度整体放大或缩小 c 倍，分子分母同比变化，只有分母上的 eps 会留下一点痕迹。要注意的是，DLFS6 在 Adam 之前还做了梯度裁剪，裁剪的阈值是绝对的，梯度整体缩放会改变裁剪是否生效，所以在 DLFS6 里这只是近似成立：

```verify id=X.3-b title="Adam 对梯度的整体缩放几乎不敏感：除以 512 后，参数只差 1e-7 量级"
def adam(grad_fn, w, steps=200, lr=1e-2, b1=0.9, b2=0.999, eps=1e-8):
    m, v = np.zeros_like(w), np.zeros_like(w)
    for t in range(1, steps + 1):
        g = grad_fn(w)
        m, v = b1 * m + (1 - b1) * g, b2 * v + (1 - b2) * g * g
        w = w - lr * (m / (1 - b1**t)) / (np.sqrt(v / (1 - b2**t)) + eps)
    return w

rng = np.random.default_rng(0)
A, b = rng.normal(size=(20, 5)), rng.normal(size=20)
grad = lambda w: A.T @ (A @ w - b)                 # 0.5·||Aw − b||² 的梯度
w0 = np.zeros(5)
w_full, w_small = adam(grad, w0), adam(lambda w: grad(w) / 512, w0)
print(f"max |Δw| = {np.abs(w_full - w_small).max():.2e}，参数本身的量级 {np.abs(w_full).max():.2f}")
assert np.abs(w_full - w_small).max() < 1e-5
```

第三，几种 GRPO 变体的区别，归根到底是“组内的奖励怎样变成 advantage”。DLFS6 只减去组均值；标准 GRPO 再除以组内标准差；RFT 不减均值，直接用奖励；MaxRL 除以组均值。同样三组奖励，四种做法给出的 advantage 很不一样：

```verify id=X.3-c title="同一组奖励，四种 advantage：DLFS6 的做法就是 Dr. GRPO"
groups = {"2/4 答对": [1, 1, 0, 0], "3/4 答对": [1, 1, 1, 0], "1/4 答对": [1, 0, 0, 0], "全错": [0, 0, 0, 0]}
eps = 1e-6
fmt = lambda a: "[" + ", ".join(f"{x:+.2f}" for x in a) + "]"
for name, r in groups.items():
    r = np.array(r, dtype=float)
    centered = r - r.mean()                                   # DLFS6 = Dr. GRPO
    grpo = centered / (r.std(ddof=1) + eps)                   # 标准 GRPO：除以无偏标准差
    rft = r                                                   # RFT：不减均值，答错的权重为 0
    maxrl = centered / (r.mean() + eps)                       # MaxRL：除以组均值
    print(f"{name}：DLFS6 {fmt(centered)}  GRPO {fmt(grpo)}  RFT {fmt(rft)}  MaxRL {fmt(maxrl)}")
    if centered.any():
        print(f"        除以标准差后放大 {grpo[0] / centered[0]:.2f} 倍")
assert np.allclose((np.array([1., 0, 0, 0]) - 0.25) / (0.5 + eps), [1.5, -0.5, -0.5, -0.5], atol=1e-5)
assert abs(1 / np.array([1., 1, 0, 0]).std(ddof=1) - 1.732) < 1e-3     # 2/4 组只放大 1.73 倍

amp = {}
for G in (4, 8, 16):                                          # 组越大，差别越明显
    one, half = np.eye(1, G)[0], np.repeat([1.0, 0.0], G // 2)
    amp[G] = (1 / one.std(ddof=1), 1 / half.std(ddof=1))
    print(f"G={G:2d}：只有 1 个答对的组放大 {amp[G][0]:.2f} 倍，一半答对的组放大 {amp[G][1]:.2f} 倍")
assert all(abs(amp[G][0] - np.sqrt(G)) < 1e-9 for G in amp) and all(amp[G][1] < 2 for G in amp)
```

除以标准差之后，“1/4 答对”和“3/4 答对”的组放大了 2 倍，“2/4 答对”的组只放大了 1.73 倍：越接近全对或全错的组，被放大得越多。组越大，这个差别越明显：只有 1 个答对的组放大 $\sqrt{G}$ 倍，G = 16 时是 4 倍，而一半答对的组始终不到 2 倍。Dr. GRPO 批评的正是这一点（[arXiv:2503.20783](https://arxiv.org/abs/2503.20783)）：除以标准差悄悄地给太容易和太难的题加了权。MaxRL（[arXiv:2602.02710](https://arxiv.org/abs/2602.02710)）则更偏向难题：“1/4 答对”那一组的正确回答得到了 +3。“全错”的组无论哪种做法都是 0，没有学习信号。CS336 2026 年的 A5 就是让学生在这几种设定之间做对照实验。DLFS6 的 `09_grpo.py` 恰好是其中的 Dr. GRPO（只减均值、按常数归一化）。


本书在每个主题上都比 CS336 讲得更慢、更直观；CS336 在系统、数据和强化学习理论上走得更深。读完本书的某一章，如果想沿着同一个主题继续往下挖，可以按下表去找 CS336 的讲次与作业（讲次的录像与可执行讲义都在 [cs336.stanford.edu](https://cs336.stanford.edu/)）：

## 小结

把 DLFS6 接到 CS336 A1 的测试上，结果比预想的还要整齐：48 个测试里，原样通过 36 个；失败的 10 个里，5 个只差一行代码（RMSNorm 的 eps、BPE 的平局规则、`get_batch` 的上界），改完全部通过；另外 5 个是刻意的设计差异或者 DLFS6 没有的功能。最有分量的结论是：把 CS336 测试用的权重装进 StoryBot，只改一个 eps，输出就与课程的参考实现一致到 $10^{-5}$。一本书、一门课，用不同的方式写出了同一个模型。

两者的差别主要在“教多深”和“允许用什么”。DLFS6 允许用 PyTorch 的现成部件，换来能在一张显卡上跑完的三个机器人；CS336 要求一切从零写起，并在系统、数据、scaling law 和强化学习理论上走得更远。读完本书再去读 CS336，你会发现大部分概念都已经见过，剩下的就是把它们做得更快、更大、更严谨。

本章所学的内容：

- StoryBot 的预训练与 A1 的 TinyStories 实验配置相同，token 预算都是 327,680,000（[验证 X.1-a](#v-X.1-a)）。
- DLFS6 原样通过 A1 的 36 个测试；三处一行修改让另外 5 个测试也通过（[验证 X.2-a](#v-X.2-a)）。
- BPE 的平局规则按 id 比较还是按 bytes 比较，会学出不同的 merge（[验证 X.2-b](#v-X.2-b)）。
- D2Z 与 cosine 在 warmup 段完全相同，之后最多相差 0.116（[验证 X.2-c](#v-X.2-c)）。
- 初始 loss 约为 ln V + σ²/2，所以初始化的尺度会抬高起点（[验证 X.3-a](#v-X.3-a)）。
- DLFS6 的 GRPO 只减组均值，等价于 Dr. GRPO；除以标准差会放大“几乎全对”或“几乎全错”的组（[验证 X.3-c](#v-X.3-c)）。
- 策略等于参考模型时，DPO 的 loss 恰好是 ln 2（[验证 X.3-d](#v-X.3-d)）。

同一个量在不同的代码库里有不同的名字：DLFS6 的 `embed_dim`、Hugging Face 的 `hidden_size`、CS336 的 `d_model`、GPT-2 的 `n_embd`。下一页的[术语与命名对照](glossary.html)把它们放在一张表里。
