第 4 章把 BPE 分词器提速到了能处理 2.2 GB TinyStories 的程度，StoryBot 的 1 万个 token 的词表已经准备好了。接下来轮到模型。我们在第 2 章亲手组装的 GPT-2 是 2019 年的设计。此后，以 LLaMA 为代表的模型把其中几个零件换成了新的写法：位置信息改用 RoPE，FFN 改用 SwiGLU，归一化改用 RMSNorm[^llama]。CS336 第 3 讲把它们与 pre-norm、去掉 bias 等做法一起，列为今天 LLM 架构的常见选择[^cs336-l3]。

本章就做这件事：保留 GPT-2 的骨架（pre-norm 的 Transformer 块、残差连接、最后的输出层），把零件一个一个换掉，再去掉三样在大规模预训练里不再划算的东西：dropout、bias，以及 embedding 与输出层之间的权重共享。换完之后的“改良版 GPT”，正是第 6 章要训练的 StoryBot。最后一节换个角度看生成：模型每吐出一个 token，原来的写法都要把前面所有的 token 重算一遍，KV cache 把这些重复计算省掉。

先来看全貌。下表左边是第 2 章的 CodeBot，右边是本章结束时的样子。在同样的尺寸下（词表 1,000、embed_dim 384、6 层），参数量从 11,121,640 变成 11,389,824，几乎没变（[验证 5.3-f](#v-5.3-f)）；变的是每个零件的做法。

| 部件 | CodeBot（第 2 章） | 改良版 GPT（本章） | 小节 |
|---|---|---|---|
| 位置信息 | 可学习的绝对位置 embedding，加在输入上 | RoPE：在每层旋转 Q、K，没有参数 | 5.1 |
| FFN | Linear → GELU → Linear，中间宽 4d | SwiGLU：三个矩阵，中间宽约 8d/3 | 5.2 |
| 归一化 | LayerNorm（γ 与 β） | RMSNorm（只有 γ） | 5.3.1 |
| Dropout | 0.1，共四处 | 无 | 5.3.2 |

## 5.1 RoPE

### 5.1.1 RoPE 的想法

回忆一下 [2.5 节](ch02.html#s2-5)。Attention 本身并不知道 token 的先后顺序，所以 GPT-2 为每个位置准备了一个可学习的向量，加到 token 的 embedding 上。这种做法叫作**绝对位置编码**（absolute position encoding）：每个位置有自己的一个向量，位置 5 就是位置 5。模型只知道“这是第 5 个”，并不直接知道它与第 3 个相隔几步。

可是在语言里，重要的往往是**相对位置**（relative position）。“the” 紧挨在 “cat” 前面，这件事无论发生在句首还是第 200 个 token 处，含义都相同。用绝对位置编码时，模型只能从大量数据里自己摸索出“整体平移之后关系不变”的规律。那么，能不能把位置编进 query 和 key，让 Attention 的分数天生只取决于两个 token 相隔多远呢？

**RoPE**（Rotary Position Embedding，旋转位置编码）的答案是：按位置旋转[^rope]。先看二维的情形。把 query 向量 $\boldsymbol q$ 和 key 向量 $\boldsymbol k$ 想象成平面上的两支箭头。位于第 $m$ 个位置的 query 逆时针转 $m\theta$，位于第 $n$ 个位置的 key 转 $n\theta$，其中 $\theta$ 是每前进一个位置要转的角度。点积只取决于两支箭头的长度和夹角，而旋转之后，夹角恰好变化了 $(n-m)\theta$，只与位置之差有关。

[^rope]: Su et al., *RoFormer: Enhanced Transformer with Rotary Position Embedding*, 2021, [arXiv:2104.09864](https://arxiv.org/abs/2104.09864)

写成公式。二维的旋转矩阵是

$$R(\phi)=\begin{pmatrix}\cos\phi & -\sin\phi\\ \sin\phi & \cos\phi\end{pmatrix}$$

旋转之后的分数为

$$\big(R(m\theta)\,\boldsymbol q\big)^{\top}\big(R(n\theta)\,\boldsymbol k\big)=\boldsymbol q^{\top}R(m\theta)^{\top}R(n\theta)\,\boldsymbol k=\boldsymbol q^{\top}R\big((n-m)\theta\big)\,\boldsymbol k$$

这里用到了旋转矩阵的两个性质：$R(\phi)^{\top}=R(-\phi)$（转置就是反着转回去），以及 $R(\alpha)R(\beta)=R(\alpha+\beta)$（连转两次，等于一次转过两个角度之和）。最右边只剩下 $n-m$，$m$ 和 $n$ 各自是多少已经无关紧要了。后面我们统一用 $\Delta=m-n$ 表示这个位置差，即 q 比 k 晚几个位置；公式里的 $(n-m)\theta$ 就是 $-\Delta\theta$。

手算一个例子。取 $\boldsymbol q=\boldsymbol k=(1,0)$，$\theta=30^\circ$。q 在位置 1、k 在位置 3 时，它们分别转到 30° 和 90°，夹角 60°，点积是 $\cos 60^\circ=0.5$。把两者同时往后挪 5 个位置（6 和 8），它们转到 180° 和 240°，夹角仍是 60°，点积仍是 0.5。

```verify id=5.1-a title="二维 RoPE：q、k 一起平移，点积不变"
import numpy as np

def rotate(v, angle):
    """把二维向量 v 逆时针旋转 angle 弧度。"""
    c, s = np.cos(angle), np.sin(angle)
    return np.array([c * v[0] - s * v[1], s * v[0] + c * v[1]])

theta = np.deg2rad(30)            # 每前进一个位置，转 30°
q = np.array([1.0, 0.0])
k = np.array([1.0, 0.0])
for m, n in [(1, 3), (6, 8), (10, 12)]:
    score = rotate(q, m * theta) @ rotate(k, n * theta)
    print(f"q 在位置 {m:2d}，k 在位置 {n:2d}（Δ = m - n = {m - n}）：q·k = {score:.4f}")
    assert np.isclose(score, np.cos(np.deg2rad(60)))      # 手算：cos 60° = 0.5

# 换成任意的 q、k 也一样：两者一起平移，分数不变
rng = np.random.default_rng(0)
q, k = rng.standard_normal(2), rng.standard_normal(2)
s1 = rotate(q, 2 * theta) @ rotate(k, 7 * theta)
s2 = rotate(q, 12 * theta) @ rotate(k, 17 * theta)
print(f"(m, n) = (2, 7) 与 (12, 17)：{s1:.4f} 与 {s2:.4f}")
assert np.isclose(s1, s2)
```

公式里的关键一步 $R(m\theta)^{\top}R(n\theta)=R\big((n-m)\theta\big)$ 也用矩阵直接确认一下：

```verify id=5.1-b title="R(mθ)ᵀ R(nθ) = R((n−m)θ)"
def R(angle):
    c, s = np.cos(angle), np.sin(angle)
    return np.array([[c, -s], [s, c]])

m, n = 2, 7
assert np.allclose(R(m * theta).T @ R(n * theta), R((n - m) * theta))
assert np.isclose(rotate(q, m * theta) @ rotate(k, n * theta), q @ R((n - m) * theta) @ k)
print("R(mθ)ᵀ R(nθ) = R((n−m)θ)：成立")
```

### 5.1.2 推广到高维向量

真实的 query 和 key 不是二维的：StoryBot 每个头的维度（head_dim）是 32，01_rope.py 的演示用的是 64。RoPE 的做法很直接：把 $d$ 维向量的分量两两配对，$(x_0,x_1)$、$(x_2,x_3)$、……共 $d/2$ 对，每一对看成一个平面，各自旋转。第 $i$ 对的转速是

$$\theta_i=\Theta^{-2i/d},\qquad i=0,1,\dots,\tfrac d2-1$$

这里 $\Theta$ 是一个常数，RoPE 论文与原书都取 10000，代码里的参数名叫 `theta`。位于第 $m$ 个位置时，第 $i$ 对转过 $m\theta_i$。手算 $d=4$ 的情形：只有两对，$\theta_0=10000^{0}=1$，$\theta_1=10000^{-2/4}=0.01$。在位置 $m=2$，第一对转 2 弧度（约 115°），第二对只转 0.02 弧度（约 1.1°）。

为什么每一对的转速要各不相同？可以想象一只有许多根指针的钟。只看秒针，分不清 3 秒和 63 秒；只看时针，又分不清相邻的两秒。几根转速不同的指针合在一起，近处和远处的位置才都能分辨。RoPE 的 $d/2$ 对就是 $d/2$ 根指针，$\theta_0=1$ 的那根最快，越往后越慢。

严格地讲，第 $i$ 对每走 $2\pi/\theta_i$ 个位置转回原处（这个数后面叫作波长）。快的几对负责区分相邻的位置；最慢的一对要走几万个位置才转满一圈，在这个范围内，不同位置的角度组合各不相同。至于上一节的相对位置性质，它对每一对都成立，而 $d$ 维向量的点积是各对点积之和，所以整体的分数同样只依赖 $m-n$。

下面的 `rope()` 是这种做法的 NumPy 版，写法与原书的代码一一对应。我们把同一个 $\boldsymbol q$ 依次放到位置 0, 1, …, 127，$\boldsymbol k$ 也一样，算出全部 128 × 128 个分数 $S[m,n]$，再检查 $m-n$ 相同的位置对是不是分数都相同：

```verify id=5.1-c title="d = 64 的 RoPE：分数只依赖有方向的位置差"
def rope(x, positions, theta=10000.0):
    """x: (T, D)；positions: T 个位置。与原书相同，相邻两维 (2i, 2i+1) 配成一对旋转。"""
    D = x.shape[-1]
    inv_freq = 1.0 / theta ** (2.0 * np.arange(D // 2) / D)               # θ_i，形状 (D/2,)
    angles = np.asarray(positions, dtype=float)[:, None] * inv_freq         # (T, D/2)
    cos, sin = np.cos(angles), np.sin(angles)
    x_even, x_odd = x[..., 0::2], x[..., 1::2]
    out = np.empty_like(x)
    out[..., 0::2] = x_even * cos - x_odd * sin
    out[..., 1::2] = x_even * sin + x_odd * cos
    return out

rng = np.random.default_rng(0)
D, T = 64, 128
q, k = rng.standard_normal(D), rng.standard_normal(D)
pos = np.arange(T)
Q = rope(np.tile(q, (T, 1)), pos)        # 把同一个 q 依次放到位置 0, 1, …, 127
K = rope(np.tile(k, (T, 1)), pos)
S = Q @ K.T                               # S[m, n]：q 在位置 m、k 在位置 n 时的分数

assert np.allclose(np.linalg.norm(Q, axis=1), np.linalg.norm(q))   # 旋转不改变长度
assert np.allclose(Q[0], q)                                          # 位置 0 不旋转
for d in [3, -3, 50]:
    diag = np.diagonal(S, offset=-d)      # 所有满足 m - n = d 的 (m, n)
    print(f"m - n = {d:+3d}：{len(diag):3d} 对位置，分数全是 {diag[0]:+.4f}")
spread = [np.ptp(np.diagonal(S, offset=-d)) for d in range(-(T - 1), T)]
print(f"全部 {len(spread)} 条对角线（m - n 从 {-(T - 1)} 到 {T - 1}）：每条上分数的最大差 < 1e-9 → {max(spread) < 1e-9}")
assert max(spread) < 1e-9

# 对照：把可学习的绝对位置编码（这里用随机向量代替）加到 q、k 上
P_abs = rng.standard_normal((T, D))
S_abs = (q + P_abs) @ (k + P_abs).T
diag = np.diagonal(S_abs, offset=-3)
print(f"绝对位置编码：m - n = +3 的分数从 {diag.min():.1f} 到 {diag.max():.1f}")
assert np.ptp(diag) > 10
```

前两行输出值得多看一眼：$m-n=+3$（q 在 k 后面 3 个位置）与 $m-n=-3$（q 在 k 前面 3 个位置）的分数不同。RoPE 编码的是**有方向的**距离，这两种情形对模型来说是两回事。最后一行是对照组：把随机的绝对位置向量加到 q、k 上，同一条对角线上的分数就从 −52 散布到 17 了。

::: note 另外两种等价的写法
把每一对 $(x_{2i},x_{2i+1})$ 看成一个复数 $x_{2i}+\mathrm{i}\,x_{2i+1}$，转 $m\theta_i$ 就是乘以 $e^{\mathrm{i}m\theta_i}$，RoPE 的论文就是这样推导的。把 $d/2$ 个 2 × 2 的旋转块排在对角线上，又得到一个 $d\times d$ 的分块对角矩阵 $R_m$，它同样满足 $R_m^{\top}R_n=R_{n-m}$。这两种写法与 `rope()` 算出来的是同一个东西（[验证 5.1-d](#v-5.1-d)）。
:::

```verify id=5.1-d title="复数乘法、分块旋转矩阵与 rope() 一致"
m = 7
inv_freq = 1.0 / 10000.0 ** (2.0 * np.arange(D // 2) / D)
z = (q[0::2] + 1j * q[1::2]) * np.exp(1j * m * inv_freq)     # 每一对看成一个复数，乘以 e^{i m θ_i}
r = rope(q[None, :], [m])[0]
assert np.allclose(z.real, r[0::2]) and np.allclose(z.imag, r[1::2])

def R_block(m):
    """D×D 的分块对角旋转矩阵：第 i 个 2×2 块转 m·θ_i。"""
    M = np.zeros((D, D))
    for i, w in enumerate(inv_freq):
        M[2 * i:2 * i + 2, 2 * i:2 * i + 2] = R(m * w)
    return M

assert np.allclose(R_block(m) @ q, r)
assert np.allclose(R_block(5).T @ R_block(12), R_block(7))
print("复数乘法、分块旋转矩阵、rope() 三种写法结果相同")
```

$\Theta$ 决定了指针最慢能慢到什么程度。第 $i$ 根指针转满一圈需要 $2\pi/\theta_i$ 个位置，我们把这个数叫作它的**波长**。$d=64$、$\Theta=10000$ 时，最快的指针每 6.28 个位置转一圈，最慢的要 47,117 个位置；把 $\Theta$ 增大到 1,000,000，最慢的指针要四百多万个位置才转一圈。直观上，上下文越长，越需要转得足够慢的指针来区分远处的位置。CS336 作业 3 的训练 API 用的就是 $\Theta=10^6$[^cs336-a3]。

[^cs336-a3]: [stanford-cs336/assignment3-scaling](https://github.com/stanford-cs336/assignment3-scaling)，作业说明里的模型配置。

```verify id=5.1-e title="θ_i 与波长：Θ 越大，最慢的指针越慢"

    inv_freq = 1.0 / base ** (2.0 * np.arange(32) / 64)        # head_dim = 64
    wavelength = 2 * np.pi / inv_freq                            # 转满一圈要走多少个位置
    print(f"Θ = {base:>9,.0f}：θ_0 = {inv_freq[0]:.4f}，θ_1 = {inv_freq[1]:.4f}，θ_31 = {inv_freq[-1]:.2e}，"
          f"波长 {wavelength[0]:.2f} … {wavelength[-1]:,.0f}")
    if base == 10_000.0:
        assert inv_freq[0] == 1.0 and abs(wavelength[-1] - 47117.24) < 0.01
    else:
        assert 4e6 < wavelength[-1] < 5e6                        # 正文：“四百多万个位置”
```

::: answer
不一定。取 q = k = 全 1 向量（d = 64），把分数除以 d，它随距离 Δ 的变化大体在下降：Δ = 0 时是 1，Δ = 50 时是 0.490。可是 Δ = 100 时又回升到 0.559，Δ = 1000 时（0.279）也比 Δ = 500 时（0.201）高。几十根指针的余弦叠加在一起，起伏在所难免。所以“RoPE 让远处的分数衰减”只是一个大致的倾向，不是单调的规律。

### 5.1.3 实现 RoPE

现在来看原书的实现。`RoPE` 类分成两半：`__init__` 把所有位置的 cos、sin 预先算好，`forward` 负责旋转。

```listing ch05/01_rope.py#L6-L46
```

先看 `__init__`。`inv_freq` 就是上面的 $\theta_i$，形状为 (half,)；`angles` 是“位置 × 转速”的外积，形状为 (max_context_len, half)。也就是说，**RoPE 的表有多少行，由 max_context_len 决定**（在 CodeBot 里，max_context_len 决定的是位置 embedding 表的行数）。cos、sin 两张表用 `register_buffer` 登记。buffer 不是参数，不会被优化器更新；但它会跟着 `model.to(device)` 一起搬到 GPU 上，也会写进 `state_dict`，保存模型时一并存下来。5.4.3 节还会用到这一点。

`forward` 收到的 x 形状为 (batch, num_head, context_len, key_dim)。`x[..., 0::2]` 取出第 0、2、4……维，`x[..., 1::2]` 取出第 1、3、5……维，两者按顺序配对，正是“相邻两维配成一对”。旋转公式逐元素地作用在这两组上。最后，`torch.stack(..., dim=-1)` 把结果排成 (…, half, 2) 的形状，再 `reshape` 回 key_dim，偶数维和奇数维就重新交错回原来的位置。

还有一处细节：旋转之前先 `x.float()`，算完再 `.to(input_dtype)` 转回去（commit 6855e70，“rope -> fp32”）。第 6 章用 `torch.autocast` 做 bf16 混合精度（ch06/05_pretrain.py 第 64、130 行）：线性层输出的 Q、K 是 bf16，cos、sin 却是 float32 的 buffer。按 PyTorch 的类型提升规则，bf16 × float32 本来就在 float32 下计算，所以这两行只是把这一点写明，再把输出转回与输入相同的 bf16。随后算分数的矩阵乘法在 autocast 下本来也要把 Q、K 转成 bf16，所以注意力层的输出与不加这两行时逐位相同。

只有把整个模型 `.to(torch.bfloat16)`，cos、sin 表也跟着变成 bf16 时，不加这两行的旋转才会全程在 bf16 下进行；这时先转 float32 能减小一些误差（表本身的 bf16 舍入还在）。第 6 章的代码在 2026-03-27 到 04-09 之间这样做过（commit 5ff851d 加上、623549e 删掉），那已是 6855e70 之后两个月的事了。下面的本地验证把这几种情形都算了一遍：

::: warn 交错式与 rotate_half 不能混用
原书把相邻的两维 $(2i,\,2i+1)$ 配成一对，这种写法叫交错式（interleaved）。Hugging Face transformers 里的 LLaMA 实现用的是 `rotate_half`，把第 $i$ 维与第 $i+d/2$ 维配成一对[^hf]。两种写法只差一次维度重排，各自都满足相对位置的性质；但用一种写法训练出来的 $W_q$、$W_k$ 直接拿到另一种写法里用，分数就全乱了。要换写法，得先把 $W_q$、$W_k$ 的输出维度按同一个置换重排一遍。
:::

[^hf]: [transformers：modeling_llama.py](https://github.com/huggingface/transformers/blob/main/src/transformers/models/llama/modeling_llama.py)中的 `rotate_half`。

```verify id=5.1-h title="交错式与 rotate_half 只差一个置换，但权重不能直接互换"
def rope_half(x, positions, theta=10000.0):
    """HF/LLaMA 的写法（rotate_half）：第 i 维与第 i + D/2 维配成一对。"""
    D = x.shape[-1]
    h = D // 2
    inv_freq = 1.0 / theta ** (2.0 * np.arange(h) / D)
    a = np.asarray(positions, dtype=float)[:, None] * inv_freq
    cos, sin = np.cos(a), np.sin(a)
    x1, x2 = x[..., :h], x[..., h:]
    return np.concatenate([x1 * cos - x2 * sin, x1 * sin + x2 * cos], axis=-1)

rng = np.random.default_rng(1)
Dh = 8
perm = np.r_[0:Dh:2, 1:Dh:2]                   # [0 2 4 6 1 3 5 7]：偶数维放前面，奇数维放后面
x = rng.standard_normal((6, Dh))
pos = np.arange(6)
assert np.allclose(rope(x, pos)[:, perm], rope_half(x[:, perm], pos))   # 两者只差一个维度置换
assert not np.allclose(rope(x, pos), rope_half(x, pos))                 # 但不能直接互换

print(f"直接换成 rotate_half：分数最大偏差 {np.abs(S_swap - S_ok).max():.2f}")
print(f"先按 perm 重排 W_q、W_k 的输出维度：最大偏差 < 1e-12 → {np.abs(S_perm - S_ok).max() < 1e-12}")

## 5.2 SwiGLU

### 5.2.1 Swish 函数

[2.9 节](ch02.html#s2-9)的 FFN 由两个线性层夹一个 GELU 组成：先把 E 维放大到 4E 维，过激活函数，再缩回 E 维。现代 LLM 把这里换成了 SwiGLU。要讲 SwiGLU，先从它用到的激活函数 Swish 说起。

如果你读过《深度学习入门：基于Python的理论与实现》3.2 节，一定记得 sigmoid 函数 $\sigma(x)=1/(1+e^{-x})$，它把任意实数压到 0 和 1 之间。**Swish** 函数就是 $x$ 乘上它自己的 sigmoid[^swish]：

$$\mathrm{Swish}(x)=x\,\sigma(x)$$

这里 $\sigma(x)$ 像一个平滑的开关：$x$ 很大时 $\sigma(x)\approx1$，$\mathrm{Swish}(x)\approx x$；$x$ 很负时 $\sigma(x)\approx0$，$\mathrm{Swish}(x)\approx0$。手算两个值：$\mathrm{Swish}(1)=\sigma(1)\approx0.7311$，$\mathrm{Swish}(-1)=-\sigma(-1)\approx-0.2689$。Swish 原本带一个参数 β，写作 $x\,\sigma(\beta x)$；β = 1 的特例又叫 **SiLU**，PyTorch 里就是 `F.silu`。

[^swish]: Ramachandran et al., *Searching for Activation Functions*, 2017, [arXiv:1710.05941](https://arxiv.org/abs/1710.05941)。论文里的 Swish 带参数 β，β = 1 时就是 SiLU。

原书的 graph.py 把三种激活函数画在一起，核心是下面几行：

三条曲线在 $x$ 很大时都贴近 $y=x$，在 $x$ 很负时都贴近 0（图里只画到 ±3，验证 5.2-a 在 ±20 处确认了这一点），不同的是中间的过渡。ReLU 在 0 处有一个硬拐角；GELU 和 Swish 是光滑的，而且都在负半轴往下沉了一点，形成一个小坑，函数不再单调。Swish 的坑更深。坑底在哪里？令导数为 0：

$$\mathrm{Swish}'(x)=\sigma(x)\big(1+x\,(1-\sigma(x))\big)=0\quad\Longrightarrow\quad\sigma(x^*)=1+\frac{1}{x^*}$$

代回去，$\mathrm{Swish}(x^*)=x^*\sigma(x^*)=x^*+1$：坑底的高度恰好比它的位置大 1。数值上 $x^*\approx-1.2785$，最小值约为 $-0.2785$。

```verify id=5.2-b title="Swish 的最小值等于 x* + 1"
import math

def bisect(f, lo, hi, iters=60):
    """在 [lo, hi] 上用二分法找 f 的零点（要求两端异号）。"""
    for _ in range(iters):
        mid = (lo + hi) / 2
        if f(lo) * f(mid) <= 0:
            hi = mid
        else:
            lo = mid
    return (lo + hi) / 2

# Swish'(x) = σ(x)·(1 + x·(1 − σ(x)))，让括号等于 0
x_star = bisect(lambda x: 1 + x * (1 - sigmoid(x)), -3.0, -0.5)
print(f"Swish 的最小值：x* = {x_star:.4f}，Swish(x*) = {swish(x_star):.4f}")
assert np.isclose(swish(x_star), x_star + 1)                 # σ(x*) = 1 + 1/x*，所以 Swish(x*) = x* + 1

Phi = lambda x: 0.5 * (1 + math.erf(x / math.sqrt(2)))          # 标准正态分布的累积分布函数
phi = lambda x: math.exp(-x * x / 2) / math.sqrt(2 * math.pi)
g_star = bisect(lambda x: Phi(x) + x * phi(x), -3.0, -0.1)       # GELU'(x) = Φ(x) + x·φ(x)
print(f"GELU 的最小值： x* = {g_star:.4f}，GELU(x*)  = {g_star * Phi(g_star):.4f}")
assert -0.18 < g_star * Phi(g_star) < -0.16
```

### 5.2.2 GLU 与 SwiGLU

激活函数逐元素地决定“放行多少”，但放行的规则是固定的。**GLU**（Gated Linear Unit，门控线性单元）把这个决定交给一组可学习的参数[^glu]：输入分成两路，一路经过 sigmoid，变成 0～1 之间的“门” $\sigma(\boldsymbol xW)$，另一路是内容 $\boldsymbol xV$，两者逐元素相乘：

$$\mathrm{GLU}(\boldsymbol x)=\sigma(\boldsymbol xW)\odot(\boldsymbol xV)$$

这里 $\odot$ 表示逐元素相乘。如果你读过《深度学习进阶：自然语言处理》6.2 节，会觉得眼熟：LSTM 的输入门、遗忘门、输出门，都是“sigmoid 的输出 × 内容”，门开多大由数据决定。

Shazeer 在 2020 年把门里的 sigmoid 换成了各种激活函数，在 Transformer 的 FFN 上做了一轮比较[^swiglu]：参数量和计算量都对齐的条件下，门里用 GELU 的 GEGLU 和用 Swish 的 SwiGLU 在留出集上的困惑度最低，都比普通的 ReLU、GELU FFN 好（论文表 1）。用 Swish 的那一个就是 **SwiGLU**：

$$\mathrm{SwiGLU}(\boldsymbol x)=\mathrm{Swish}(\boldsymbol xW)\odot(\boldsymbol xV)$$

手算一下。设某一维上 $a=(\boldsymbol xW)_j$，$b=(\boldsymbol xV)_j$。$a=2$、$b=3$ 时，$\mathrm{Swish}(2)\cdot3=2\times0.8808\times3\approx5.2848$；$a=-2$ 时变成 −0.7152；$a=-8$ 时只剩 −0.0080，这一维几乎被关掉了。与 sigmoid 门不同，Swish 门的输出不局限在 0～1 之间，它本身也带着大小。

[^glu]: Dauphin et al., *Language Modeling with Gated Convolutional Networks*, 2017, [arXiv:1612.08083](https://arxiv.org/abs/1612.08083)
[^swiglu]: Shazeer, *GLU Variants Improve Transformer*, 2020, [arXiv:2002.05202](https://arxiv.org/abs/2002.05202)。表 1（T5 的片段填空任务，留出集 log-perplexity，越低越好）：训练 524,288 步时，ReLU FFN 1.677、GELU FFN 1.679、GEGLU 1.633、SwiGLU 1.636，GEGLU 与 SwiGLU 是八种里最低的两个；65,536 步时也是这两个最低（2026-10 查）。

```verify id=5.2-c title="Swish 门：a 很负时，这一维几乎被关掉"

### 5.2.3 使用 SwiGLU 的 FFN

把 SwiGLU 放进 FFN，后面再接一个把维度缩回去的矩阵 $O$：

$$\mathrm{FFN}(\boldsymbol x)=\big(\mathrm{Swish}(\boldsymbol xW)\odot(\boldsymbol xV)\big)\,O$$

这里 $W$、$V$ 的形状是 $d\times h$，$O$ 是 $h\times d$，$h$ 是中间层的宽度。原来的 FFN 有两个矩阵，现在变成了三个。为了公平比较，通常让参数量保持不变：原来的 FFN（$h=4d$，不算 bias）有 $2\cdot d\cdot 4d=8d^2$ 个参数，SwiGLU 有 $3dh$ 个，令两者相等，得到

$$h=\frac{8d}{3}$$

$d=384$ 时 $h=1024$，两边都是 1,179,648 个参数。$d=512$ 时 $8d/3=1365.33$，不是整数：原书默认的写法 `int(x_dim * 8 / 3)` 得到 1365，参数量与 4d 的 FFN 差了 512 个。

那么，实际训练时取多少呢？StoryBot（ch06/05_pretrain.py）没有用默认值，而是直接给了 `ff_dim = 1344`。1344 = 21 × 64，是离 1365.33 最近的 64 的倍数。LLaMA 向上取到 256 的倍数：$d=4096$ 时 int(8d/3) = 10922，取整后是 11008[^llama-ffn]。取整是为了让矩阵的形状更规整，GPU 上的矩阵乘法更高效[^nv]。

[^llama-ffn]: LLaMA 官方实现中的 `FeedForward`：先 `hidden_dim = int(2 * hidden_dim / 3)`，再取整到 `multiple_of` 的倍数，[meta-llama/llama：model.py](https://github.com/meta-llama/llama/blob/main/llama/model.py)

## 5.3 RMSNorm 及其他改进

### 5.3.1 RMSNorm

[2.9 节](ch02.html#s2-9)的 LayerNorm 对每个 token 的向量做两件事：减去均值，再除以标准差，之后乘上可学习的 $\boldsymbol\gamma$、加上 $\boldsymbol\beta$。如果你读过《深度学习入门：基于Python的理论与实现》6.3 节，会记得 Batch Norm 也在做同一类“强制调整分布”的事，只不过它沿 batch 方向统计；LayerNorm 沿特征方向统计，每个 token 各算各的。

**RMSNorm** 更简单：不减均值，只除以均方根（root mean square，RMS），也不要 $\boldsymbol\beta$[^rmsnorm]：

$$\mathrm{RMSNorm}(\boldsymbol x)=\boldsymbol\gamma\odot\frac{\boldsymbol x}{\sqrt{\frac1d\sum_{i=1}^{d}x_i^2+\varepsilon}}$$

这里 $d$ 是向量的维度，$\varepsilon$ 是防止除以 0 的小常数，$\boldsymbol\gamma$ 是可学习的缩放（初始为全 1）。手算 $\boldsymbol x=(1,2,3,4)$：平方的平均是 $(1+4+9+16)/4=7.5$，RMS 为 $\sqrt{7.5}\approx2.7386$，结果是 (0.3651, 0.7303, 1.0954, 1.4606)。同一个向量做 LayerNorm：均值 2.5，方差 1.25，结果是 (−1.3416, −0.4472, 0.4472, 1.3416)。

[^rmsnorm]: Zhang & Sennrich, *Root Mean Square Layer Normalization*, 2019, [arXiv:1910.07467](https://arxiv.org/abs/1910.07467)。摘要原文：“reduces the running time by 7%~64% on different models”（2026-10 查）。

```verify id=5.3-a title="手算的 LayerNorm 与 RMSNorm"
def layer_norm(x, eps=1e-5):          # γ = 1、β = 0 时的 LayerNorm
    mu = x.mean(-1, keepdims=True)
    var = x.var(-1, keepdims=True)
    return (x - mu) / np.sqrt(var + eps)

def rms_norm(x, eps=1e-5):            # γ = 1 时的 RMSNorm（03_rmsnorm.py）
    return x / np.sqrt((x ** 2).mean(-1, keepdims=True) + eps)

x = np.array([1.0, 2.0, 3.0, 4.0])
print("LayerNorm:", np.array2string(layer_norm(x), precision=4))
print("RMSNorm  :", np.array2string(rms_norm(x), precision=4))
assert np.allclose(rms_norm(x, eps=0), x / np.sqrt(7.5))              # mean(x²) = 30/4 = 7.5
assert np.allclose(layer_norm(x, eps=0), (x - 2.5) / np.sqrt(1.25))   # 均值 2.5，方差 1.25
```

`__init__` 的参数名叫 `x`，其实是向量的维度。γ 初始化为全 1，eps 固定为 1e-5。

两者的关系可以用一句话说清：**LayerNorm 就是先减去均值、再做 RMSNorm**。由此马上得到两条性质。整体乘以一个正数（缩放）时，两者的输出都不变；整体加上一个常数（平移）时，LayerNorm 不变，RMSNorm 却会变。RMSNorm 的输出 RMS 约为 1，但均值不为 0。参数方面，RMSNorm 只有 $d$ 个 γ，LayerNorm 还要再加 $d$ 个 β。

```verify id=5.3-b title="LayerNorm = 先减均值再 RMSNorm；两者都不怕缩放，只有 LayerNorm 不怕平移"

      f"每行均值 {np.array2string(y.mean(-1), precision=3)}")

放弃平移不变性，换来了什么？省掉了“减均值”这一步计算和 β 这组参数。RMSNorm 的作者认为 LayerNorm 起作用主要靠缩放而不是减均值，并报告它在几个任务上效果与 LayerNorm 相当，运行时间在不同模型上省下 7%～64%（论文摘要）[^rmsnorm]。LLaMA 用的也是它。

eps 看起来无关紧要，其实不然。03 的手写版用 1e-5；从 04 开始，原书改用 PyTorch 自带的 `nn.RMSNorm(embed_dim)`。它的 eps 默认是 `None`，意思是取输入数据类型的机器精度 `torch.finfo(dtype).eps`，float32 下是 $2^{-23}\approx1.19\times10^{-7}$。

两者什么时候有区别？RMSNorm 输出的 RMS 等于 $\sqrt{\mathrm{ms}/(\mathrm{ms}+\varepsilon)}$，ms 是输入平方的平均。输入的 RMS 正常（约为 1）时，两种 eps 没有区别。可是在初始化时，embedding 的元素服从 $N(0,\,0.02^2)$，RMS 约为 0.02，ms 约为 $4\times10^{-4}$，eps = 1e-5 会让第一层 RMSNorm 的输出缩小约 1.2%。输入再小一些，差别就大得多：

### 5.3.2 去掉 Dropout

CodeBot 在四个地方用了 dropout：embedding 之后、注意力权重、注意力的输出和 FFN 的输出，比率都是 0.1。如果你读过《深度学习入门：基于Python的理论与实现》6.4.3 节，应该还记得 dropout 是对付过拟合的手段：训练时随机关掉一部分神经元，效果近似于同时训练许多个网络再取平均。改良版 GPT 把它全部去掉了。

为什么可以去掉？先比较一下两个机器人的训练量（StoryBot 的训练集是原书作者放在 Hugging Face 上的 `tiny_stories_train.bin`，大小 1,082,458,446 字节[^hf-bin]）：

```verify id=5.3-e title="CodeBot 把语料看了 61 遍，StoryBot 连一遍都看不完"

CodeBot 把 268 万个 token 的语料反复看了 61 遍，过拟合是实实在在的风险；StoryBot 在整个预训练中连训练集的一遍都看不完，每个 token 平均连一次都见不到，dropout 要防的过拟合风险小得多，它带来的噪声却还在。CS336 第 3 讲给出的理由也是这一条：预训练的数据比参数多得多，语料通常只过一遍，很难被模型记住；较新的模型大多不用 dropout，只靠 weight decay[^cs336-l3]。

[^cs336-l3]: CS336 2026 年第 3 讲 *Architectures, hyperparameters* 的讲义，[stanford-cs336/lectures：lecture_03.pdf](https://github.com/stanford-cs336/lectures/blob/main/lecture_03.pdf)
[^hf-bin]: [huggingface.co/datasets/koki0702/zero-llm-data：storybot/tiny_stories_train.bin](https://huggingface.co/datasets/koki0702/zero-llm-data/resolve/main/storybot/tiny_stories_train.bin)。对这个地址发 HEAD 请求，响应头 `x-linked-size: 1082458446`（2026-10 查）。

去掉 dropout 还有一个好处：前向计算变成了确定的。dropout 只在 train 模式下起作用，同一个输入跑两次会得到不同的结果。第 3 章已经见识过它给 GRPO 带来的麻烦（[3.9 节](ch03.html#s3-9)）：同一个 SFT 起点，只在更新前加一行 `model.eval()`，第 51 轮的准确率就从 60.5% 变成 98.8%（运行记录 codebot-3060ti 与 codebot-grpo-evalfix-3060ti，[验证 2.10-h](ch02.html#v-2.10-h)）。改良版没有 dropout，train 模式和 eval 模式下的前向完全相同，这类问题从根上就没有了。

### 5.3.3 去掉 bias

CodeBot 的注意力投影本来就没有 bias，但 FFN 的两个线性层、LayerNorm 的 β 和输出层都有。改良版把它们全部去掉了：所有 `nn.Linear` 都写着 `bias=False`，RMSNorm 也只有 γ。这样省下的参数微乎其微，在与 CodeBot 同尺寸的模型里只有 17,512 个，约占 0.16%（[验证 5.3-f](#v-5.3-f)）。所以去掉 bias 的主要理由不在参数量。PaLM 的论文报告说，去掉所有的 bias 能让大模型的训练更稳定[^palm]。CS336 第 3 讲也把去掉 bias 列为如今的常见做法，给的理由是省内存和优化更稳定[^cs336-l3]。对本书这种千万参数级的小模型来说，bias 只占 0.16%，省下的内存可以忽略；稳定性的收益是在大模型上观察到的，我们没有在小模型上做过对比。

[^palm]: Chowdhery et al., *PaLM: Scaling Language Modeling with Pathways*, 2022, [arXiv:2204.02311](https://arxiv.org/abs/2204.02311)，第 2 节 “No Biases”。

### 5.3.4 取消权重共享

[2.10 节](ch02.html#s2-10)的 CodeBot 让输入端的 embedding 与输出层共用一个矩阵（`self.embed.weight = self.unembed.weight`）。如果你读过《深度学习进阶：自然语言处理》6.5 节，那里的 RNN 语言模型用的也是这种**权重共享**（weight tying）。改良版不再共享，两者各有一份。

这是一个取舍。共享省下 $V\times E$ 个参数：同尺寸的 CodeBot 里是 384,000 个，StoryBot 里是 5,120,000 个，占后者全部参数的 22.6%（[验证 5.4-b](#v-5.4-b)）。不共享的代价就是这些参数，换来的是输入端（把 id 变成向量）和输出端（给每个词打分）可以各学各的。CS336 作业 1 的参考模型、作业 3 的训练 API 用的也都是不共享的版本。

把本节的三处改动和 5.1、5.2 节的零件放在一起，同尺寸的两个模型的参数可以逐项对上账：

参数量可以手算。每个 Block 有 4 个 $E\times E$ 的注意力矩阵、3 个 SwiGLU 矩阵（共 $3EF$ 个参数）和两个 RMSNorm 的 γ（$2E$）；再加上 embedding、末尾的 RMSNorm 和输出层：

$$N=VE+L\,(4E^2+3EF+2E)+E+EV$$

这里 $V$ 是词表大小，$E$ 是 embed_dim，$L$ 是层数，$F$ 是 ff_dim。头数 $H$ 不出现在公式里，因为 $H$ 个头的总维度 $H\times D$ 正好等于 $E$。

最后，先验算、后实验：刚初始化的模型，loss 应该是多少？[2.10 节](ch02.html#s2-10)对 CodeBot 算过一次，这里换成改良版再算一遍。末尾的 RMSNorm 把每个位置的向量缩放到 RMS ≈ 1（γ 初始为 1），所以它的长度平方约为 $E$；输出层的权重独立地服从 $N(0,\,0.02^2)$，于是每个 logit 近似服从 $N(0,\sigma^2)$，其中

$$\sigma=0.02\sqrt{E}$$

V 个这样的 logit 做 logsumexp，约等于 $\ln\big(V\cdot\mathbb E[e^{z}]\big)=\ln V+\sigma^2/2$（正态分布满足 $\mathbb E[e^{z}]=e^{\sigma^2/2}$）；正确 token 的 logit 平均为 0。所以初始的交叉熵约为

$$L_0\approx\ln V+\frac{\sigma^2}{2}$$

手算 04 的配置：$E=384$，$\sigma=0.02\times\sqrt{384}\approx0.392$，$\sigma^2/2\approx0.0768$，$L_0\approx9.2103+0.0768=9.2871$，比均匀分布的 $\ln V$ 略高一点。

## 5.5 KV cache

模型已经可以拿去训练了（第 6 章）。这一节看另一头：训练好的模型，怎样**高效地**生成文本。

### 5.5.1 文本生成中的浪费

[3.2 节](ch03.html#s3-2)的生成循环是这样的：把目前为止的全部 token 送进模型，取最后一个位置的 logits 选出下一个 token，把它接到末尾，再把全部 token 送进模型……原书 05_kvcache.py 里的 `generate_without_cache` 就是这个写法：

```listing ch05/05_kvcache.py#L255-L267
```

问题就写在第 261 行的注释 `# 毎回、全てのトークンを渡す` 里：“每次都传入全部 token”。生成第 t 个 token 时，前面 t − 1 个 token 早就算过了，这一步又从头算一遍。从 1 个 token 的 prompt 出发生成 n 个 token，模型一共要处理 $1+2+\cdots+n=n(n+1)/2$ 个 token；如果每个 token 只算一次，只需要 n 个。n = 200 时是 20,100 对 200，相差 100.5 倍：

```

如果你读过《深度学习进阶：自然语言处理》7.1 节（隐藏状态见 5.2 节），会记得用 RNN 生成文本时没有这个问题：它把过去的一切压缩进一个固定大小的隐藏状态，每一步只需要上一步的隐藏状态和新 token。Transformer 没有这样一个单一的状态，每一步都要回头看过去的全部 token。那么，“回头看”的时候，究竟哪些计算是省不掉的？

### 5.5.2 Attention 与 KV cache

在模型的各个部件里，只有 Attention 让不同位置的 token 相互作用；embedding、RMSNorm、FFN 都是逐个位置独立计算的。所以只需要盯住 Attention。带因果掩码的 Attention 有两个性质。

第一，**过去的行不变**。第 i 个位置只能看见位置 0～i，后面新来的 token 它看不见，所以它的输出与新 token 无关。第二，**新的一行只需要新 token 的 q，加上全部的 K、V**：新 token 的输出，就是用它自己的 query 给所有 key 打分，再对所有 value 加权求和。

```verify id=5.5-b title="旧的行不随新 token 改变；新的一行只需要新 q 和全部 K、V"
def softmax(s):
    e = np.exp(s - s.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

def causal_attention(Q, K, V):
    T, D = Q.shape
    s = Q @ K.T / np.sqrt(D)
    s = np.where(np.tril(np.ones((T, T), bool)), s, -np.inf)
    return softmax(s) @ V

rng = np.random.default_rng(4)
Q, K, V = (rng.standard_normal((6, 8)) for _ in range(3))      # 6 个 token，head_dim = 8
full = causal_attention(Q, K, V)                                # 训练时的做法：6×6 全部算出来
assert np.allclose(full[:5], causal_attention(Q[:5], K[:5], V[:5]))   # ① 前 5 行与第 6 个 token 无关
last = softmax(Q[5] @ K.T / np.sqrt(8)) @ V                      # ② 新 token：1 个 query 对全部 K、V
assert np.allclose(full[5], last)
print("① 前 5 行不随新 token 改变；② 最后一行只需要新 token 的 q 和全部 K、V")
```

第一个性质会逐层传下去：第 1 层里过去位置的输出不变，第 2 层这些位置的输入就不变，它们的 K、V 也不变……于是每一层里过去位置的 K、V 都是定值，算一次就可以存起来，以后反复使用。这就是 **KV cache**。过去位置的 Q 再也用不上（它们的输出已经算完了），所以只存 K 和 V。

在看原书的 PyTorch 代码之前，我们先用 NumPy 把整件事从头写一遍。下面从 `init_params` 到 `generate` 是一个结构与 storybot/model.py 相同的小 GPT（RoPE、RMSNorm、SwiGLU、pre-norm，权重随机）。`attention` 里加入了 KV cache：`cache` 为 None 时，就是普通的前向计算；不为 None 时，把这次算出的 K、V 接到缓存后面，再用缓存里的全部 K、V 计算。`mask` 参数暂时不用管，后面两节会用到它。

```verify id=5.5-c title="NumPy 小 GPT：有无 KV cache，生成结果与每一步的 logits 都相同"
EPS = float(np.finfo(np.float32).eps)            # nn.RMSNorm(eps=None) 在 float32 下用的 eps

def rmsnorm(x, g):
    return g * x / np.sqrt((x * x).mean(-1, keepdims=True) + EPS)

def silu(x):
    return x / (1.0 + np.exp(-x))

def init_params(V=64, C=32, E=32, H=4, L=2, F=None, theta=10000.0, std=0.02, seed=0):
    """一个与 storybot/model.py 结构相同的小 GPT（权重随机）。C 即 max_context_len。"""
    F = F or int(E * 8 / 3)
    r = np.random.default_rng(seed)
    w = lambda *shape: r.normal(0.0, std, shape)
    D = E // H
    inv_freq = 1.0 / theta ** (2.0 * np.arange(D // 2) / D)
    angles = np.arange(C)[:, None] * inv_freq                  # (C, D/2)，即 RoPE 的 cos/sin 表
    blocks = [dict(g1=np.ones(E), Wq=w(E, E), Wk=w(E, E), Wv=w(E, E), Wo=w(E, E),
                   g2=np.ones(E), W=w(E, F), V=w(E, F), O=w(F, E)) for _ in range(L)]
    return dict(H=H, C=C, emb=w(V, E), blocks=blocks, g=np.ones(E), unemb=w(E, V),
                cos=np.cos(angles), sin=np.sin(angles))

def rope_at(x, P, offset):
    """x: (H, T, D)。与 05_kvcache.py 的 RoPE.forward 相同，包括超出 max_context_len 时的钳位。"""
    T = x.shape[1]
    if offset + T > P["C"]:
        offset = P["C"] - T
    cos, sin = P["cos"][offset:offset + T], P["sin"][offset:offset + T]
    e, o = x[..., 0::2], x[..., 1::2]
    out = np.empty_like(x)
    out[..., 0::2] = e * cos - o * sin
    out[..., 1::2] = e * sin + o * cos
    return out

def attention(x, b, P, cache=None, mask="book"):
    T, E = x.shape
    H = P["H"]
    D = E // H
    split = lambda m: m.reshape(T, H, D).transpose(1, 0, 2)              # (T, E) → (H, T, D)
    q, k, v = split(x @ b["Wq"]), split(x @ b["Wk"]), split(x @ b["Wv"])
    offset = 0 if cache is None else cache["offset"]
    q, k = rope_at(q, P, offset), rope_at(k, P, offset)
    first = cache is None or cache["k"] is None                          # 训练，或者 prefill
    if cache is not None:                                                # KV cache：存下旋转后的 K 和 V
        cache["k"] = k if first else np.concatenate([cache["k"], k], axis=1)
        cache["v"] = v if first else np.concatenate([cache["v"], v], axis=1)
        cache["offset"] += T
        k, v = cache["k"], cache["v"]
    s = q @ k.transpose(0, 2, 1) / np.sqrt(D)                            # (H, T, 缓存长度)
    need_mask = {"book": cache is None or first,     # 原书现在的写法：训练与 prefill 加 mask
                 "buggy": cache is None,             # 8b3911f 之前：用了 cache 就不加
                 "aligned": True}[mask]              # 一般情形：按右下角对齐
    if need_mask:
        Tk = k.shape[1]
        s = np.where(np.tril(np.ones((T, Tk), bool), k=Tk - T), s, -np.inf)
    w = np.exp(s - s.max(-1, keepdims=True))
    w /= w.sum(-1, keepdims=True)
    return (w @ v).transpose(1, 0, 2).reshape(T, E) @ b["Wo"]

def forward(ids, P, caches=None, mask="book"):
    x = P["emb"][ids]                                                    # (T, E)
    for i, b in enumerate(P["blocks"]):
        x = x + attention(rmsnorm(x, b["g1"]), b, P, None if caches is None else caches[i], mask)
        h = rmsnorm(x, b["g2"])
        x = x + (silu(h @ b["W"]) * (h @ b["V"])) @ b["O"]               # SwiGLU
    return rmsnorm(x, P["g"]) @ P["unemb"]                               # (T, V)

def new_caches(P):
    return [dict(k=None, v=None, offset=0) for _ in P["blocks"]]

def generate(P, prompt, n, use_cache, mask="book"):
    """贪心生成 n 个 token。use_cache=False 时每步重算全部 token（generate_without_cache）。"""
    ids = list(prompt)
    caches, feed = new_caches(P), list(prompt)
    for _ in range(n):
        if use_cache:
            logits = forward(np.array(feed), P, caches, mask)   # 第一次是整段 prompt（prefill），之后是 1 个 token（decode）
        else:
            logits = forward(np.array(ids), P)
        ids.append(int(logits[-1].argmax()))
        feed = [ids[-1]]
    return ids

P = init_params()
prompt = [5, 17, 42, 8, 33, 2]
a = generate(P, prompt, 20, use_cache=False)
b = generate(P, prompt, 20, use_cache=True)
print("无 cache：", a[len(prompt):])
print("有 cache：", b[len(prompt):])

    full = forward(np.array(a[:t]), P)[-1]
    inc = forward(np.array(a[:t] if t == len(prompt) else a[t - 1:t]), P, caches)[-1]
    worst = max(worst, np.abs(full - inc).max())
print(f"20 步里 logits 的最大差 < 1e-12 → {worst < 1e-12}")
assert worst < 1e-12
```

### 5.5.3 Prefill 与 Decode

有了 KV cache，生成分成两个阶段。第一次调用把整段 prompt 一起送进模型，算出每个位置的 K、V 存进缓存，同时得到下一个 token 的 logits，这一步叫 **Prefill**。之后每次只送进 1 个新 token：先算出它的 K、V，追加到缓存末尾，再用它的 q 与缓存里的全部 K、V（包括它自己的那一组）算出输出，这一步叫 **Decode**。

两者的计算形态很不一样。Prefill 与训练相同，一次处理很多个 token；如果不加掩码，prompt 前面的 token 就会看见后面的，所以**必须加因果掩码**。Decode 只处理 1 个 token，缓存里的 key 都不在它之后（最后一个就是它自己），所以不需要掩码。

```widget ch05-kv caption="无 cache 时，每一步都把整个下三角重算一遍；有 cache 时，prefill 算一次 prompt 的下三角，之后每一步只算新的一行。打开“prefill 不加 mask”，prompt 内部出现指向未来的红格，它们只在 prompt 除最后一行以外的各行：最后一行本来就能看见整个 prompt。只有一层时，这几行的输出没人用；从第二层起，它们会变成下一层的 K、V 进入缓存，bug 才显形。"
{"prompt": 4, "total": 12}
```

原书仓库早期的代码恰好在这里出过错（纸书 2026-06 出版之前就修好了）。2026-02-18 的 commit 8b3911f 的说明写道：使用 KV cache 时，原来的代码在 Prefill 阶段也没有加因果掩码，未来的 token 被看见了，“自回归生成被破坏，输出重复多、质量低”。修复前的条件是 `if not use_cache:`，也就是只要用了 cache 就不加掩码；修复后改成“训练时或第一次调用时加掩码”。storybot/model.py 里留着修复时写的三行注释，把三种情形说得很清楚：

CS336 第 10 讲用**算术强度**（arithmetic intensity，每传输一个字节做多少次运算）来描述 prefill 与 decode 的差别：prefill 一次处理很多 token，受限于计算（compute-bound）；decode 一次只处理 1 个 token，受限于内存带宽（memory-bound）[^cs336-l10]。我们的模型只有一千多万个参数，情况还要多一层：上面的实验说明，在这台 CPU 上，decode 一步里逐次调用的开销，与读权重、做计算的时间差不多各占一半。

两台设备上的结果，可以用同一笔账来解释：每一步的耗时 ≈ 固定开销 + 真正的计算。固定开销来自依次发出的那近 400 次 torch 调用，与 t 无关；计算量则随参与计算的 token 数增长。在单线程的 CPU 上，计算本身就慢：全部重算一步，t = 800 时要 423 ms，是 t = 1 时的 50 倍，KV cache 省下的正是这部分。到了 GPU 上，同样 800 个 token 一步只要 21 ms，与只算 1 个 token 一样快，多出来的计算完全藏在了固定开销里。

GPU 上的每一次运算，都要经过 Python 和 PyTorch 的调度，再启动一个 GPU kernel。这台机器上，这些开销加起来就是每一步 20 ms 左右，比单线程 CPU 上 decode 一步（7～14 ms）还慢（两份记录不是同一时间测的）；这 20 ms 具体花在了哪里，我们没有再往下拆。KV cache 省的是计算，可这里的瓶颈不在计算，它也就几乎帮不上忙。

那么，在 GPU 上，KV cache 什么时候才划算？要等每一步真正的计算量大到盖过这些固定开销：模型更大（每次矩阵乘法更大），上下文更长（全部重算一步的计算量随 t 增长，在这台 GPU 上到 t = 800 还没有露头），或者一次生成多条序列（batch 越大，每次运算做的事越多）。这几种情形我们没有在这台 GPU 上测，这里是直观的推断。反过来，减少调用的次数也有用：[8.5 节](ch08.html#s8-5)的 `torch.compile` 会把相邻的运算融合成一个 kernel。

速度说完了，再看代价。KV cache 是用空间换时间。每个 token 要在每一层存一份 K 和一份 V，各有 $H_{kv}\times D$ 个数，所以每个 token 占用

$$2\times L\times H_{kv}\times D\times b\ \ \text{字节}$$

这里 $L$ 是层数，$H_{kv}$ 是 K、V 的头数（到目前为止与 query 的头数相同），$D$ 是 head_dim，$b$ 是每个数占的字节数（fp32 为 4，bf16 为 2）。05 的演示模型用 fp32，每个 token 占 2 × 6 × 6 × 64 × 4 = 18,432 字节，256 个 token 是 4.5 MiB。

::: confusion 上下文窗口只有 256K，怎么会“消耗”了 80 万个 token？
常常能看到这样的统计：某个模型的上下文窗口是 256K，可一个智能体任务却记下了 80 万、甚至几千万个 token 的消耗。窗口不是上限吗，怎么会超出去？

关键在于，窗口限制的是**一次请求**的长度，而消耗统计的是**所有请求之和**。模型在两次请求之间不保留任何状态，就像 utils.generate 一开头就 `clear_cache()`。所以智能体每走一轮，都要把系统提示、任务和此前的全部对话重新发送一遍。

手算一个例子。开头有 3,000 个 token，每轮新增 800 个（工具的输出加上模型的回复），一共走 300 轮。最后一次请求是 3,000 + 800 × 300 = 243,000 个 token，在 256K 的窗口之内；但 300 次请求加起来是 3,000 × 300 + 800 × (1 + 2 + … + 300) = 37,020,000 个 token，是窗口的 145 倍。累计量随轮数**平方**增长：轮数翻一倍，累计量差不多变成 4 倍。

如果历史长到连一次请求都装不下呢？那一轮就发不出去了。要继续做下去，只能截掉或压缩最早的历史再发，这与 WebBot 的滑动窗口是同一个思路（本节前面）。所以单次请求永远不会超过窗口。累计量照样随轮数增长，只是超出之后每轮正好多一个窗口那么多，从平方增长变成了线性增长。还是上面的例子，走到第 317 轮，完整的历史就有 256,600 个 token，装不进窗口了。

如果服务端把上一轮的 KV cache 留着（这种做法叫**前缀缓存**（prefix caching）），下一轮只需要为新增的那部分 token 做 prefill，需要重新计算的 token 一共只有 243,000 个，随轮数线性增长[^vllm]。新增的那部分一次就有好几个 token，正需要 5.5.4 节说的“右下角对齐”的掩码。注意，前缀缓存省的是计算，不是“发送了多少 token”：每一轮的请求里照样是全部历史，只是前缀不必重算。它也只在历史还装得下时成立：一旦开始截掉最早的历史，截断处后面的 token 位置全都变了，它们的 K、V 只能重算；截断处之前的部分（例如开头的系统提示）倒还能复用（[验证 5.5-k](#v-5.5-k) 的最后几行）。看到一个消耗数字，先问它数的是“发送的 token”还是“新算的 token”。

带走一句话：窗口管的是每一次请求有多长，消耗算的是所有请求加起来有多少。历史均匀增长时，后者大约是最后一次请求的“轮数的一半”倍（37,020,000 ÷ 243,000 ≈ 152，300 的一半是 150）。
:::

[^vllm]: vLLM 的 PagedAttention 论文讨论了在多个请求之间共享前缀的 KV cache：Kwon et al., *Efficient Memory Management for Large Language Model Serving with PagedAttention*, 2023, [arXiv:2309.06180](https://arxiv.org/abs/2309.06180)

```verify id=5.5-k title="单次请求不超过窗口；累计消耗先随轮数平方增长，超出窗口之后线性增长"

print(f"复用上一轮的 KV cache（前缀缓存）：第 1 轮 prefill {prefill[0]:,} 个，之后每轮 {prefill[1]:,} 个，"
      f"一共 {prefill.sum():,} 个")
assert prefill.sum() == 243_000 and np.all(prefill[1:] == per_turn)

history = base + per_turn * np.arange(1, 401)                 # 走到 400 轮
sent = np.minimum(history, window)                            # 装不下时，只能发送最近的 window 个 token
t_over = int(np.argmax(history > window)) + 1
print(f"走到 400 轮：第 {t_over} 轮的完整历史 {history[t_over - 1]:,} 个 token，装不进窗口；"
      f"此后每轮只发送 {window:,} 个，400 轮累计 {sent.sum():,}")
assert t_over == 317 and history[t_over - 2] <= window < history[t_over - 1]
assert np.all(sent[t_over - 1:] == window) and sent.sum() == 62_520_800   # 超出之后每轮正好多一个窗口：线性增长

# 截断之后前缀缓存为什么失效：用 5.5.2 节的 NumPy 小 GPT，保留开头 2 个 token（比如系统提示），删掉接下来的 2 个
P = init_params(std=0.2, seed=3)
ids = np.array([5, 17, 42, 8, 33, 2, 9, 14, 21, 3])
full_c, cut_c = new_caches(P), new_caches(P)
forward(ids, P, full_c)                                       # 完整的历史
forward(np.r_[ids[:2], ids[4:]], P, cut_c)                    # 截掉第 2、3 个 token 之后再发
for i, (a, b) in enumerate(zip(full_c, cut_c)):
    head = np.abs(a["k"][:, :2] - b["k"][:, :2]).max()        # 截断处之前：开头的 2 个 token
    tail = np.abs(a["k"][:, 4:] - b["k"][:, 2:]).max()        # 截断处之后：同样的 6 个 token，位置往前挪了 2
    print(f"第 {i + 1} 层的 K：截断处之前最大差 {head:.1e}，之后最大差 {tail:.3f}")
    assert head < 1e-12 and tail > 1e-2
```

## 小结

本章保留了 GPT-2 的骨架，把零件换成了现代 LLM 的标准配置。RoPE 用旋转把位置编进 query 和 key，让注意力分数只依赖有方向的位置差，而且不需要任何参数；SwiGLU 用门控的 FFN 代替 GELU 的 FFN，中间宽度取 8d/3，参数量不变；RMSNorm 省掉了减均值和 β。去掉 dropout、bias 和权重共享之后，组装出来的改良版 GPT 就是 StoryBot 的模型。最后，我们看到 KV cache 怎样把生成时的重复计算省掉，也看到了它的几个坑：prefill 必须加掩码，超过上下文长度后位置会被钳住，实测的加速比也远不如计算量之比那么夸张，在 GPU 上、batch = 1 时甚至几乎不省时间。

这些零件在第 III 部还会继续用：WebBot 的模型就是本章的改良版 GPT 加上 GQA 和 Flash Attention（[第 8 章](ch08.html)）。

**本章所学的内容**

- RoPE 把 q、k 按位置旋转，分数只依赖有方向的位置差 $m-n$，没有参数；交错式与 rotate_half 只差一个维度置换，训练好的权重却不能直接互换（[验证 5.1-c](#v-5.1-c)、[验证 5.1-h](#v-5.1-h)）。
- SwiGLU 有三个矩阵，中间宽度取 8d/3 时与 4d 的 FFN 参数量相同；StoryBot 的 1344 = 21 × 64（[验证 5.2-d](#v-5.2-d)）。
- RMSNorm 就是不减均值的 LayerNorm；手写版的 eps = 1e-5 与 `nn.RMSNorm` 默认的 1.19e-7 在小输入上差别巨大（[验证 5.3-b](#v-5.3-b)、[验证 5.3-c](#v-5.3-c)）。
- 改良版 GPT 去掉了位置 embedding、dropout、bias，不再共享权重；StoryBot 有 22,696,448 个参数，初始 loss ≈ ln V + σ²/2（[验证 5.4-b](#v-5.4-b)、[验证 5.4-c](#v-5.4-c)）。
- 在 max_context_len 之内、每次只 decode 1 个 token 时，KV cache 不改变输出；prefill 必须加因果掩码，这个 bug 只有在 prompt ≥ 2 个 token、模型 ≥ 2 层时才显形（[验证 5.5-c](#v-5.5-c)、[验证 5.5-d](#v-5.5-d)）。
- KV cache 省的是计算，每一步的固定开销省不掉：CPU 上生成 200 个 token 只快 5 倍左右，RTX 3060 Ti 上 batch = 1 时几乎不快（[验证 5.5-g](#v-5.5-g)、[验证 5.5-l](#v-5.5-l)）。
- 超过 max_context_len 后位置会被钳住；上下文窗口限制的是单次请求，累计消耗随轮数平方增长（[验证 5.5-i](#v-5.5-i)、[验证 5.5-k](#v-5.5-k)）。

模型已经齐了，还差训练。下一章，我们用 AdamW、warmup 加线性衰减的学习率和 bf16 混合精度，在 3.28 亿个 token 上把它训练成 StoryBot。先说结果：在一张 H100 上，预训练只要 16 分钟，验证集 loss 降到 1.30；连同生成和 DPO，三个脚本一共花了 1.17 美元（运行记录 storybot-h100，[验证 6.5-k](ch06.html#v-6.5-k)）。
