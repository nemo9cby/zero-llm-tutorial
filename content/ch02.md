上一章，我们把 TinyCodes 里的 Python 代码变成了一串 token，词表大小是 1,000（[第 1 章](ch01.html)）。这一章要造的，是读这串 token 的那个东西：**模型**。语言模型做的事情一句话就能说完：给定前面的 token，给出下一个 token 的概率分布。CodeBot 的模型每次最多读入 256 个 token，在每个位置上输出 1,000 个数，分别表示词表里每个 token 成为“下一个”的可能性。

这个模型的核心部件叫作 **Attention**。我们不从论文里的公式讲起，而是从每个 Python 程序员都熟悉的字典出发：先把“按键取值”放宽成“按相似度取值”，得到一个“软字典”（2.1 节）；把它写成矩阵运算（2.2 节）；再修补它在高维时的数值问题（2.3 节）。然后我们退后一步，看清 Transformer 的全貌和 Attention 在其中的角色（2.4 节）。接下来依次补上位置信息、因果掩码、Value 的低秩化和多头（2.5–2.8 节），最后用 LayerNorm、FFN 和残差连接搭成 Transformer 块，组装出 GPT-2（2.9–2.10 节）。

先看终点。本章结束时，我们会得到一个用 `GPT(1000, 256, 384, 6, 6, 1536, 0.1)` 创建的模型。它把形状为 (1, 256) 的 token id 变成形状为 (1, 256, 1000) 的 logits，共有 11,121,640 个参数，这个数我们会在 2.10 节逐项数清楚。本章的代码在 CPU 上几秒钟就能跑完，用 GPU 训练它是第 3 章的事。正文里每个带“验”字印章的单元都能在浏览器里重新运行；需要 PyTorch 的结论，则给出本地测试的命令和源码。

## 2.1 Attention 的基本原理

### 2.1.2 软字典

那么，能不能让查询“差不多对上”也有结果呢？设想一个记录了几部电影的字典：键描述电影的风格，值是某位用户给它打的分。现在来了一部新电影，它的风格与哪个键都不完全相同，我们仍然想估计这位用户会给它打几分。

一个自然的做法是：去看风格相似的那些电影，按相似的程度把它们的评分混合起来，越相似的电影说话越有分量。这就是**软字典**的思路。直观上，它像是去问一位看过很多电影的朋友“这部新片我大概会打几分”，朋友会想起几部类似的片子，按相似程度掂量它们的分数。

严格地讲，软字典要回答三个问题：怎样衡量相似度，怎样把相似度变成权重，怎样用权重混合各个值。DLFS6 的回答分别是点积、softmax 和加权和。用 $\mathbf{q}$ 表示查询向量，$\mathbf{k}_i$ 和 $v_i$ 表示第 $i$ 个键和值（共 $n$ 个）：

$$s_i=\mathbf{q}\cdot\mathbf{k}_i,\qquad w_i=\frac{\exp(s_i)}{\sum_{j=1}^{n}\exp(s_j)},\qquad \text{结果}=\sum_{i=1}^{n}w_iv_i$$

这里，$s_i$ 是查询与第 $i$ 个键的相似度，点积越大越相似；$w_i$ 是 softmax 给出的权重，全是正数且总和为 1，所以结果是各个值的加权平均。

用一个能心算的例子走一遍。设查询 $\mathbf{q}=(1,0)$，两个键 $\mathbf{k}_1=(1,0)$、$\mathbf{k}_2=(0,1)$，对应的值是 10 和 20。相似度为 $(1,0)$，权重为 $\bigl(e/(e+1),\,1/(e+1)\bigr)=(0.731,\,0.269)$，结果是 $10\times0.731+20\times0.269=12.69$。查询更像第一个键，所以结果靠近 10，但第二个值也贡献了一份。

如果你读过《深度学习进阶：自然语言处理》8.1 节，会认出这个结构：那里的 Attention 同样是“内积算相似度 → softmax 得权重 → 加权和”。书中的理由是：“选择”这个操作无法微分，于是干脆全部选上，再按权重混合。

```verify id=2.1-a title="硬字典要么命中要么报错；软字典总能给出加权平均"
import numpy as np

d = {'apple': 100, 'banana': 200, 'cherry': 300, 'durian': 400}
print(d['banana'])
try:
    d['Banana']
    hit = True
except KeyError as err:
    hit = False
    print("KeyError:", err)
assert not hit

def softmax(x):
    x = np.asarray(x)
    e = np.exp(x - x.max(axis=-1, keepdims=True))   # 每行减去自己的最大值（原因见 2.1.3 节）
    return e / e.sum(axis=-1, keepdims=True)        # 每行除以自己的和

q = np.array([1.0, 0.0])                    # (2,)
K = np.array([[1.0, 0.0], [0.0, 1.0]])      # (2, 2)：每行一个键
v = np.array([10.0, 20.0])                  # (2,)
w = softmax(K @ q)                          # (2, 2) @ (2,) -> (2,)
print("权重:", np.round(w, 3), " 结果:", round(float(w @ v), 2))
assert np.isclose(w[0], np.e / (np.e + 1)) and round(float(w @ v), 2) == 12.69
```

注释是日文：類似度 = 相似度，重み付き和 = 加权和，七部电影依次是偏动作、偏剧情、偏喜剧、均衡型、动作剧情片、喜剧剧情片和纯动作片。运行后得到：新电影的预测评分是 78.66 分；权重最大的是 (7, 6, 2)，占 72.62%，其次是 (5, 5, 5)，占 26.71%，其余几部几乎没有分量。

为什么偏偏是这两部？算一下点积就明白了。查询 (6, 4, 5) 与七个键的点积依次是 71、59、59、75、76、70、63。最大的 76 和 75 只差 1，所以权重之比是 $e^{76}:e^{75}=e:1$；其余的点积至少再小 5，$e^{-5}\approx0.007$，几乎可以忽略。于是预测评分约为 $75+5\times\frac{e}{1+e}=75+5\times0.731=78.66$。

```verify id=2.1-b title="复现原书：预测评分 78.66，权重集中在 (7,6,2) 与 (5,5,5)"
keys = np.array([[8, 2, 3], [3, 9, 1], [1, 2, 9], [5, 5, 5],
                 [7, 6, 2], [2, 7, 6], [9, 1, 1]], dtype=float)  # (7, 3)：七部电影的风格
ratings = np.array([85, 70, 60, 75, 80, 65, 90], dtype=float)    # (7,)：用户的评分
new_movie = np.array([6, 4, 5], dtype=float)                     # (3,)：新电影

def soft_dict(q, K, v, T=1.0):
    w = softmax(K @ q / T)        # (7, 3) @ (3,) -> (7,)：相似度 -> 权重（T 是温度，后面会用到）
    return w @ v, w               # (7,) @ (7,) -> 标量：加权和

s = keys @ new_movie              # (7,)：七个点积
result, w = soft_dict(new_movie, keys, ratings)
print("点积:", s.astype(int).tolist())
print(f"预测评分: {result:.2f}")
for k, wi in zip(keys.astype(int).tolist(), w):
    print(f"  {tuple(k)}: {wi * 100:5.2f}%")
assert round(float(result), 2) == 78.66
assert round(float(w[4]) * 100, 2) == 72.62 and round(float(w[3]) * 100, 2) == 26.71
assert abs(result - (75 + 5 * np.e / (1 + np.e))) < 0.01   # 只看最大的两项，已经很接近
```

::: confusion 点积最大的，并不是“最像”的那一部
看到 (7, 6, 2) 拿走了大部分权重，你也许会觉得意外：(6, 4, 5) 看上去明明更像“均衡型”的 (5, 5, 5)。这个直觉没有错，如果用余弦相似度或欧氏距离来衡量，最像的确实是 (5, 5, 5)。问题出在点积本身：$\mathbf{q}\cdot\mathbf{k}=\lVert\mathbf{q}\rVert\,\lVert\mathbf{k}\rVert\cos\theta$，它不只看方向，还看长度。(7, 6, 2) 的长度是 9.43，(5, 5, 5) 只有 8.66，多出来的这一截把它推到了第一。

可以带走的结论是：软字典里的“相似度”是点积，键越长越容易被选中。在真正的 Transformer 里，查询和键都是模型学出来的向量，长度本身也成了模型可以利用的信号；也正因为如此，不要把注意力权重直接读成“最近邻”。
:::

```verify id=2.1-c title="点积挑中 (7,6,2)，余弦与欧氏距离挑中 (5,5,5)"

dist = np.linalg.norm(keys - new_movie, axis=1)                                        # (7, 3) - (3,) -> (7,)
pick = lambda i: tuple(keys[i].astype(int).tolist())
print("点积最大:", pick(s.argmax()), " 余弦最大:", pick(cos.argmax()), " 距离最近:", pick(dist.argmin()))
print(f"长度: |(7,6,2)| = {np.linalg.norm(keys[4]):.2f}, |(5,5,5)| = {np.linalg.norm(keys[3]):.2f}")
assert pick(s.argmax()) == (7, 6, 2)
assert pick(cos.argmax()) == pick(dist.argmin()) == (5, 5, 5)
```

软字典和硬字典之间是什么关系？在 softmax 之前把相似度除以一个正数 $T$，就得到带**温度**（temperature）的版本：$\mathbf{w}=\mathrm{softmax}(\mathbf{s}/T)$。$T$ 越小，最大的那个相似度越占优势，权重越接近“只选一个”；$T\to0$ 时，软字典退化成“取相似度最大的键的值”。反过来，$T$ 越大，权重越平均；$T\to\infty$ 时，结果就是所有值的简单平均。

既然 $T\to0$ 就是“取最像的那个”，那么拿字典里的某个键本身去查询，应该原样取回它的值，和硬字典一样。我们来确认一下：

```verify id=2.1-d title="T→0 退化为硬查找，但遇到并列就不是；T→∞ 变成简单平均"
for k, v_true in zip(keys, ratings):
    r, _ = soft_dict(k, keys, ratings, T=0.001)
    print(f"用键 {tuple(k.astype(int).tolist())} 查询 -> {r:6.2f}   (字典里的值 {v_true:.0f})")
r_hot, _ = soft_dict(new_movie, keys, ratings, T=1e6)
print(f"T = 1e6 时: {r_hot:.2f}，正是七个评分的平均 {ratings.mean():.2f}")
assert round(float(soft_dict(keys[0], keys, ratings, T=0.001)[0]), 2) == 87.5    # (8,2,3) 与 (9,1,1) 并列
assert round(float(soft_dict(keys[3], keys, ratings, T=0.001)[0]), 2) == 73.33   # 三方并列
assert abs(r_hot - 75.0) < 1e-3
```

七次查询里，有五次原样取回了值，但 (8, 2, 3) 得到 87.5，(5, 5, 5) 得到 73.33。原因还是点积：(8, 2, 3) 与自己的点积是 64 + 4 + 9 = 77，与 (9, 1, 1) 的点积是 72 + 2 + 3 = 77，两者并列，权重各占一半，结果是 85 与 90 的平均 87.5；(5, 5, 5) 与自己、与 (7, 6, 2)、与 (2, 7, 6) 的点积都是 75，三方并列，结果是 (75 + 80 + 65) / 3 = 73.33。所以“软字典在 $T\to0$ 时等于硬字典”这句话，只在没有并列时成立。

::: warn 原书的 softmax 会溢出
原书的 `soft_dictionary` 直接计算 `np.exp(similarity)`，没有先减去最大值。书中的点积最大只有 76，所以没有问题；但 float64 的 `exp` 在参数超过约 709.8 时就会溢出成 `inf`，结果变成 `inf / inf = nan`。如果相似度放大 10 倍（比如特征的取值范围变大，或者向量的维度变高），点积就会超过 700，正好越过这条线。如果你读过《深度学习入门：基于Python的理论与实现》3.5.2 节，会记得解决办法：softmax 的输入同时减去同一个常数，结果不变；先减去最大值，最大的指数就是 $e^0=1$，不会溢出。我们在[验证 2.1-a](#v-2.1-a) 里写的 `softmax` 就是这么做的。
:::

```verify id=2.1-e title="朴素 softmax 溢出成 nan；减去最大值不改变结果"
s10 = s * 10                                     # 相似度放大 10 倍：最大 760
print("放大后的点积:", s10.astype(int).tolist())
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(s10) / np.exp(s10).sum()      # 原书的写法
print("朴素写法:", naive)
print("先减最大值:", np.round(softmax(s10), 4))
x3 = np.array([1.0, 2.0, 3.0])
print("平移不变:", np.allclose(softmax(x3), softmax(x3 + 100)), "  但缩放会变:", np.round(softmax(10 * x3), 4))
assert np.isnan(naive).any() and np.isclose(softmax(s10).sum(), 1.0)
assert np.allclose(softmax(x3), softmax(x3 + 100))
```

## 2.2 Attention 的公式与实现

### 2.2.1 用公式表示 Attention

2.1 节的软字典用 for 循环逐个计算点积。现在我们把它写成矩阵运算。按照《深度学习进阶：自然语言处理》1.1 节的习惯，向量一律写成行向量：查询 $\mathbf{q}$ 是 1×3 的矩阵，把 7 个键按行叠起来得到 7×3 的矩阵 $K$，7 个值叠起来得到 7×1 的矩阵 $V$。于是

$$\mathbf{y}=\mathrm{softmax}(\mathbf{q}K^\top)\,V$$

这里，$\mathbf{q}K^\top$ 的形状是 (1, 3) × (3, 7) = (1, 7)，正好是 7 个点积；softmax 把它们变成 7 个权重；再乘以 (7, 1) 的 $V$，得到 (1, 1) 的结果，也就是加权和。三行 for 循环，变成了两次矩阵乘法。

### 2.2.2 支持多个查询

如果有好几部新电影要预测呢？把它们的查询也按行叠起来，得到矩阵 $Q$，公式几乎不用改：

$$Y=\mathrm{softmax}(QK^\top)\,V$$

这里的 softmax 对 $QK^\top$ 的**每一行**分别计算。原书用了三个查询：(6, 4, 5)、(2, 8, 3) 和 (4, 3, 7)。于是 $Q$ 是 3×3，$QK^\top$ 是 3×7，其中第 $i$ 行第 $j$ 列是第 $i$ 个查询与第 $j$ 个键的点积；$Y$ 是 3×1，每行是一部新电影的预测评分。

```verify id=2.2-a title="矩阵形式一次算出三个查询：78.66 / 69.76 / 61.20"
def attention(Q, K, V):
    S = Q @ K.T          # (3, 3) @ (3, 7) -> (3, 7)：每行是一个查询与 7 个键的点积
    W = softmax(S)       # (3, 7)：逐行 softmax，每行之和为 1
    return W @ V         # (3, 7) @ (7, 1) -> (3, 1)：逐行加权和

Q = np.array([[6, 4, 5], [2, 8, 3], [4, 3, 7]], dtype=float)   # (3, 3)：三部新电影
V = ratings[:, None]                                            # (7,) -> (7, 1)
Y = attention(Q, keys, V)
print("Q", Q.shape, " K", keys.shape, " V", V.shape, " ->  Y", Y.shape)
print("预测评分:", [f"{y:.2f}" for y in Y[:, 0]])
print("每行权重之和:", np.round(softmax(Q @ keys.T).sum(axis=-1), 12))
assert [round(float(y), 2) for y in Y[:, 0]] == [78.66, 69.76, 61.2]
assert np.isclose(Y[0, 0], result)               # 第一行就是 2.1 节的结果
```

::: column Attention 的逐行计算
矩阵形式看起来像是一次“整体”的计算，其实它只是把每一行各算各的，再叠起来。$Y$ 的第 $i$ 行只取决于 $Q$ 的第 $i$ 行：$\mathbf{y}_i=\mathrm{softmax}(\mathbf{q}_iK^\top)\,V$，这正是 2.1 节针对单个查询的软字典。换句话说，矩阵乘法只是替我们写好了那个“对每个查询循环一遍”的 for 循环。

```verify id=2.2-b title="逐行算一遍，结果与矩阵形式完全相同"
rows = np.vstack([softmax(q_i @ keys.T) @ V for q_i in Q])   # 每次一行：(3,) @ (3, 7) -> (7,)；(7,) @ (7, 1) -> (1,)
print("逐行:", rows.shape, "  与矩阵形式相同:", np.allclose(rows, attention(Q, keys, V)))
assert np.allclose(rows, attention(Q, keys, V))
```

这个读法有两个用处。第一，它说明 softmax 必须按行做：每一行用自己的最大值、自己的分母。第二，2.6 节的因果掩码也是一条逐行的规则：“第 $i$ 行只能看第 0 到第 $i$ 个键”。
:::

::: confusion 每行的最大值，为什么要写 keepdims=True？
逐行计算最容易出错的地方，是求每行最大值和分母时的形状。`S.max(axis=-1)` 的形状是 (3,)，而 `S` 是 (3, 7)。两者直接相减时，NumPy 按**广播**（broadcasting）规则从最后一维开始对齐：7 和 3 对不上，于是报错。这还算幸运。

到了 2.6 节，分数矩阵会变成 C×C 的方阵。这时形状为 (C,) 的“每行最大值”会被当成一个**行向量**，悄悄地减到每一**列**上：不报错，每行之和也还是 1，结果却是错的。同样的事故也会发生在别处，比如形状 (3,) 的标签减去形状 (3, 1) 的预测，得到的是一个 3×3 的矩阵，求平均之后照样是一个“正常”的数。

可以带走的结论是：按行做的归约（max、sum、mean）一律写 `axis=-1, keepdims=True`，让结果保持 (…, 1) 的形状；遇到方阵时，形状对得上并不代表算对了。
:::

```verify id=2.2-c title="忘了 keepdims：长方阵报错，方阵悄悄算错"
def softmax_no_keepdims(S):
    e = np.exp(S - S.max(axis=-1))                 # (C, C) - (C,)：(C,) 被广播成一行，减到了每一列上

    print("长方阵:", err)
```

## 2.3 Attention 缩放

### 2.3.1 softmax 函数的饱和问题

在电影的例子里，点积最大只有 76，结果就已经很“偏心”了：最大的两项只差 1，权重之比就是 e : 1。如果点积的数值再大一些，会发生什么呢？原书的第三个脚本先做了一个极端的实验：

```listing ch02/03_attn_scaling.py#L1-L6
```

输出是 `tensor([0.0000e+00, 3.7835e-44, 1.0000e+00])`：几乎全部权重都落在了 300 上。这是因为 softmax 只关心输入之间的**差**：$e^{200}/e^{300}=e^{-100}\approx3.7\times10^{-44}$。输入相差 100，权重就相差 $e^{100}pprox2.7	imes10^{43}$ 倍。这种几乎只有一个 1、其余全是 0 的状态，叫作 softmax 的**饱和**（saturation）。

饱和有什么坏处呢？第一，软字典又变回了硬字典，加权混合的好处没有了。第二，也是更要紧的一点：梯度消失了。softmax 的输出 $\mathbf{p}$ 对输入 $\mathbf{s}$ 的导数是一个矩阵（雅可比矩阵），$J=\mathrm{diag}(\mathbf{p})-\mathbf{p}^\top\mathbf{p}$，它的对角元素是 $p_i(1-p_i)$。当 $\mathbf{p}$ 接近 one-hot 时，每个 $p_i$ 不是接近 0 就是接近 1，$J$ 的所有元素都接近 0：无论分数怎样微调，输出几乎不变，学习也就无从谈起。

手算一下：输入 (1, 2, 3) 时，softmax 是 (0.090, 0.245, 0.665)，最大的对角元素是 $0.665\times0.335=0.223$；输入 (100, 200, 300) 时，$J$ 的元素全都小到 $10^{-44}$ 量级。

```verify id=2.3-a title="softmax 饱和：输出几乎 one-hot，雅可比矩阵几乎为 0"
def softmax_jacobian(p):
    return np.diag(p) - np.outer(p, p)        # (n, n)：J[i, j] = ∂p_i / ∂s_j

for s_in in (np.array([1.0, 2.0, 3.0]), np.array([100.0, 200.0, 300.0])):
    p = softmax(s_in)
    print(f"s = {s_in.tolist()}  p = {np.array2string(p, precision=4)}  max|J| = {np.abs(softmax_jacobian(p)).max():.3g}")
print("float32 下（与原书的输出相同）:", softmax(np.array([100.0, 200.0, 300.0], dtype=np.float32)))
assert abs(softmax_jacobian(softmax(np.array([1.0, 2.0, 3.0])))[2, 2] - 0.665 * 0.335) < 1e-3
assert np.abs(softmax_jacobian(softmax(np.array([100.0, 200.0, 300.0])))).max() < 1e-40
```

### 2.3.2 引入缩放

分数为什么会变大？问题出在维度上。设查询 $\mathbf{q}$ 和键 $\mathbf{k}$ 都是 $d$ 维向量，各个分量相互独立，均值为 0、方差为 1。点积 $\mathbf{q}\cdot\mathbf{k}=\sum_{i=1}^{d}q_ik_i$ 是 $d$ 项之和，每一项 $q_ik_i$ 的均值为 0，方差为 $\mathrm{E}[q_i^2]\,\mathrm{E}[k_i^2]=1$。独立随机变量之和的方差等于方差之和，所以

$$\mathrm{Var}(\mathbf{q}\cdot\mathbf{k})=d$$

这里，$d$ 是向量的维数。标准差是 $\sqrt{d}$：$d=64$ 时，点积的典型大小是 8；$d=1024$ 时是 32。维度越高，分数越大，softmax 越容易饱和。

解决办法很直接：把点积除以 $\sqrt{d}$，方差就回到 $d/d=1$。这就是 Transformer 论文（[Vaswani et al., 2017](https://arxiv.org/abs/1706.03762)）里的**缩放点积注意力**（scaled dot-product attention）：

$$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

原书用 10,000 次采样来确认方差（$d=10$）：

```listing ch02/03_attn_scaling.py#L24-L49
```

脚本没有固定随机种子，每次运行的数值略有不同；但两个方差之比永远恰好是 10，因为把数据除以 $\sqrt{10}$ 会让方差恰好变成原来的 1/10，这是代数恒等式，与采样无关。我们换成 $d=64$ 并固定种子再做一次。严格的推导（需要哪些独立性假设）见[附录 B](appendix-b.html)。

```verify id=2.3-b title="Var(q·k) ≈ d；除以 √d 之后 ≈ 1"
rng = np.random.default_rng(0)
d = 64
q_s = rng.standard_normal((10000, d))      # (10000, 64)：一万个随机查询
k_s = rng.standard_normal((10000, d))      # (10000, 64)：一万个随机键

assert abs(dots.var() / d - 1) < 0.1                     # 一万个样本，采样误差约 1.5%
assert abs(dots.var() / (dots / np.sqrt(d)).var() - d) < 1e-9
```

### 2.3.3 缩放的效果

缩放到底改变了什么？我们做一个对照实验：随机生成 256 个键和 100 个查询，分别用不缩放和缩放的分数做 softmax，统计每行最大的那个权重（越接近 1 越尖锐）、最大权重超过 0.99 的行占多少（饱和的比例），以及雅可比矩阵的大小（梯度有多大）。

```verify id=2.3-c title="不缩放时 d 越大越尖锐；缩放后尖锐程度与 d 无关"
rng = np.random.default_rng(0)
n_keys, trials = 256, 100
table = {}
print("    d | 不缩放: 最大权重 饱和比例  ‖J‖ | 缩放后: 最大权重 饱和比例  ‖J‖")
for d in (4, 16, 64, 256, 1024):
    K_r = rng.standard_normal((n_keys, d))           # (256, d)：256 个随机键
    Q_r = rng.standard_normal((trials, d))           # (100, d)：100 个随机查询
    raw = Q_r @ K_r.T                                # (100, d) @ (d, 256) -> (100, 256)
    row = []
    for sc in (raw, raw / np.sqrt(d)):
        P_r = softmax(sc)                            # (100, 256)：每行是一个查询的注意力
        s2, s4 = (P_r ** 2).sum(-1), (P_r ** 4).sum(-1)
        jac = np.sqrt(np.maximum((P_r ** 2 * (1 - P_r) ** 2).sum(-1) + s2 ** 2 - s4, 0))   # ‖diag(p) - pᵀp‖_F
        row += [P_r.max(-1).mean(), (P_r.max(-1) > 0.99).mean(), jac.mean()]
    table[d] = row
    print(f"{d:5d} |          {row[0]:.3f}    {row[1]:.2f}  {row[2]:.3f} |          {row[3]:.3f}    {row[4]:.2f}  {row[5]:.3f}")
unscaled_max = [table[d][0] for d in table]
scaled_max = [table[d][3] for d in table]
assert all(a < b for a, b in zip(unscaled_max, unscaled_max[1:]))   # 不缩放：d 越大越尖
assert max(scaled_max) - min(scaled_max) < 0.01                     # 缩放后：与 d 无关
assert table[1024][1] > 0.5 and max(table[d][4] for d in table) == 0
assert table[4][2] < table[16][2] > table[1024][2]                  # 不缩放时 ‖J‖ 先升后降
```

不缩放时，$d$ 越大，最大权重越接近 1，饱和的行越多；$d=1024$ 时，七成以上的行已经把几乎全部权重压在一个键上。缩放之后，最大权重稳定在 0.04 左右，不随 $d$ 变化。

这里值得停下来想一想。把分数除以 $\sqrt{d}$，等价于把 2.1 节的温度设为 $T=\sqrt{d}$。反过来看，不缩放的 softmax 作用在方差为 1 的“标准分数” $\mathbf{q}\cdot\mathbf{k}/\sqrt{d}$ 上，相当于温度 $T=1/\sqrt{d}$：维度越高，温度越低，分布越尖。所以缩放真正修正的，是“softmax 的温度随 $d$ 漂移”这件事：缩放之后，不管 $d$ 是 16 还是 1024，注意力的尖锐程度都一样。

表的最后一列还藏着一个容易被说错的地方。常见的说法是“不缩放会导致梯度消失”。但不缩放时，雅可比矩阵的大小并不随 $d$ 单调下降：$d=16$ 时它反而比缩放之后更大。中等尖锐的分布梯度最大，只有接近 one-hot 时梯度才真正消失。所以更准确的说法是：不缩放时，有效温度随 $d$ 变化；$d$ 大到一定程度，softmax 饱和，梯度才消失。


## 2.4 Transformer 的基本结构

### 2.4.1 Transformer 的运作流程

到这里，我们已经有了 Attention 这个零件。在继续打磨它之前，先退后一步，看看它将被装进一台什么样的机器。GPT 系列使用的是 **Transformer** 的解码器部分，它处理一串 token 的流程如下表。形状以 CodeBot 为例：批大小 B = 1，序列长度 C = 256，嵌入维数 E = 384，词表大小 V = 1000。

| 步骤 | 做什么 | 输出形状 | 详见 |
|---|---|---|---|
| 1. 输入 | token id 序列 | <span style="white-space:nowrap">(1, 256)</span> | 第 1 章 |
| 2. 嵌入 | 查表把每个 id 换成 384 维向量，再加上位置向量 | <span style="white-space:nowrap">(1, 256, 384)</span> | 2.5 节、2.10 节 |
| 3. Transformer 块 × 6 | Attention 在位置之间交换信息，FFN 在每个位置内部加工 | <span style="white-space:nowrap">(1, 256, 384)</span> | 2.6–2.9 节 |
| 4. 最终 LayerNorm | 规范化每个位置的向量 | <span style="white-space:nowrap">(1, 256, 384)</span> | 2.9 节 |
| 5. 反嵌入 | 一个线性层把 384 维映射成 1000 个分数（logits） | <span style="white-space:nowrap">(1, 256, 1000)</span> | 2.10 节 |
| 6. softmax | 每个位置得到“下一个 token”的概率分布 | <span style="white-space:nowrap">(1, 256, 1000)</span> | 本节专栏 |

注意形状的变化：从第 2 步到第 4 步，形状始终是 (1, 256, 384)。每个 Transformer 块读进这样一个张量，再写出同样形状的张量，所以块可以像积木一样一个接一个地叠起来。只有开头的嵌入和结尾的反嵌入，在“token 的世界”和“向量的世界”之间来回转换。

```verify id=2.4-a title="形状流程：(1, 256) → (1, 256, 384) → (1, 256, 1000)"
rng = np.random.default_rng(0)
B, C, E, V_size = 1, 256, 384, 1000
ids = rng.integers(0, V_size, size=(B, C))           # (1, 256)：token id
tok_table = rng.normal(0, 0.02, size=(V_size, E))     # (1000, 384)：每个 token 一行
pos_table = rng.normal(0, 0.02, size=(C, E))          # (256, 384)：每个位置一行
x_emb = tok_table[ids] + pos_table                     # (1, 256, 384) + (256, 384) -> (1, 256, 384)，按最后两维广播
onehot = np.eye(V_size)[ids[0, 0]]                     # (1000,)
assert np.allclose(onehot @ tok_table, tok_table[ids[0, 0]])   # 查表 == one-hot 乘以矩阵
# ……中间是 6 个 Transformer 块，每块的输入输出都是 (1, 256, 384)……
W_out = rng.normal(0, 0.02, size=(V_size, E))         # (1000, 384)：反嵌入
logits = x_emb @ W_out.T                               # (1, 256, 384) @ (384, 1000) -> (1, 256, 1000)
print(ids.shape, "->", x_emb.shape, "->", logits.shape)
assert logits.shape == (1, 256, 1000)
```

::: column Transformer 与句子的概率计算
语言模型给一个句子打分的方式，是把它拆成一连串“猜下一个”。设句子由 token $w_1,w_2,\dots,w_T$ 组成，根据概率的乘法定理（链式法则），

$$P(w_1,\dots,w_T)=P(w_1)\,P(w_2\mid w_1)\cdots P(w_T\mid w_1,\dots,w_{T-1})=\prod_{t=1}^{T}P(w_t\mid w_{<t})$$

这里，$w_{<t}$ 表示第 $t$ 个 token 之前的全部 token。右边的每一项都是“已知前文，下一个 token 恰好是 $w_t$ 的概率”，这正是上表最后一步在每个位置输出的东西。如果你读过《深度学习进阶：自然语言处理》5.1.2 节，会记得语言模型就是这样定义的；那里的 RNN 一个时刻接一个时刻地算这些条件概率，Transformer 则在一次前向计算里同时给出所有位置的条件概率。

连乘的结果很快会小到难以处理，所以实际计算时取对数，把乘积变成求和，再取负号并对 token 数求平均：

$$L=-\frac{1}{T}\sum_{t=1}^{T}\ln P(w_t\mid w_{<t})$$

这就是训练时最小化的**交叉熵**（cross entropy）损失。如果你读过《深度学习入门：基于Python的理论与实现》4.2.2 节，会认出它：正确答案是一个 one-hot 向量，交叉熵只取出正确那一项的 $-\ln$ 概率。

手算一个例子。一个 3 个 token 的句子，三个条件概率依次是 0.5、0.2、0.1，句子的概率就是 $0.5\times0.2\times0.1=0.01$。$-\ln0.01=4.605$，平均到每个 token 是 1.535。它的指数 $e^{1.535}=4.64$ 叫作**困惑度**（perplexity），可以理解为“模型平均在 4.64 个候选之间犹豫”（《深度学习进阶：自然语言处理》5.5.2 节）。

最后还要确认一件事：把条件概率连乘起来，得到的真是一个概率分布吗？也就是说，所有可能的句子的概率加起来，是不是恰好等于 1？下面的验证用一个随意编造的“模型”检查了这一点：只要每一步给出的都是合法的分布，连乘的结果就是合法的分布。
:::

```verify id=2.4-b title="链式法则：条件概率连乘是一个合法的分布；交叉熵 = 平均负对数概率"
import itertools
probs = np.array([0.5, 0.2, 0.1])
L_ce = -np.log(probs).mean()
print(f"P(句子) = {probs.prod():.3f}   交叉熵 = {L_ce:.3f} nats/token   困惑度 = {np.exp(L_ce):.2f}")
assert np.isclose(L_ce, -np.log(probs.prod()) / 3) and np.isclose(np.exp(L_ce), 0.01 ** (-1 / 3))

rng = np.random.default_rng(0)
cond = {}
def next_dist(prefix):                        # 随意编造的“模型”：给每个前缀一个下一 token 的分布
    if prefix not in cond:
        cond[prefix] = softmax(rng.normal(size=3))   # 词表大小 3
    return cond[prefix]

total = sum(np.prod([next_dist(seq[:t])[tok] for t, tok in enumerate(seq)])
            for seq in itertools.product(range(3), repeat=4))       # 全部 3^4 = 81 个长度为 4 的句子
print(f"81 个句子的概率之和 = {total:.12f}")
assert abs(total - 1) < 1e-12
```

::: confusion “nats”是什么单位？
用自然对数 ln 计算交叉熵时，单位叫 **nat**；用以 2 为底的对数计算时，单位是 **bit**。两者只差一个常数因子：1 nat = $1/\ln2$ = 1.4427 bits。PyTorch 的 `F.cross_entropy` 用的是自然对数，所以训练日志里的 loss 都是 nats。

记住一个基准就够用了：如果模型对下一个 token 毫无头绪，只能在 V 个 token 里平均地猜，每个 token 的概率是 1/V，交叉熵就是 $\ln V$。CodeBot 的词表有 1,000 个 token，$\ln1000=6.9078$ nats，也就是 9.97 bits，困惑度恰好是 1000，即“在全部 1000 个候选之间犹豫”。第 3 章开始训练时，日志里的第一个 loss 会出现在这个数附近；2.10 节会解释，为什么刚初始化的模型实际会比它略高一点，约为 6.98。如果你在别处看到 9.97，那多半是同一件事用 bits 报告的结果。
:::

```verify id=2.4-c title="均匀瞎猜的交叉熵是 ln V；nats 与 bits 只差 1/ln 2"

```

### 2.4.2 Attention 在 Transformer 中的作用

表里第 3 步有一句话值得细看：Attention 在位置之间交换信息，FFN 在每个位置内部加工。在一个 Transformer 块里，只有 Attention 会让第 $i$ 个位置的输出依赖其他位置的输入；LayerNorm 和 FFN（2.9 节）都是对每个位置的向量单独做同样的运算，位置之间互不相干。这有点像开会：Attention 是大家互相交流的环节，FFN 是各自回到座位上消化。

严格地讲，这意味着：改动第 $j$ 个位置的输入，FFN 的输出只有第 $j$ 行会变；Attention 的输出则是所有能“看到”位置 $j$ 的行都会变。我们用一个随机的小例子确认一下。这里的 Attention 还没有掩码，每个位置都能看到所有位置。

```verify id=2.4-d title="FFN 逐位置独立，Attention 让位置之间互通"
rng = np.random.default_rng(1)
x = rng.normal(size=(5, 8))                             # (5, 8)：5 个位置，每个 8 维
W1, W2 = rng.normal(size=(8, 32)), rng.normal(size=(32, 8))
Wq, Wk, Wv = (rng.normal(size=(8, 8)) for _ in range(3))
ffn_toy = lambda x: np.maximum(x @ W1, 0) @ W2          # (5, 8) -> (5, 32) -> (5, 8)：逐行计算
attn_toy = lambda x: softmax((x @ Wq) @ (x @ Wk).T / np.sqrt(8)) @ (x @ Wv)   # (5, 5) @ (5, 8) -> (5, 8)
x2 = x.copy()
x2[2] += 1.0                                            # 只改动位置 2
changed = lambda f: (np.abs(f(x2) - f(x)).max(axis=-1) > 1e-12).astype(int).tolist()
print("FFN 输出变化的位置:      ", changed(ffn_toy))
print("Attention 输出变化的位置:", changed(attn_toy))
assert changed(ffn_toy) == [0, 0, 1, 0, 0] and changed(attn_toy) == [1, 1, 1, 1, 1]
```

没有掩码时，改动位置 2 会影响所有位置，包括排在它前面的位置 0 和 1。在 2.6 节我们会看到，这恰恰是训练语言模型时必须堵上的漏洞。

## 2.5 位置编码

### 2.5.1 为什么需要位置信息

Attention 有一个奇特的性质：它不知道顺序。点积只看两个向量的内容，不管它们排在第几位。如果把输入的 token 打乱顺序，没有掩码的 Attention 的输出只是跟着一起打乱，每个 token 得到的输出向量完全不变。这个性质叫作**置换等变**（permutation equivariance）。

对语言来说，这是个大问题。CodeBot 的分词器把 `return a - b` 和 `return b - a` 都切成同样的 5 个 token（`re`、`turn`、` a`、` -`、` b`），只是顺序不同，意思却正好相反。

```localcheck verify/test_ch02.py::test_return_a_minus_b_and_b_minus_a_are_the_same_tokens title="两段代码的 token 完全相同，只有顺序不同"
```

```verify id=2.5-a title="没有位置信息的 Attention 对顺序视而不见"
perm = [4, 2, 0, 1, 3]                                  # 打乱顺序

print("先打乱再算 == 先算再打乱:", same)
assert same
```

### 2.5.2 位置编码的机制

解决办法是把位置信息直接“写进”输入向量：给每个位置 $t$ 准备一个向量 $\mathbf{p}_t$，加到该位置的 token 嵌入上：

$$\mathbf{x}_t=\mathbf{e}(w_t)+\mathbf{p}_t$$

这里，$\mathbf{e}(w_t)$ 是 token $w_t$ 的嵌入向量，$\mathbf{p}_t$ 是第 $t$ 个位置的**位置编码**（positional encoding）。同一个 token 出现在不同的位置，得到的输入向量就不一样了，Attention 的点积也就能区分顺序。

```verify id=2.5-b title="加上位置向量之后，打乱顺序会改变每个 token 的输出"
pos_vecs = rng.normal(size=x.shape)                      # (5, 8)：每个位置一个向量
with_pos = lambda x: attn_toy(x + pos_vecs)              # 先加位置向量，再做 Attention
diff = np.abs(with_pos(x[perm]) - with_pos(x)[perm]).max()
print(f"加上位置向量后，打乱前后的最大差: {diff:.2f}")
assert diff > 0.1
```

### 2.5.3 绝对位置编码

位置向量从哪里来？Transformer 的原论文用的是一组固定的正弦、余弦函数：

$$\mathrm{PE}(p,2i)=\sin\!\left(\frac{p}{10000^{2i/d}}\right),\qquad \mathrm{PE}(p,2i+1)=\cos\!\left(\frac{p}{10000^{2i/d}}\right)$$

这里，$p$ 是位置，$i$ 是维度对的编号（$0\le i<d/2$），$d$ 是向量的维数。每一对维度就像一根以不同速度旋转的时钟指针：前面的维度转得快，后面的维度转得慢。

它有一个漂亮的性质：两个位置编码的点积只取决于它们的距离。看最简单的 $d=2$：$\mathrm{PE}(p)=(\sin p,\cos p)$，于是 $\mathrm{PE}(p)\cdot\mathrm{PE}(p+k)=\sin p\,\sin(p+k)+\cos p\,\cos(p+k)=\cos k$，与 $p$ 无关。一般的 $d$ 也一样，因为每一对维度都满足这个恒等式。像这样直接为每个位置指定一个向量的做法，叫作**绝对位置编码**（absolute positional encoding）。

```verify id=2.5-c title="正弦位置编码：PE(p)·PE(p+k) 只取决于距离 k"
def sinusoidal(n_pos, d):
    pos = np.arange(n_pos)[:, None]                      # (n_pos, 1)
    i = np.arange(d // 2)[None, :]                       # (1, d/2)
    ang = pos / 10000 ** (2 * i / d)                     # (n_pos, 1) 与 (1, d/2) 广播 -> (n_pos, d/2)
    pe = np.zeros((n_pos, d))
    pe[:, 0::2], pe[:, 1::2] = np.sin(ang), np.cos(ang)  # 偶数维放 sin，奇数维放 cos
    return pe

pe = sinusoidal(256, 64)
for k in (1, 5, 50):
    print(f"k = {k:2d}: PE(p)·PE(p+k)，p = 0, 37, 150 ->", [f"{pe[p] @ pe[p + k]:.6f}" for p in (0, 37, 150)])
print("|PE(p)|² =", np.round((pe ** 2).sum(axis=-1)[:3], 6), "(= d/2)")
assert np.allclose([pe[p] @ pe[p + 5] for p in range(200)], pe[0] @ pe[5])
assert np.allclose((pe ** 2).sum(axis=-1), 32)
```

## 2.6 Attention 掩码

### 2.6.1 高效的数据格式

现在来想一想，训练时要喂给模型什么样的数据。语言模型学的是“看前文、猜下一个”，所以一条训练样本就是一对（前文，下一个 token）。好在我们不必一对一对地准备：一段长度为 C+1 的 token 序列，本身就包含了 C 对这样的样本。

以 2.8 节会用到的一段代码 `def add(a, b):` 为例，它的前几个 token 是 `def`、` add`、`(`、`a`。把同一段序列错开一位，输入取前 C 个，目标取后 C 个：

| 位置 | 输入看到的前文 | 应该预测的下一个 |
|---|---|---|
| 0 | `def` | ` add` |
| 1 | `def add` | `(` |
| 2 | `def add(` | `a` |

一条长度为 4 的序列，一次给出了 3 个训练样本，而且这 3 个位置可以在一次前向计算里并行处理。第 3 章的 `TokenDataset` 正是这样切数据的：

### 2.6.2 Attention 的问题

这种格式有一个致命的漏洞。看上表的位置 0：它要预测的 ` add`，正好是位置 1 的输入。2.4 节说过，没有掩码的 Attention 让每个位置都能看到所有位置；于是位置 0 只要把注意力放到位置 1 上，就能直接“抄”到答案。每个位置都这么做，训练 loss 会降得很漂亮，模型却什么也没学会。到了生成的时候，下一个 token 还不存在，无处可抄。

```verify id=2.6-b title="没有掩码时，位置 0 的输出会随位置 1（它的答案）变化"

x_leak[1] += 1.0                                         # 只改动位置 1
moved = np.abs(attn_toy(x_leak)[0] - attn_toy(x)[0]).max() > 1e-12
print("改动位置 1 之后，位置 0 的输出变了吗？", bool(moved))
assert moved
```

这不是杞人忧天。我们在本地做了一个实验：用相互独立、均匀随机的 token 训练一个单层的小 GPT，词表大小为 8，序列长度为 8。随机 token 里没有任何规律可学，诚实的模型只能瞎猜，loss 应该停在 $\ln8=2.08$。结果是：保留掩码时，loss 确实停在 2.08 附近；去掉掩码后，loss 降到了 $\ln8/8=0.26$ 附近。逐个位置看，前 7 个位置的 loss 都接近 0，它们抄到了答案；只有最后一个位置的 loss 仍在 2 以上，因为它无处可抄。

### 2.6.3 Attention 掩码的机制

办法是在 softmax 之前，把“未来”位置的分数改成 $-\infty$。$e^{-\infty}=0$，这些位置的权重就严格等于 0；剩下的权重经过 softmax 的归一化，和仍然是 1。第 $i$ 行只保留第 0 到第 $i$ 列，用一个下三角矩阵（lower triangular matrix）表示“可以看”的位置最方便。C = 4 时：

$$M=\begin{pmatrix}1&0&0&0\\1&1&0&0\\1&1&1&0\\1&1&1&1\end{pmatrix}$$

这里，$M_{ij}=1$ 表示第 $i$ 个位置可以看到第 $j$ 个位置。注意对角线是 1：每个位置都能看到自己，它要预测的是下一个 token，看自己不算作弊。NumPy 的 `np.tril` 和 PyTorch 的 `torch.tril` 都默认保留对角线（参数 `k=0`）。第 $i$ 行可见的范围是 `[:i+1]`：切片左闭右开，要写 `i+1` 才包含第 $i$ 列自己。

```verify id=2.6-c title="因果掩码：上三角严格为 0，每行之和为 1，第 0 行只看自己"
def causal_softmax(S):
    C = S.shape[-1]
    mask = np.tril(np.ones((C, C), dtype=bool))         # (C, C)：下三角（含对角线）为 True
    return softmax(np.where(mask, S, -np.inf))          # 未来的位置 -> -inf -> 权重 0

S = np.random.default_rng(0).standard_normal((5, 5))
W_c = causal_softmax(S)
print(np.round(W_c, 3))
assert (np.triu(W_c, k=1) == 0).all() and np.allclose(W_c.sum(axis=-1), 1) and W_c[0, 0] == 1.0
M = np.tril(np.ones((4, 4), dtype=bool))
assert M[2, 2] and not M[2, 3] and M[2, :2 + 1].all()      # 第 2 行可见 [:3]，即第 0、1、2 列
```

如果一整行都被遮住，会怎样？比如误写成 `np.tril(..., k=-1)`（不含对角线），第 0 行就一个可见的位置也没有，softmax 无从归一化：朴素的写法得到 0/0，先减最大值的写法得到 $-\infty-(-\infty)$，结果都是 NaN。下三角掩码本身不会出现这种情况，但以后遇到填充（padding）掩码时要格外小心：NaN 不会安分地待在一行里。

```verify id=2.6-d title="整行都是 -inf：0/0 = nan，而且会传给下一层的每一行"
strict = np.tril(np.ones((5, 5), dtype=bool), k=-1)       # 不含对角线：第 0 行全是 False
with np.errstate(invalid="ignore"):
    W_bad = softmax(np.where(strict, S, -np.inf))
    out_bad = W_bad @ np.random.default_rng(1).standard_normal((5, 4))   # 这一层的输出
    W_next = causal_softmax(out_bad @ out_bad.T)          # 下一层：每一行都能看到位置 0
print("第 0 行的权重:", W_bad[0])
print("这一层有 nan 的行:", np.isnan(out_bad).any(axis=-1).astype(int).tolist())
print("下一层有 nan 的行:", np.isnan(W_next).any(axis=-1).astype(int).tolist())
assert np.isnan(W_bad[0]).all() and not np.isnan(out_bad[1:]).any() and np.isnan(W_next).any(axis=-1).all()
```

::: confusion 掩码“加上了”，为什么还会漏？
一个自然的想法是：只要未来位置的权重是 0，未来的信息就进不来。这只说对了一半。权重为 0 的位置确实不会通过 $V$ 进入输出，但未来的分数还可能通过**归一化的分母**混进来。两种常见的写法都会出这个问题。

一是 softmax 做错了轴。分数矩阵的第 $i$ 行是第 $i$ 个查询对所有键的分数，softmax 必须沿最后一维（`axis=-1`）做。如果写成 `axis=-2`，就成了按列归一化：第 $j$ 列的分母里，有第 $j$ 行之后所有行的分数，也就是未来查询的分数。

二是先 softmax、后遮挡。先对整行做 softmax，再把未来位置的权重置 0：被遮住的权重确实是 0，但其余权重的分母里已经包含了未来的分数，每行之和也不再是 1。

检验的方法与 2.6.2 节一样：改动未来的 token，看过去位置的输出变不变。可以带走的一句话：**先遮挡，再沿最后一维做 softmax**，顺序和轴都不能换。
:::

```verify id=2.6-e title="三种写法的泄漏检测：只有“先遮挡、再按行 softmax”不漏"
rng = np.random.default_rng(0)
```

```verify id=2.6-f title="06 的 NumPy 版：位置 0 输出自己的值；改动未来，过去逐位不变"
def causal_attention(Q, K, V):
    C, D = Q.shape[-2], Q.shape[-1]
    S = Q @ np.swapaxes(K, -1, -2) / np.sqrt(D)          # (..., C, D) @ (..., D, C) -> (..., C, C)
    mask = np.tril(np.ones((C, C), dtype=bool))          # (C, C)
    return softmax(np.where(mask, S, -np.inf)) @ V       # (..., C, C) @ (..., C, Dv) -> (..., C, Dv)
```

## 2.7 Value 矩阵的高效化

### 2.7.1 大模型中 Attention 的难点

2.6 节的类有三个权重矩阵：`W_q` 和 `W_k` 各是 D×E，`W_v` 是 E×E。以原书的配置 E = 256、D = 64 为例：

| 矩阵 | 形状 | 参数量 |
|---|---|---|
| `W_q` | 64 × 256 | 16,384 |
| `W_k` | 64 × 256 | 16,384 |
| `W_v` | 256 × 256 | 65,536 |

光是 `W_v` 就占了三分之二，而且它随 E 的平方增长。2.8 节还要并排放好几个这样的 Attention，如果每一个都配一个 E×E 的 `W_v`，代价会成倍增加。

```verify id=2.7-a title="06 的参数：W_v 占了三分之二"

print(f"07：W_q + W_k + W_v + W_o = 4 × {D7 * E7:,} = {4 * D7 * E7:,}（其中值的部分 W_v + W_o = {2 * D7 * E7:,}）")
```

### 2.7.2 用矩阵分解做低秩近似

办法是用两个“瘦”矩阵的乘积，代替这个“胖”矩阵：

$$W_{\text{eff}}=W_o\,W_v,\qquad W_v\in\mathbb{R}^{D\times E},\quad W_o\in\mathbb{R}^{E\times D}$$

这里，$W_v$ 先把 E 维压到 D 维，$W_o$ 再把 D 维还原回 E 维（形状仍按 `nn.Linear` 的习惯写成“输出 × 输入”）。参数量从 $E^2$ 变成 $2ED$：E = 256、D = 64 时，从 65,536 降到 32,768。代价是表达能力：两个矩阵的乘积，秩最多为 D。

手算一个最小的例子。E = 4、D = 1 时，$W_o$ 是 4×1 的列向量 $\mathbf{u}$，$W_v$ 是 1×4 的行向量 $\mathbf{v}^\top$，乘积 $\mathbf{u}\mathbf{v}^\top$ 是 4×4 的矩阵，但它的每一列都是 $\mathbf{u}$ 的倍数，秩为 1；它只用 8 个数就描述了 16 个元素。这种做法叫**低秩近似**（low-rank approximation）。

```verify id=2.7-b title="两个窄矩阵的乘积：256×256，秩却只有 64"
rng = np.random.default_rng(0)
W_v7 = rng.normal(size=(D7, E7))          # (64, 256)：E -> D
W_o7 = rng.normal(size=(E7, D7))          # (256, 64)：D -> E
W_eff = W_o7 @ W_v7                        # (256, 64) @ (64, 256) -> (256, 256)
print("W_o @ W_v 的形状:", W_eff.shape, "  秩:", np.linalg.matrix_rank(W_eff))
u, v_row = np.array([[1.0], [2.0], [3.0], [4.0]]), np.array([[1.0, 0.0, -1.0, 2.0]])
print("4×1 乘 1×4：形状", (u @ v_row).shape, " 秩", np.linalg.matrix_rank(u @ v_row))
assert np.linalg.matrix_rank(W_eff) == 64 and np.linalg.matrix_rank(u @ v_row) == 1
```

### 2.7.3 从矩阵分解重新理解 Attention

为什么可以把 $W_o$ 放到 Attention 的后面？看第 $i$ 个位置的输出（这里把向量写成列向量，便于看清矩阵作用的顺序）：

$$\mathbf{y}_i=W_o\Bigl(\sum_j a_{ij}\,W_v\mathbf{x}_j\Bigr)=\sum_j a_{ij}\,(W_oW_v)\,\mathbf{x}_j$$

这里，$a_{ij}$ 是注意力权重，是一个标量，所以 $W_o$ 可以穿过求和号，与 $W_v$ 合成一个矩阵。也就是说，“先用 $W_v$ 压缩、做完加权和、再用 $W_o$ 还原”，与“直接用 $W_oW_v$ 这个 E×E 矩阵当作值矩阵”完全等价。

这给了 Attention 一个新的读法：每个位置先把自己压缩成一个 D 维的“摘要”（$W_v\mathbf{x}_j$），Attention 按权重混合这些摘要，最后由 $W_o$ 把混合的结果写回 E 维的表示里。在 Transformer 的可解释性研究中，$W_oW_v$ 这个组合被称为 OV 电路（[Elhage et al., 2021](https://transformer-circuits.pub/2021/framework/index.html)）。2.9 节讲残差连接时，我们还会回到“写回”这个说法。

```verify id=2.7-c title="07（W_v 压缩 + W_o 还原）== 06（值矩阵取 W_o @ W_v）"
def attn07(x, W_q, W_k, W_v, W_o):
    return attn06(x, W_q, W_k, W_v) @ W_o.T          # (B, C, D) @ (D, E) -> (B, C, E)

W_q7, W_k7 = rng.normal(0, 0.06, (D7, E7)), rng.normal(0, 0.06, (D7, E7))
x7 = rng.standard_normal((2, 5, E7))
y07 = attn07(x7, W_q7, W_k7, W_v7, W_o7)
y06 = attn06(x7, W_q7, W_k7, W_eff)
print("07 的输出形状:", y07.shape, "  与“值矩阵 = W_o @ W_v”的 06 相等:", np.allclose(y07, y06))
assert np.allclose(y07, y06)
```

## 2.8 多头 Attention

### 2.8.1 从多个视角捕捉

一个 Attention 对每个查询只给出一组权重，也就是只用一种方式去“看”前文。但读代码时，我们同时关心好几种关系：上一个 token 是什么？这个变量在哪里定义过？当前在哪个函数里？只靠一组权重，很难同时兼顾这些。

**多头 Attention**（multi-head attention）的做法是：并排放 H 个 Attention，每个都有自己的 $W_q$、$W_k$、$W_v$，各自算出一组权重；每个“头”（head）只在 D 维的小空间里工作，最后把所有头的结果拼起来，由 $W_o$ 写回 E 维。通常取 $H\times D=E$，这样总的计算量与一个 E 维的 Attention 差不多。

真实的模型里，不同的头确实学会了不同的“看法”。下图用的是原书作者用第 3 章的预训练脚本训练、公开发布的 CodeBot 权重 `model_pretrain.pt`（6 层，每层 6 个头），读两段代码时的注意力权重。每一行是一个查询，颜色越深，表示它在那一列的键上放的权重越大；对角线以上是空的，因为未来被掩码遮住了。

几个值得一看的头如下（L 表示层，H 表示头，都从 0 开始编号）：

- **L4H3 盯着上一个 token**。在 `def add(a, b)` 那段代码里，` b` 把 0.99 的权重放在紧挨着它的 ` +` 上。这种头叫作 previous-token head。
- **L5H2 盯着函数名**。大多数位置都在看 ` add`，比如 `return` 之后的 ` a` 把 0.92 的权重放在了 ` add` 上。
- **L1H2 盯着第一个 token**。第 1 层的六个头平均约有一半的权重落在开头的 `def` 上，L1H2 最多，达到 0.71。这种现象被称为 attention sink（[Xiao et al., 2023](https://arxiv.org/abs/2309.17453)），论文给出的一种解释是：softmax 的权重之和必须为 1，没有特别要看的内容时，多余的权重就“停靠”在开头的 token 上。
- **L4H0 在抄前文**。第二段代码在 `print(` 之后又写了一遍 `square`，这一次被切成了 `s`、`qu`、`are` 三个 token。读这三个 token 时，L4H0 把最大的权重依次放在前文 `square` 里的“下一段”上：`s` → `qu`（0.67）、`qu` → `are`（0.73）、`are` → `(`（0.77）；模型在这三处预测的下一个 token，也正是 `qu`、`are` 和 `(`。这种“在前文里找到同样的内容，看它后面跟着什么”的行为，与可解释性研究中的 induction head 一致（[Olsson et al., 2022](https://transformer-circuits.pub/2022/in-context-learning-and-induction-heads/index.html)）。只凭一段代码，还不能断定这个头的全部职能；但模型确实在借助前文补全函数名。

### 2.8.2 多头 Attention 的公式

把上面的话写成公式。每个头 $h$ 有自己的投影矩阵，计算方法与 2.6 节完全相同：

$$\mathrm{head}_h=\mathrm{softmax}\!\left(\frac{Q_hK_h^\top}{\sqrt{D}}+M\right)V_h,\qquad Q_h=XW_q^{(h)\top},\;K_h=XW_k^{(h)\top},\;V_h=XW_v^{(h)\top}$$

$$\mathrm{MultiHead}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\,W_o^\top$$

这里，$X$ 是 (C, E) 的输入；每个头的 $W_q^{(h)}$、$W_k^{(h)}$、$W_v^{(h)}$ 都是 D×E；$M$ 是 2.6 节的掩码，可见处为 0，未来处为 $-\infty$；$\mathrm{head}_h$ 的形状是 (C, D)。H 个头拼起来是 (C, H·D)，再由 E×(H·D) 的 $W_o$ 映射回 (C, E)。不算偏置，参数量是 $4\cdot E\cdot(H\cdot D)$：E = 512、H = 8、D = 64 时为 1,048,576。

原书 08 的前半段用 E = 16、H = 3、D = 8 做演示，这时 $H\cdot D=24\ne E$。这说明 $H\cdot D$ 并不一定要等于 E，反正 $W_o$ 会把它映射回 E 维；只是实践中通常取相等。

```verify id=2.8-b title="多头的参数量：4·E·(H·D)；H·D 不必等于 E"
mha_params = lambda E, H, D: 4 * E * H * D            # W_q、W_k、W_v 各 (H*D)×E，W_o 是 E×(H*D)
print(f"E = 512, H = 8, D = 64: {mha_params(512, 8, 64):,}")
print(f"E = 16,  H = 3, D = 8 : {mha_params(16, 3, 8):,}（W_o 把 24 维映射回 16 维）")
assert mha_params(512, 8, 64) == 1_048_576 == 4 * 512 ** 2
```

### 2.8.3 两个等价的公式

$\mathrm{Concat}(\dots)\,W_o^\top$ 还有另一种写法。把 $W_o$ 按列切成 H 块，第 $h$ 块 $W_o^{(h)}$ 是 E×D，与第 $h$ 个头对应，那么

$$\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\,W_o^\top=\sum_{h=1}^{H}\mathrm{head}_h\,W_o^{(h)\top}$$

这就是分块矩阵的乘法：$[A\;\;B]\begin{bmatrix}C\\D\end{bmatrix}=AC+BD$。用标量手算：$[1\;\;2]\begin{bmatrix}3\\4\end{bmatrix}=1\times3+2\times4=11$。左边的写法是“先拼接、再变换”，计算效率高；右边的写法是“每个头各自变换、再相加”，更容易理解：每个头独立地把自己的结果写回 E 维的表示，头与头之间只是相加。


```verify id=2.8-d title="批量计算所有头 == 逐个头分别计算"
def split_heads(t, H):
    *lead, C, HD = t.shape
    return np.swapaxes(t.reshape(*lead, C, H, HD // H), -3, -2)   # (..., C, H*D) -> (..., C, H, D) -> (..., H, C, D)
```

::: confusion 为什么 view 之前一定要先 transpose？
`Q.view(B, C, H, D).transpose(1, 2)` 与 `Q.view(B, H, C, D)` 得到的形状都是 (B, H, C, D)，后者还少写一步。为什么不能直接这样写？

因为形状只描述“怎么数”，不描述“谁是谁”。在内存里，`Q` 是按位置一行一行存放的：先是位置 0 的全部 H·D 个数，再是位置 1 的，以此类推。`view(B, C, H, D)` 只是把每一行切成 H 段，位置还是那个位置；`transpose(1, 2)` 再把头换到前面。而 `view(B, H, C, D)` 会把这串数直接重新解读成“头 0 的 C 个位置、头 1 的 C 个位置……”：所谓“头 0 的第 1 个位置”，其实是位置 0 的第二段数据，而“头 1 的第 0 个位置”可能装着位置 1 甚至更靠后的数据。代码不报任何错误，因果掩码遮住的却只是“名义上”的未来，真正的未来就这样漏进了过去。

合并时还有一个坑：`transpose` 之后的张量在内存里不再连续，PyTorch 的 `view` 会直接报 RuntimeError，所以原书写成 `.contiguous().view(...)`；改用 `reshape` 也可以，它会在需要时自动复制。NumPy 的 `reshape` 总会在需要时复制，所以在 NumPy 里只会遇到前一个坑。下面的验证和实验台演示前一个坑，本地测试则在 PyTorch 里把两个坑都复现了一遍。

## 2.9 Transformer 块

### 2.9.1 LayerNorm 的机制

直观上，在深层网络里，每一层输出的数值范围会在训练中漂移，下一层就得不停地适应。**LayerNorm**（层归一化）的做法是：对每个 token 的向量单独做标准化，减去它自己 E 个分量的均值、除以标准差，再乘以可学习的缩放 $\boldsymbol\gamma$，加上可学习的平移 $\boldsymbol\beta$：

$$\mathrm{LN}(\mathbf{x})=\boldsymbol\gamma\odot\frac{\mathbf{x}-\mu}{\sqrt{\sigma^2+\epsilon}}+\boldsymbol\beta,\qquad \mu=\frac{1}{E}\sum_{i=1}^{E}x_i,\qquad \sigma^2=\frac{1}{E}\sum_{i=1}^{E}(x_i-\mu)^2$$

这里，$\epsilon$ 是防止除以 0 的小常数（原书取 $10^{-5}$），$\odot$ 表示逐元素相乘。注意方差除以的是 E，不是 E−1。

手算一个例子：$\mathbf{x}=(1,2,3,6)$，$\mu=3$，$\sigma^2=(4+1+0+9)/4=3.5$，$\sigma=1.871$，标准化之后是 $(-1.069,\,-0.535,\,0,\,1.604)$，均值为 0，方差为 1。

如果你读过《深度学习入门：基于Python的理论与实现》6.3 节，会记得 Batch Normalization：它对**每个特征**在 batch 维度上标准化，所以一个样本的结果会受同一 batch 里其他样本的影响。LayerNorm 换了一个方向，对**每个 token** 在特征维度上标准化，只看自己。所以推理时一次只来一个 token 也没有问题。

```verify id=2.9-a title="LayerNorm：每个 token 均值 0、方差 1；误除以 E-1 会整体缩小"
def layer_norm(x, gamma, beta, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)              # (..., 1)：每个 token 自己的均值
    var = x.var(axis=-1, keepdims=True)              # (..., 1)：np.var 默认除以 E（ddof=0）
    return gamma * (x - mu) / np.sqrt(var + eps) + beta

x4 = np.array([1.0, 2.0, 3.0, 6.0])
print("LN(1, 2, 3, 6) =", np.round(layer_norm(x4, 1.0, 0.0), 3))
assert np.allclose(layer_norm(x4, 1.0, 0.0, eps=0), np.array([-2, -1, 0, 3]) / np.sqrt(3.5))

rng = np.random.default_rng(0)
xt = rng.standard_normal((5, 384)) * 3 + 2                     # 5 个 token，各 384 维
yt = layer_norm(xt, 1.0, 0.0)
print("每个 token 的均值:", np.round(yt.mean(axis=-1), 6) + 0.0, "  方差:", np.round(yt.var(axis=-1), 4))
yt_unbiased = (xt - xt.mean(-1, keepdims=True)) / np.sqrt(xt.var(-1, ddof=1, keepdims=True) + 1e-5)
for E_ in (4, 384):
    print(f"E = {E_:3d}：误除以 E-1 时，输出整体乘以 √((E-1)/E) = {np.sqrt((E_ - 1) / E_):.6f}")
assert np.allclose(yt.mean(axis=-1), 0) and np.allclose(yt.var(axis=-1), 1, atol=1e-5)
assert np.allclose(yt_unbiased, yt * np.sqrt(383 / 384), atol=1e-6)
```

### 2.9.3 FFN 的实现

Transformer 块里的另一个子层是 **FFN**（feed-forward network，前馈网络）：两层全连接，中间夹一个激活函数，对每个位置单独计算。中间层通常是 E 的 4 倍宽：CodeBot 的 E = 384，中间层是 1536 维。

$$\mathrm{FFN}(\mathbf{x})=\mathrm{GELU}(\mathbf{x}W_1^\top+\mathbf{b}_1)\,W_2^\top+\mathbf{b}_2$$

激活函数用的是 **GELU**（Gaussian Error Linear Unit）。它的定义是 $\mathrm{GELU}(x)=x\,\Phi(x)$，其中 $\Phi$ 是标准正态分布的累积分布函数：输入越大，越接近“原样通过”；输入越小，越接近“关掉”。如果你读过《深度学习入门：基于Python的理论与实现》3.2 节，可以把它看成平滑版的 ReLU：ReLU 在 0 处硬生生地拐弯，GELU 则在负半轴留下一个小小的凹陷，最低点约为 −0.17。手算两个点：$\Phi(1)=0.8413$，所以 $\mathrm{GELU}(1)=0.8413$；$\Phi(-1)=0.1587$，所以 $\mathrm{GELU}(-1)=-0.1587$，而 ReLU 在这里是 0。

$\Phi$ 要用误差函数 erf 来算：$\Phi(x)=\frac{1}{2}\bigl(1+\mathrm{erf}(x/\sqrt{2})\bigr)$。GELU 的论文（[Hendrycks & Gimpel, 2016](https://arxiv.org/abs/1606.08415)）同时给出了一个用 tanh 的近似式，原版 GPT-2 用的就是这个近似（[openai/gpt-2 的 model.py](https://github.com/openai/gpt-2/blob/master/src/model.py)）：

$$\mathrm{GELU}(x)\approx\frac{1}{2}x\left(1+\tanh\!\left[\sqrt{2/\pi}\,\bigl(x+0.044715x^3\bigr)\right]\right)$$

`forward` 只有两行，每行都是同样的模式：先用 LayerNorm 规范化，送进子层，再把子层的输出**加回**原来的 x。这种“加回去”的连接叫作**残差连接**（residual connection）；先规范化、再进子层的排法叫作 **Pre-LN**。

可以这样理解残差连接：有一股贯穿所有块的数据流 x，常被称为**残差流**（residual stream）。每个子层都从中读取信息（经过 LayerNorm），再把自己算出的结果加进去，而不是替换掉它；2.7 节说 $W_o$ 把 Attention 的结果“写回”，写回的就是这股残差流。如果你读过《深度学习入门：基于Python的理论与实现》5.3 节，会记得加法节点在反向传播时把梯度原样传给每一个输入；所以无论叠多少层，梯度都能沿着这条加法的“捷径”直达底层，同书 8.2.4 节的 ResNet 也是这个道理。

一个直接的推论是：如果两个子层的输出恰好都是 0，这个块就什么也不做，输出等于输入。我们用 NumPy 搭一个块来确认。参数按 `codebot/model.py` 的 state_dict 命名，2.10 节会直接复用：

### 2.10.2 改进模型

在 2.9 节的积木之外，`GPT` 类还有两处值得单独拿出来说的改进：


第一处是**权重共享**（weight tying，注释“重み共有”）。`self.embed.weight = self.unembed.weight` 让输入端的 `embed` 和输出端的 `unembed` 共用同一个 1000×384 的矩阵。直观上，输入时 token $w$ 被表示成矩阵的第 $w$ 行；输出时，logits 的第 $w$ 个分量是最后的向量与同一行的点积，也就是说，“像 $w$ 的向量”会给 $w$ 打高分。一个矩阵身兼二职，省下了 384,000 个参数。如果你读过《深度学习进阶：自然语言处理》6.5.3 节，那里的 BetterRnnlm 用的也是这个技巧。注意 CodeBot 的 `unembed` 还带一个长度为 1000 的偏置，而原版 GPT-2 的输出层没有偏置，直接乘以嵌入矩阵的转置。

第二处是**权重初始化**（注释“重みの初期化”）。所有 `Linear` 和 `Embedding` 的权重都从均值 0、标准差 0.02 的正态分布里取，偏置置 0；`nn.LayerNorm` 保持默认的 $\gamma=1$、$\beta=0$。有一个细节：共享的矩阵会被初始化两次，`apply` 先访问 `embed`，后访问 `unembed`，最后生效的是 `Linear` 的那一次。好在两者都是 N(0, 0.02²)，结果没有区别（本地测试用一个把两种初始化设成不同常数的子类确认了这个顺序）。此外，模型里还有好几处 dropout（嵌入之后、注意力权重上、注意力输出和 FFN 输出上），它们的影响留到 2.10.4 节再看。

参数数清楚了，再来预测一个数：刚初始化、还没训练的模型，loss 是多少？2.4 节说过，均匀地瞎猜，交叉熵是 $\ln V=6.9078$。实际测出来却是 6.98 左右，略高一些。差的这 0.08 从哪里来？

原因是初始化后的 logits 并不全是 0，而是带着一点随机的起伏。设 logits $z_1,\dots,z_V$ 相互独立，都服从 $N(0,\sigma^2)$，正确答案的 logit 与其他的没有区别，那么交叉熵的期望约为

$$\mathrm{E}\Bigl[\ln\sum_{j}e^{z_j}-z_{\text{答案}}\Bigr]\approx\ln\bigl(V\,\mathrm{E}[e^{z}]\bigr)-0=\ln V+\frac{\sigma^2}{2}$$

这里用到了正态分布的性质 $\mathrm{E}[e^z]=e^{\sigma^2/2}$。那么 $\sigma$ 是多少呢？最终 LayerNorm 的输出每个分量方差约为 1，`unembed` 的每个权重标准差是 0.02，每个 logit 是 384 项之和，所以 $\sigma^2\approx384\times0.02^2=0.154$，$\sigma\approx0.392$。代入得 $\ln1000+0.154/2=6.908+0.077=6.985$。

```verify id=2.10-c title="初始 loss ≈ ln V + σ²/2 ≈ 6.98，比 ln V 略高"
rng = np.random.default_rng(0)
V_, E_, N_ = 1000, 384, 64
h_last = layer_norm(rng.standard_normal((N_, E_)), 1.0, 0.0)   # (64, 384)：最终 LN 的输出，每个分量方差约 1
W_un = rng.normal(0, 0.02, (V_, E_))                           # (1000, 384)：N(0, 0.02²) 初始化
z = h_last @ W_un.T                                            # (64, 384) @ (384, 1000) -> (64, 1000)：logits
lse = np.log(np.exp(z).sum(axis=-1))                           # (64,)：z 很小，不会溢出
ce = (lse - z.mean(axis=-1)).mean()                            # 正确答案随机：对 1000 个可能的答案取平均
sigma2 = E_ * 0.02 ** 2
print(f"logits 的标准差 {z.std():.3f}（手算 √(384 × 0.02²) = {np.sqrt(sigma2):.3f}）")
print(f"交叉熵 {ce:.3f}   ln V = {np.log(V_):.3f}   ln V + σ²/2 = {np.log(V_) + sigma2 / 2:.3f}")
assert abs(z.std() - np.sqrt(sigma2)) < 0.01 and abs(ce - (np.log(V_) + sigma2 / 2)) < 0.02
```

```verify id=2.10-e title="dropout：train 模式下每次结果都不同，注意力行之和不再是 1"
def dropout(a, p, rng):
    keep = rng.random(a.shape) >= p                 # 以概率 p 置 0
    return np.where(keep, a / (1 - p), 0.0)         # 留下的放大 1/(1-p)，期望不变

rng = np.random.default_rng(0)
w_attn = causal_softmax(rng.standard_normal((6, 6)))   # (6, 6)：一张注意力权重

print("dropout 后每行之和:", np.round(w1.sum(axis=-1), 3))
```

最后，我们把本章写过的 NumPy 零件，`layer_norm`、`mha`、`gelu_erf`、`ffn`、`block_forward`，串成一个完整的 GPT 前向计算，与 PyTorch 版的 `GPT` 逐个 logit 比对。为了让浏览器在几毫秒内跑完，我们用一个很小的、随机初始化的 CodeBot 同型模型（V = 50、上下文 16、E = 32、H = 4、L = 2）。它的权重和 PyTorch 算出的参考 logits 都存在 `tiny_ref.npz` 里：

```verify id=2.10-f title="端到端：本章的 NumPy 零件拼成的 GPT，与 PyTorch 版逐个 logit 对齐" files=data/ch02/tiny_ref.npz
def gpt_forward(ids, P, n_layer, n_head):
    C = len(ids)
    x = P["embed.weight"][ids] + P["pos_embed.weight"][:C]       # (C, E)：token 嵌入 + 位置嵌入
    for i in range(n_layer):
        x = block_forward(x, P, i, n_head)                        # (C, E) -> (C, E)
    x = layer_norm(x, P["norm.weight"], P["norm.bias"])           # 最终 LayerNorm
    return x @ P["unembed.weight"].T + P["unembed.bias"]          # (C, E) @ (E, V) + (V,) -> (C, V)

Z = np.load("data/ch02/tiny_ref.npz")
P_tiny = {k: Z[k].astype(np.float64) for k in Z.files if k not in ("ids", "ref_logits")}
ids_tiny = Z["ids"].tolist()
logits_np = gpt_forward(ids_tiny, P_tiny, n_layer=2, n_head=4)
err = np.abs(logits_np - Z["ref_logits"]).max()
print("ids:", ids_tiny)
print("logits 形状:", logits_np.shape, "  与 PyTorch 的最大差 < 1e-6:", bool(err < 1e-6))
print("每个位置最可能的下一个 token 一致:", bool((logits_np.argmax(-1) == Z["ref_logits"].argmax(-1)).all()))
print("embed.weight 与 unembed.weight 相同:", np.array_equal(Z["embed.weight"], Z["unembed.weight"]))
assert logits_np.shape == (12, 50) and err < 1e-6
```

## 小结

本章从 Python 的字典出发，把“完全相等才能取值”放宽成“按相似度加权混合”，得到了软字典；写成矩阵就是 Attention，再除以 $\sqrt{d}$，让 softmax 的温度不随维度漂移。接着，我们给 Attention 补上了它天生缺少的两样东西：位置信息和因果掩码；用低秩分解给值矩阵减负，用多头让模型同时从几个角度看前文。最后，LayerNorm、FFN 和残差连接把这些零件装成 Transformer 块，6 个块叠起来，加上嵌入和反嵌入，就是 CodeBot 的 GPT-2：11,121,640 个参数，每一个都有来处。

这个模型现在还什么都不会：它的 loss 在 6.98 左右，相当于在 1000 个 token 里瞎猜。

**本章所学的内容**

- 软字典用点积衡量相似度、用 softmax 把相似度变成权重、用加权和混合各个值；点积偏爱长的键，而且 T→0 时只有在没有并列时才退化为硬查找（[验证 2.1-c](#v-2.1-c)、[验证 2.1-d](#v-2.1-d)）
- 随机查询与键的点积方差约为 d；除以 √d 让 softmax 的有效温度与 d 无关，不缩放时 d 越大越容易饱和（[验证 2.3-b](#v-2.3-b)、[验证 2.3-c](#v-2.3-c)）
- 语言模型按链式法则给句子打分，交叉熵是平均负对数概率，单位是 nats；均匀瞎猜的 loss 是 ln V = 6.9078（[验证 2.4-b](#v-2.4-b)、[验证 2.4-c](#v-2.4-c)）
- 没有位置信息的 Attention 对顺序视而不见；CodeBot 的可学习位置表只有 256 行，第 257 个位置查不到（[验证 2.5-a](#v-2.5-a)、[验证 2.5-d](#v-2.5-d)）
- 因果掩码必须在 softmax 之前施加，并沿最后一维归一化；遮错轴、先 softmax 后遮挡，都会让未来漏进过去（[验证 2.6-e](#v-2.6-e)）
- 拆分多头要先 view 再 transpose；省掉 transpose 不会报错，却破坏因果性（[验证 2.8-e](#v-2.8-e)）
- CodeBot 的 GPT 有 11,121,640 个参数，初始 loss 约为 ln V + σ²/2 ≈ 6.98；本章的 NumPy 零件拼成的 GPT 与 PyTorch 版逐个 logit 对齐（[验证 2.10-a](#v-2.10-a)、[验证 2.10-c](#v-2.10-c)、[验证 2.10-f](#v-2.10-f)）
