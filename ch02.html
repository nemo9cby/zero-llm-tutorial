模型【基础篇】：从软字典到 GPT-2

从 Python 的字典出发，一步一步搭出 Attention，再把它组装成 CodeBot 的大脑：一个 11,121,640 个参数的 GPT-2，每个参数都数得清来历。

上一章，我们把 TinyCodes 里的 Python 代码变成了一串 token，词表大小是 1,000（第 1 章）。这一章要造的，是读这串 token 的那个东西：模型。语言模型做的事情一句话就能说完：给定前面的 token，给出下一个 token 的概率分布。CodeBot 的模型每次最多读入 256 个 token，在每个位置上输出 1,000 个数，分别表示词表里每个 token 成为“下一个”的可能性。

这个模型的核心部件叫作 Attention。我们不从论文里的公式讲起，而是从每个 Python 程序员都熟悉的字典出发：先把“按键取值”放宽成“按相似度取值”，得到一个“软字典”（2.1 节）；把它写成矩阵运算（2.2 节）；再修补它在高维时的数值问题（2.3 节）。然后我们退后一步，看清 Transformer 的全貌和 Attention 在其中的角色（2.4 节）。接下来依次补上位置信息、因果掩码、Value 的低秩化和多头（2.5–2.8 节），最后用 LayerNorm、FFN 和残差连接搭成 Transformer 块，组装出 GPT-2（2.9–2.10 节）。

先看终点。本章结束时，我们会得到下面这样创建的一个模型：

GPT(vocab_size=1000,
    max_context_len=256,
    embed_dim=384,
    n_head=6, n_layer=6,
    ff_dim=1536,
    dropout_rate=0.1)

参数名已经说明了一大半。词表有 1,000 个 token，模型一次最多读 256 个，每个 token 在模型里是一个 384 维的向量。n_head 是 Attention 的头数，n_layer 是 Transformer 块叠了几层，ff_dim 是 FFN 中间层的宽度，dropout_rate 是训练时随机丢弃的比例。这些名词本章都会一一讲到。这个模型把形状为 (1, 256) 的 token id 变成形状为 (1, 256, 1000) 的 logits，共有 11,121,640 个参数，这个数我们会在 2.10 节逐项数清楚。

本章的代码都很小，只用 CPU 就能运行；用 GPU 训练它是第 3 章的事。正文里每个带“验”字印章的单元都能在浏览器里重新运行。需要 PyTorch 的结论，则给出本地测试的命令和源码；其中几项还要用到原书作者公开的预训练权重 model_pretrain.pt（2.3.3 节第一次用到时再介绍），文件不存在时，这几项测试会跳过。

2.1 Attention 的基本原理

2.1.1 Python 的字典

我们从一个再熟悉不过的数据结构说起：Python 的字典（dict）。字典里存着若干“键（key）→ 值（value）”对，拿一个键去查，就能取回对应的值。原书的第一个脚本正是从这里开始的：

d['banana'] 取回 200。这里的查询（query）'banana' 必须与某个键完全相等，查找才会成功；写成 'Banana' 或 'bananas'，得到的只有 KeyError。换句话说，字典的查找是“硬”的：要么完全命中，取回一个值；要么什么也得不到。

2.1.2 软字典

那么，能不能让查询“差不多对上”也有结果呢？设想一个记录了几部电影的字典：键描述电影的风格，值是某位用户给它打的分。现在来了一部新电影，它的风格与哪个键都不完全相同，我们仍然想估计这位用户会给它打几分。

一个自然的做法是：去看风格相似的那些电影，按相似的程度把它们的评分混合起来，越相似的电影说话越有分量。这就是软字典的思路。直观上，它像是去问一位看过很多电影的朋友“这部新片我大概会打几分”，朋友会想起几部类似的片子，按相似程度掂量它们的分数。

严格地讲，软字典要回答三个问题：怎样衡量相似度，怎样把相似度变成权重，怎样用权重混合各个值。DLFS6 的回答分别是点积、softmax 和加权和。用 \mathbf{q} 表示查询向量，\mathbf{k}_i 和 v_i 表示第 i 个键和值（共 n 个）：

s_i=\mathbf{q}\cdot\mathbf{k}_i,\qquad w_i=\frac{\exp(s_i)}{\sum_{j=1}^{n}\exp(s_j)},\qquad \text{结果}=\sum_{i=1}^{n}w_iv_i

这里，s_i 是查询与第 i 个键的相似度，点积越大越相似；w_i 是 softmax 给出的权重，全是正数且总和为 1，所以结果是各个值的加权平均。

用一个能心算的例子走一遍。设查询 \mathbf{q}=(1,0)，两个键 \mathbf{k}_1=(1,0)、\mathbf{k}_2=(0,1)，对应的值是 10 和 20。相似度为 (1,0)，权重为 \bigl(e/(e+1),\,1/(e+1)\bigr)=(0.731,\,0.269)，结果是 10\times0.731+20\times0.269=12.69。查询更像第一个键，所以结果靠近 10，但第二个值也贡献了一份。

如果你读过《深度学习进阶：自然语言处理》8.1 节，会认出这个结构：那里的 Attention 同样是“内积算相似度 → softmax 得权重 → 加权和”。书中的理由是：“选择”这个操作无法微分，于是干脆全部选上，再按权重混合。

验证 2.1-a硬字典要么命中要么报错；软字典总能给出加权平均
import numpy as np

d = {'apple': 100, 'banana': 200, 'cherry': 300, 'durian': 400}
print(d['banana'])
try:
    d['Banana']
    hit = True
except KeyError as err:
    hit = False
    print("KeyError:", err)
assert not hit

def softmax(x):
    x = np.asarray(x)
    e = np.exp(x - x.max(axis=-1, keepdims=True))   # 每行减去自己的最大值（原因见 2.1.3 节）
    return e / e.sum(axis=-1, keepdims=True)        # 每行除以自己的和

q = np.array([1.0, 0.0])                    # (2,)
K = np.array([[1.0, 0.0], [0.0, 1.0]])      # (2, 2)：每行一个键
v = np.array([10.0, 20.0])                  # (2,)
w = softmax(K @ q)                          # (2, 2) @ (2,) -> (2,)
print("权重:", np.round(w, 3), " 结果:", round(float(w @ v), 2))
assert np.isclose(w[0], np.e / (np.e + 1)) and round(float(w @ v), 2) == 12.69

2.1.3 软字典的实现示例

下面是原书的实现。键是 (动作性, 剧情性, 喜剧性) 三个 0–10 的分数，值是这位用户的评分（0–100 分），新电影的风格是 (6, 4, 5)。

注释是日文：類似度 = 相似度，重み付き和 = 加权和，七部电影依次是偏动作、偏剧情、偏喜剧、均衡型、动作剧情片、喜剧剧情片和纯动作片。运行后得到：新电影的预测评分是 78.66 分；权重最大的是 (7, 6, 2)，占 72.62%，其次是 (5, 5, 5)，占 26.71%，其余几部几乎没有分量。

为什么偏偏是这两部？算一下点积就明白了。查询 (6, 4, 5) 与七个键的点积依次是 71、59、59、75、76、70、63。最大的 76 和 75 只差 1，所以权重之比是 e^{76}:e^{75}=e:1；其余的点积至少再小 5，e^{-5}\approx0.007，几乎可以忽略。于是预测评分约为 75+5\times\frac{e}{1+e}=75+5\times0.731=78.66。

验证 2.1-b复现原书：预测评分 78.66，权重集中在 (7,6,2) 与 (5,5,5)

你可能会困惑点积最大的，并不是“最像”的那一部

看到 (7, 6, 2) 拿走了大部分权重，你也许会觉得意外：(6, 4, 5) 看上去明明更像“均衡型”的 (5, 5, 5)。这个直觉没有错，如果用余弦相似度或欧氏距离来衡量，最像的确实是 (5, 5, 5)。问题出在点积本身：\mathbf{q}\cdot\mathbf{k}=\lVert\mathbf{q}\rVert\,\lVert\mathbf{k}\rVert\cos\theta，它不只看方向，还看长度。(7, 6, 2) 的长度是 9.43，(5, 5, 5) 只有 8.66，多出来的这一截把它推到了第一。

可以带走的结论是：软字典里的“相似度”是点积，键越长越容易被选中。在真正的 Transformer 里，查询和键都是模型学出来的向量，长度本身也成了模型可以利用的信号；也正因为如此，不要把注意力权重直接读成“最近邻”。

软字典和硬字典之间是什么关系？在 softmax 之前把相似度除以一个正数 T，就得到带温度（temperature）的版本：\mathbf{w}=\mathrm{softmax}(\mathbf{s}/T)。T 越小，最大的那个相似度越占优势，权重越接近“只选一个”；T\to0 时，软字典退化成“取相似度最大的键的值”。反过来，T 越大，权重越平均；T\to\infty 时，结果就是所有值的简单平均。

既然 T\to0 就是“取最像的那个”，那么拿字典里的某个键本身去查询，应该原样取回它的值，和硬字典一样。我们来确认一下：

验证 2.1-dT→0 退化为硬查找，但遇到并列或更长的键就不是；T→∞ 变成简单平均

七次查询里，有五次原样取回了值，但 (8, 2, 3) 得到 87.5，(5, 5, 5) 得到 73.33。原因还是点积：(8, 2, 3) 与自己的点积是 64 + 4 + 9 = 77，与 (9, 1, 1) 的点积是 72 + 2 + 3 = 77，两者并列，权重各占一半，结果是 85 与 90 的平均 87.5；(5, 5, 5) 与自己、与 (7, 6, 2)、与 (2, 7, 6) 的点积都是 75，三方并列，结果是 (75 + 80 + 65) / 3 = 73.33。

所以“软字典在 T\to0 时等于硬字典”有个前提：用来查询的键，与自己的点积必须严格大于它与其他任何键的点积。这里失败的两次都是并列；但只要字典里有一个方向相近、更长的键，连并列都不需要。比如字典里只有 (5, 5, 5) 和 (10, 10, 10) 两个键，用 (5, 5, 5) 去查，自己的点积 75 输给了 150，取回的就是别人的值。换成余弦相似度，每个键与自己的相似度都是最大值 1，问题就只剩下并列。

注意原书的 softmax 会溢出

原书的 soft_dictionary 直接计算 np.exp(similarity)，没有先减去最大值。书中的点积最大只有 76，所以没有问题；但 float64 的 exp 在参数超过约 709.8 时就会溢出成 inf，结果变成 inf / inf = nan。如果相似度放大 10 倍（比如特征的取值范围变大，或者向量的维度变高），点积就会超过 700，正好越过这条线。如果你读过《深度学习入门：基于Python的理论与实现》3.5.2 节，会记得解决办法：softmax 的输入同时减去同一个常数，结果不变；先减去最大值，最大的指数就是 e^0=1，不会溢出。我们在验证 2.1-a 里写的 softmax 就是这么做的。

2.2 Attention 的公式与实现

2.2.1 用公式表示 Attention

2.1 节的软字典用 for 循环逐个计算点积。现在我们把它写成矩阵运算。按照《深度学习进阶：自然语言处理》1.1 节的习惯，向量一律写成行向量：查询 \mathbf{q} 是 1×3 的矩阵，把 7 个键按行叠起来得到 7×3 的矩阵 K，7 个值叠起来得到 7×1 的矩阵 V。于是

\mathbf{y}=\mathrm{softmax}(\mathbf{q}K^\top)\,V

这里，\mathbf{q}K^\top 的形状是 (1, 3) × (3, 7) = (1, 7)，正好是 7 个点积；softmax 把它们变成 7 个权重；再乘以 (7, 1) 的 V，得到 (1, 1) 的结果，也就是加权和。三行 for 循环，变成了两次矩阵乘法。

2.2.2 支持多个查询

如果有好几部新电影要预测呢？把它们的查询也按行叠起来，得到矩阵 Q，公式几乎不用改：

Y=\mathrm{softmax}(QK^\top)\,V

这里的 softmax 对 QK^\top 的每一行分别计算。原书用了三个查询：(6, 4, 5)、(2, 8, 3) 和 (4, 3, 7)。于是 Q 是 3×3，QK^\top 是 3×7，其中第 i 行第 j 列是第 i 个查询与第 j 个键的点积；Y 是 3×1，每行是一部新电影的预测评分。

验证 2.2-a矩阵形式一次算出三个查询：78.66 / 69.76 / 61.20
def attention(Q, K, V):
    S = Q @ K.T          # (3, 3) @ (3, 7) -> (3, 7)：每行是一个查询与 7 个键的点积
    W = softmax(S)       # (3, 7)：逐行 softmax，每行之和为 1
    return W @ V         # (3, 7) @ (7, 1) -> (3, 1)：逐行加权和

这个读法有两个用处。第一，它说明 softmax 必须按行做：每一行用自己的最大值、自己的分母。第二，2.6 节的因果掩码也是一条逐行的规则：“第 i 行只能看第 0 到第 i 个键”。

你可能会困惑每行的最大值，为什么要写 keepdims=True？

逐行计算最容易出错的地方，是求每行最大值和分母时的形状。S.max(axis=-1) 的形状是 (3,)，而 S 是 (3, 7)。两者直接相减时，NumPy 按广播（broadcasting）规则从最后一维开始对齐：7 和 3 对不上，于是报错。这还算幸运。

到了 2.6 节，分数矩阵会变成 C×C 的方阵。这时形状为 (C,) 的“每行最大值”会被当成一个行向量：第 j 行的最大值，被减到了第 j 列的每个元素上。不报错，每行之和也还是 1，结果却是错的。同样的事故也会发生在别处，比如形状 (3,) 的标签减去形状 (3, 1) 的预测，得到的是一个 3×3 的矩阵，求平均之后照样是一个“正常”的数。

可以带走的结论是：按行做的归约（max、sum、mean）一律写 axis=-1, keepdims=True，让结果保持 (…, 1) 的形状；遇到方阵时，形状对得上并不代表算对了。

验证 2.2-c忘了 keepdims：长方阵报错，方阵悄悄算错

2.3 Attention 缩放

2.3.1 softmax 函数的饱和问题

在电影的例子里，点积最大只有 76，结果就已经很“偏心”了：最大的两项只差 1，权重之比就是 e : 1。如果点积的数值再大一些，会发生什么呢？原书的第三个脚本先做了一个极端的实验：

输出是 tensor([0.0000e+00, 3.7835e-44, 1.0000e+00])：几乎全部权重都落在了 300 上。这是因为 softmax 只关心输入之间的差：e^{200}/e^{300}=e^{-100}\approx3.7\times10^{-44}。输入相差 100，权重就相差 e^{100}\approx2.7\times10^{43} 倍。这种几乎只有一个 1、其余全是 0 的状态，叫作 softmax 的饱和（saturation）。

饱和有什么坏处呢？第一，软字典又变回了硬字典，加权混合的好处没有了。第二，也是更要紧的一点：梯度消失了。softmax 的输出 \mathbf{p} 对输入 \mathbf{s} 的导数是一个矩阵（雅可比矩阵），J=\mathrm{diag}(\mathbf{p})-\mathbf{p}^\top\mathbf{p}，它的对角元素是 p_i(1-p_i)。当 \mathbf{p} 接近 one-hot 时，每个 p_i 不是接近 0 就是接近 1，J 的所有元素都接近 0：无论分数怎样微调，输出几乎不变，学习也就无从谈起。

手算一下：输入 (1, 2, 3) 时，softmax 是 (0.090, 0.245, 0.665)，最大的对角元素是 0.665\times0.335=0.223；输入 (100, 200, 300) 时，J 的元素全都小到 10^{-44} 量级。

验证 2.3-asoftmax 饱和：输出几乎 one-hot，雅可比矩阵几乎为 0
def softmax_jacobian(p):
    return np.diag(p) - np.outer(p, p)        # (n, n)：J[i, j] = ∂p_i / ∂s_j

    p = softmax(s_in)
    print(f"s = {s_in.tolist()}  p = {np.array2string(p, precision=4)}  max|J| = {np.abs(softmax_jacobian(p)).max():.3g}")

2.3.2 引入缩放

分数为什么会变大？问题出在维度上。设查询 \mathbf{q} 和键 \mathbf{k} 都是 d 维向量，各个分量相互独立，均值为 0、方差为 1。点积 \mathbf{q}\cdot\mathbf{k}=\sum_{i=1}^{d}q_ik_i 是 d 项之和，每一项 q_ik_i 的均值为 0，方差为 \mathrm{E}[q_i^2]\,\mathrm{E}[k_i^2]=1。独立随机变量之和的方差等于方差之和，所以

\mathrm{Var}(\mathbf{q}\cdot\mathbf{k})=d

这里，d 是向量的维数。标准差是 \sqrt{d}：d=64 时，点积的典型大小是 8；d=1024 时是 32。维度越高，分数越大，softmax 越容易饱和。

解决办法很直接：把点积除以 \sqrt{d}，方差就回到 d/d=1。这就是 Transformer 论文（Vaswani et al., 2017）里的缩放点积注意力（Scaled Dot-Product Attention）：

\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V

原书用 10,000 次采样来确认方差（d=10）：

脚本没有固定随机种子，每次运行的数值略有不同；但两个方差之比永远恰好是 10，因为把数据除以 \sqrt{10} 会让方差恰好变成原来的 1/10，这是代数恒等式，与采样无关。我们换成 d=64 并固定种子再做一次。严格的推导（需要哪些独立性假设）见附录 B。

不缩放时，d 越大，最大权重越接近 1，饱和的行越多；d=1024 时，七成以上的行已经把几乎全部权重压在一个键上。缩放之后，最大权重稳定在 0.04 左右，不随 d 变化。

这里值得停下来想一想。把分数除以 \sqrt{d}，等价于把 2.1 节的温度设为 T=\sqrt{d}。反过来看，不缩放的 softmax 作用在方差为 1 的“标准分数” \mathbf{q}\cdot\mathbf{k}/\sqrt{d} 上，相当于温度 T=1/\sqrt{d}：维度越高，温度越低，分布越尖。所以缩放真正修正的，是“softmax 的温度随 d 漂移”这件事：缩放之后，不管 d 是 16 还是 1024，注意力的尖锐程度都一样。

表的最后一列还藏着一个容易被说错的地方。常见的说法是“不缩放会导致梯度消失”。可是这一列量的是 softmax 这一步的 \partial\mathbf{p}/\partial\mathbf{s}，而不缩放时，它在 d=4 到 256 都比缩放之后大（d=16 时约 0.30，缩放后约 0.10），到 d=1024 才降到 0.07。中等尖锐的分布梯度最大，只有接近 one-hot 时梯度才真正消失。

而且这只是 softmax 这一步。梯度还要经过 s=\mathbf{q}\cdot\mathbf{k} 传到查询上：缩放后，这一步乘的是 \mathbf{k}/\sqrt{d}；不缩放时乘的是 \mathbf{k}，大了 \sqrt{d} 倍。两步合起来，从 d=16 起，不缩放时传到查询上的梯度平均反而是缩放后的 10 倍以上。所以更准确的说法是：不缩放时，有效温度随 d 漂移；只有饱和到接近 one-hot 的那些行（就像 2.3.1 节的 (100, 200, 300)），梯度才真正消失。

2.4.1 Transformer 的运作流程

到这里，我们已经有了 Attention 这个零件。在继续打磨它之前，先退后一步，看看它将被装进一台什么样的机器。GPT 系列使用的是 Transformer 的解码器部分，它处理一串 token 的流程如下表。形状以 CodeBot 为例：批大小 B = 1，序列长度 C = 256，embedding 维数 E = 384，词表大小 V = 1000。

步骤 做什么 输出形状 详见
1. 输入 token id 序列 (1, 256) 第 1 章
2. embedding 查表把每个 id 换成 384 维向量，即词嵌入（token embedding），再加上位置向量 (1, 256, 384) 2.5 节、2.10 节
3. Transformer 块 × 6 Attention 在位置之间交换信息，FFN 在每个位置内部加工 (1, 256, 384) 2.6–2.9 节
4. 最终 LayerNorm 规范化每个位置的向量 (1, 256, 384) 2.9 节
5. 输出层 一个线性层（unembed）把 384 维映射成 1000 个分数（logits） (1, 256, 1000) 2.10 节
6. softmax（模型之外） 把 logits 变成每个位置“下一个 token”的概率分布：训练时由 F.cross_entropy 在内部完成，生成时由采样函数完成 (1, 256, 1000) 本节专栏

注意形状的变化：从第 2 步到第 4 步，形状始终是 (1, 256, 384)。每个 Transformer 块读进这样一个张量，再写出同样形状的张量，所以块可以像积木一样一个接一个地叠起来。只有开头的 embedding 和结尾的输出层，在“token 的世界”和“向量的世界”之间来回转换。还要注意，模型本身只算到第 5 步的 logits；第 6 步的 softmax 由用到 logits 的代码去做，2.10.1 节读 forward 时，你会发现里面没有 softmax。

专栏Transformer 与句子的概率计算

语言模型给一个句子打分的方式，是把它拆成一连串“猜下一个”。设句子由 token w_1,w_2,\dots,w_T 组成，根据概率的乘法定理（链式法则），

P(w_1,\dots,w_T)=P(w_1)\,P(w_2\mid w_1)\cdots P(w_T\mid w_1,\dots,w_{T-1})=\prod_{t=1}^{T}P(w_t\mid w_{<t})

这里，w_{<t} 表示第 t 个 token 之前的全部 token。右边的每一项都是“已知前文，下一个 token 恰好是 w_t 的概率”，这正是上表最后一步在每个位置输出的东西。如果你读过《深度学习进阶：自然语言处理》5.1.2 节，会记得语言模型就是这样定义的；那里的 RNN 一个时刻接一个时刻地算这些条件概率，Transformer 则在一次前向计算里同时给出所有位置的条件概率。

连乘的结果很快会小到难以处理，所以实际计算时取对数，把乘积变成求和，再取负号并对 token 数求平均：

L=-\frac{1}{T}\sum_{t=1}^{T}\ln P(w_t\mid w_{<t})

这就是训练时最小化的交叉熵（cross entropy）损失。如果你读过《深度学习入门：基于Python的理论与实现》4.2.2 节，会认出它：正确答案是一个 one-hot 向量，交叉熵只取出正确那一项的 -\ln 概率。

手算一个例子。一个 3 个 token 的句子，三个条件概率依次是 0.5、0.2、0.1，句子的概率就是 0.5\times0.2\times0.1=0.01。-\ln0.01=4.605，平均到每个 token 是 1.535。它的指数 e^{1.535}=4.64 叫作困惑度（perplexity），可以理解为“模型平均在 4.64 个候选之间犹豫”（《深度学习进阶：自然语言处理》5.5.2 节）。

最后还要确认一件事：把条件概率连乘起来，得到的真是一个概率分布吗？也就是说，所有长度为 T 的句子的概率加起来，是不是恰好等于 1？下面的验证用一个随意编造的“模型”检查了这一点：只要每一步给出的都是合法的分布，连乘的结果就是合法的分布。

注意这里固定了长度。把长度 1、2、3、4 的句子放在一起，概率之和是 4，而不是 1：每种长度各自是一个分布。要让长短不一的句子共用一个分布，模型还得能预测“到此为止”。这就是结束 token 的作用，CodeBot 的词表里就有一个 <|endoftext|>（1.5 节）。把它也当成一次预测，各种长度的句子的概率合起来才等于 1。

验证 2.4-b链式法则：固定长度时，条件概率连乘是一个合法的分布；长度可变时要靠结束 token；交叉熵 = 平均负对数概率

你可能会困惑“nats”是什么单位？

训练日志里的 loss 只是一个数，不带单位，很容易被当成一个没有量纲的“分数”。其实它有单位。用自然对数 ln 计算交叉熵时，单位叫 nat；用以 2 为底的对数计算时，单位是 bit。两者只差一个常数因子：1 nat = 1/\ln2 = 1.4427 bits。PyTorch 的 F.cross_entropy 用的是自然对数，所以训练日志里的 loss 都是 nats。

bit 最好体会：1 bit 就是一个是非题的答案。从 1000 个等可能的 token 里猜中一个，大约要问 10 个是非题（2^{10}=1024），准确地说是 \log_21000=9.97 bits。1 nat 则约合 1.44 个是非题。

记住一个基准就够用了：如果模型对下一个 token 毫无头绪，只能在 V 个 token 里平均地猜，每个 token 的概率是 1/V，交叉熵就是 \ln V。CodeBot 的词表有 1,000 个 token，\ln1000=6.9078 nats，也就是 9.97 bits，困惑度恰好是 1000，即“在全部 1000 个候选之间犹豫”。2.10 节会解释，为什么刚初始化的模型实际会比它略高一点，约为 6.98；本书在第 3 章实际训练时，日志里的第一个 loss 是 6.9843（验证 2.10-g）。如果你在别处看到 9.97，那多半是同一件事用 bits 报告的结果。

2.4.2 Attention 在 Transformer 中的作用

表里第 3 步有一句话值得细看：Attention 在位置之间交换信息，FFN 在每个位置内部加工。在一个 Transformer 块里，只有 Attention 会让第 i 个位置的输出依赖其他位置的输入；LayerNorm 和 FFN（2.9 节）都是对每个位置的向量单独做同样的运算，位置之间互不相干。这有点像开会：Attention 是大家互相交流的环节，FFN 是各自回到座位上消化。

严格地讲，这意味着：改动第 j 个位置的输入，FFN 的输出只有第 j 行会变；Attention 的输出则是所有能“看到”位置 j 的行都会变。我们用一个随机的小例子确认一下。这里的 Attention 还没有掩码，每个位置都能看到所有位置。

2.5 位置编码

2.5.1 为什么需要位置信息

Attention 有一个奇特的性质：它不知道顺序。点积只看两个向量的内容，不管它们排在第几位。如果把输入的 token 打乱顺序，没有掩码的 Attention 的输出只是跟着一起打乱，每个 token 得到的输出向量完全不变。这个性质叫作置换等变（permutation equivariance）。

对语言来说，这是个大问题。CodeBot 的分词器把 return a - b 和 return b - a 都切成同样的 5 个 token（'re'、'turn'、' a'、' -'、' b'，引号里开头的空格也是 token 的一部分），只是顺序不同，意思却正好相反。

2.5.2 位置编码的机制

解决办法是把位置信息直接“写进”输入向量：给每个位置 t 准备一个向量 \mathbf{p}_t，加到该位置的 token embedding 上：

\mathbf{x}_t=\mathbf{e}(w_t)+\mathbf{p}_t

这里，\mathbf{e}(w_t) 是 token w_t 的 embedding 向量，\mathbf{p}_t 是第 t 个位置的位置编码（positional encoding）。同一个 token 出现在不同的位置，得到的输入向量就不一样了，Attention 的点积也就能区分顺序。

2.5.3 绝对位置编码

位置向量从哪里来？Transformer 的原论文用的是一组固定的正弦、余弦函数：

\mathrm{PE}(p,2i)=\sin\!\left(\frac{p}{10000^{2i/d}}\right),\qquad \mathrm{PE}(p,2i+1)=\cos\!\left(\frac{p}{10000^{2i/d}}\right)

这里，p 是位置，i 是维度对的编号（0\le i<d/2），d 是向量的维数。每一对维度就像一根以不同速度旋转的时钟指针：前面的维度转得快，后面的维度转得慢。

像这样直接为每个位置指定一个向量、加在输入上的做法，叫作绝对位置编码（absolute positional encoding）。“绝对”说的是做法：第 p 个位置总是拿到同一个向量，与它前后是什么无关。

正弦位置编码还有一个漂亮的性质：两个位置编码的点积只取决于它们的距离。看最简单的 d=2：\mathrm{PE}(p)=(\sin p,\cos p)，于是 \mathrm{PE}(p)\cdot\mathrm{PE}(p+k)=\sin p\,\sin(p+k)+\cos p\,\cos(p+k)=\cos k，与 p 无关。一般的 d 也一样，因为每一对维度都满足这个恒等式。

不过，这个“只看距离”的性质到不了 Attention 的分数那里。分数是 (\mathbf{e}_i+\mathbf{p}_i)W_q^\top 与 (\mathbf{e}_j+\mathbf{p}_j)W_k^\top 的点积：位置向量先和 token embedding 加在一起，展开后有 token 与位置的交叉项；又经过了 W_q、W_k 的变换。所以分数并不只取决于距离。第 5 章的 RoPE，正是要让分数对位置的依赖只剩下相对距离。

验证 2.5-c正弦位置编码：PE(p)·PE(p+k) 只取决于距离 k；加上 token embedding 或经过 W_q、W_k 之后就不是了

    pos = np.arange(n_pos)[:, None]                      # (n_pos, 1)
    i = np.arange(d // 2)[None, :]                       # (1, d/2)

    return pe

2.5.4 可学习的位置编码

GPT-2 和 CodeBot 用的是另一种做法：不预先规定位置向量的样子，而是准备一张表，每个位置一行，像其他参数一样从数据里学出来。这叫可学习的位置编码（learned positional encoding）。在代码里，它和 token embedding 一样，也是一个 nn.Embedding：

pos_embed 是一张 256 行、384 列的表。前向计算时，torch.arange(0, C) 生成位置编号 0, 1, …, C−1，查出对应的行，加到 token embedding 上；形状 (B, C, 384) 与 (C, 384) 相加，靠的是 2.4 节验证过的广播。

2.6 Attention 掩码

2.6.1 高效的数据格式

2.6.3 Attention 掩码的机制

办法是在 softmax 之前，把“未来”位置的分数改成 -\infty。e^{-\infty}=0，这些位置的权重就严格等于 0；剩下的权重经过 softmax 的归一化，和仍然是 1。第 i 行只保留第 0 到第 i 列，用一个下三角矩阵（lower triangular matrix）表示“可以看”的位置最方便。C = 4 时：

M=\begin{pmatrix}1&0&0&0\\1&1&0&0\\1&1&1&0\\1&1&1&1\end{pmatrix}

这里，M_{ij}=1 表示第 i 个位置可以看到第 j 个位置。注意对角线是 1：每个位置都能看到自己，它要预测的是下一个 token，看自己不算作弊。NumPy 的 np.tril 和 PyTorch 的 torch.tril 都默认保留对角线（NumPy 的参数是 k=0，PyTorch 的是 diagonal=0）。第 i 行可见的范围是 [:i+1]：切片左闭右开，要写 i+1 才包含第 i 列自己。

def causal_softmax(S):
    C = S.shape[-1]
    mask = np.tril(np.ones((C, C), dtype=bool))         # (C, C)：下三角（含对角线）为 True
    return softmax(np.where(mask, S, -np.inf))          # 未来的位置 -> -inf -> 权重 0

你可能会困惑掩码“加上了”，为什么还会漏？

一个自然的想法是：只要未来位置的权重是 0，未来的信息就进不来。这只说对了一半。权重为 0 的位置确实不会通过 V 进入输出，但未来的分数还可能通过归一化的分母混进来。两种常见的写法都会出这个问题。

一是 softmax 做错了轴。分数矩阵的第 i 行是第 i 个查询对所有键的分数，softmax 必须沿最后一维（axis=-1）做。如果写成 axis=-2，就成了按列归一化：第 j 列的分母里，有第 j 行之后所有行的分数，也就是未来查询的分数。

二是先 softmax、后遮挡。先对整行做 softmax，再把未来位置的权重置 0：被遮住的权重确实是 0，但其余权重的分母里已经包含了未来的分数，每行之和也不再是 1。

检验的方法与 2.6.2 节一样：改动未来的 token，看过去位置的输出变不变。可以带走的一句话：先遮挡，再沿最后一维做 softmax，顺序和轴都不能换。

2.6.4 Attention 掩码的实现

把 2.2 节的公式、2.3 节的缩放和本节的掩码合在一起，就是原书的 06：

这个类做了两处推广。第一，查询、键、值不再是现成的数据，而是由同一个输入 X 经过三个线性变换得到：Q=XW_q^\top、K=XW_k^\top、V=XW_v^\top（权重按 nn.Linear 的习惯存成“输出维数 × 输入维数”）。查询和键都来自序列自身，所以这种用法叫自注意力（Self-Attention）。第二，输入多了一个批维度，形状是 (B, C, E)，分别是批大小、上下文长度和 embedding 维数，这也是转置要写成 K.transpose(-2, -1) 的原因。另外请注意，W_q 和 W_k 把 E 维映射到 D 维（key_dim），W_v 却是 E×E 的方阵。这一点到下一节会改变。

我们把它翻译成 NumPy，并做两个检查：位置 0 只能看到自己，所以它的输出恰好是自己的值向量；改动位置 3、4 的输入，位置 0–2 的输出一个比特也不变。

def causal_attention(Q, K, V):
    C, D = Q.shape[-2], Q.shape[-1]
    S = Q @ np.swapaxes(K, -1, -2) / np.sqrt(D)          # (..., C, D) @ (..., D, C) -> (..., C, C)
    mask = np.tril(np.ones((C, C), dtype=bool))          # (C, C)
    return softmax(np.where(mask, S, -np.inf)) @ V       # (..., C, C) @ (..., C, Dv) -> (..., C, Dv)

2.7.2 用矩阵分解做低秩近似

办法是用两个“瘦”矩阵的乘积，代替这个“胖”矩阵：

W_{\text{eff}}=W_o\,W_v,\qquad W_v\in\mathbb{R}^{D\times E},\quad W_o\in\mathbb{R}^{E\times D}

这里，W_v 先把 E 维压到 D 维，W_o 再把 D 维还原回 E 维（形状仍按 nn.Linear 的习惯写成“输出 × 输入”）。参数量从 E^2 变成 2ED：E = 256、D = 64 时，从 65,536 降到 32,768。代价是表达能力：两个矩阵的乘积，秩最多为 D。

手算一个最小的例子。E = 4、D = 1 时，W_o 是 4×1 的列向量 \mathbf{u}，W_v 是 1×4 的行向量 \mathbf{v}^\top，乘积 \mathbf{u}\mathbf{v}^\top 是 4×4 的矩阵，但它的每一列都是 \mathbf{u} 的倍数，秩为 1；它只用 8 个数就描述了 16 个元素。这种做法叫低秩近似（low-rank approximation）。

验证 2.7-b两个窄矩阵的乘积：256×256，秩却只有 64

2.7.3 从矩阵分解重新理解 Attention

为什么可以把 W_o 放到 Attention 的后面？看第 i 个位置的输出（这里把向量写成列向量，便于看清矩阵作用的顺序）：

\mathbf{y}_i=W_o\Bigl(\sum_j a_{ij}\,W_v\mathbf{x}_j\Bigr)=\sum_j a_{ij}\,(W_oW_v)\,\mathbf{x}_j

这里，a_{ij} 是注意力权重，是一个标量，所以 W_o 可以穿过求和号，与 W_v 合成一个矩阵。也就是说，“先用 W_v 压缩、做完加权和、再用 W_o 还原”，与“直接用 W_oW_v 这个 E×E 矩阵当作值矩阵”完全等价。

这给了 Attention 一个新的读法：每个位置先把自己压缩成一个 D 维的“摘要”（W_v\mathbf{x}_j），Attention 按权重混合这些摘要，最后由 W_o 把混合的结果写回 E 维的表示里。在 Transformer 的可解释性研究中，W_oW_v 这个组合被称为 OV 电路（Elhage et al., 2021）。2.9 节讲残差连接时，我们还会回到“写回”这个说法。

2.8 多头 Attention

2.8.1 从多个视角捕捉

一个 Attention 对每个查询只给出一组权重，也就是只用一种方式去“看”前文。但读代码时，我们同时关心好几种关系：上一个 token 是什么？这个变量在哪里定义过？当前在哪个函数里？只靠一组权重，很难同时兼顾这些。

多头 Attention（Multi-Head Attention）的做法是并排放 H 个 Attention。每个“头”（head）都有自己的 W_q、W_k、W_v，各自算出一组权重，但只在 D 维的小空间里工作。最后把所有头的结果拼起来，由 W_o 写回 E 维。通常取 H\times D=E，这样总的计算量与一个 E 维的 Attention 差不多。

真实的模型里，不同的头确实学会了不同的“看法”。下图画的是官方预训练权重 model_pretrain.pt（来历见 2.3.3 节；6 层，每层 6 个头）读两段代码时的注意力权重。每一行是一个查询；颜色越醒目（浅色主题下越深，深色主题下越亮），表示它在那一列的键上放的权重越大，图下的色标标出了 0 到 1 对应的颜色。对角线以上是空的，因为未来被掩码遮住了。

几个值得一看的头如下（L 表示层，H 表示头，都从 0 开始编号，所以 L1 是第二层）：

  • L4H3 盯着上一个 token。在 def add(a, b) 那段代码里，' b' 把 0.99 的权重放在紧挨着它的 ' +' 上。这种头叫作 previous-token head。
  • L5H2 盯着函数名。大多数位置都在看 ' add'，比如 return 之后的 ' a' 把 0.92 的权重放在了 ' add' 上。
  • L1H2 盯着开头的 token。L1 的六个头平均约有一半的权重落在开头的 'def' 上，L1H2 最多，达到 0.71。这种现象被称为 Attention Sink（Xiao et al., 2023），论文给出的一种解释是：softmax 的权重之和必须为 1，没有特别要看的内容时，多余的权重就“停靠”在开头的 token 上。
  • L4H0 的样子像在抄前文。第二段代码里，def square 中的 square 被切成 ' s'、'qu'、'are'；print( 后面的 square 没有前导空格，被切成 's'、'qu'、'are'。's' 与 ' s' 是两个不同的 token，可读后面这三个 token 时，L4H0 仍然把最大的权重依次放在前文 square 的“下一段”上：'s' → 'qu'（0.67）、'qu' → 'are'（0.73）、'are' → '('（0.77）。模型在这三处预测的下一个 token，也正是 'qu'、'are' 和 '('。这种“在前文里找到同样的内容，看它后面跟着什么”的行为，与可解释性研究中的 induction head 一致（Olsson et al., 2022）。

2.8.2 多头 Attention 的公式

把上面的话写成公式。每个头 h 有自己的投影矩阵，计算方法与 2.6 节完全相同：

\mathrm{head}_h=\mathrm{softmax}\!\left(\frac{Q_hK_h^\top}{\sqrt{D}}+M\right)V_h,\qquad Q_h=XW_q^{(h)\top},\;K_h=XW_k^{(h)\top},\;V_h=XW_v^{(h)\top}
\mathrm{MultiHead}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\,W_o^\top

这里，X 是 (C, E) 的输入；每个头的 W_q^{(h)}、W_k^{(h)}、W_v^{(h)} 都是 D×E；M 是 2.6 节的掩码，可见处为 0，未来处为 -\infty；\mathrm{head}_h 的形状是 (C, D)。H 个头拼起来是 (C, H·D)，再由 E×(H·D) 的 W_o 映射回 (C, E)。不算偏置，参数量是 4\cdot E\cdot(H\cdot D)。原书 08 末尾的使用示例取 E = 512、H = 8、D = 64，参数量是 1,048,576；CodeBot 的 E = 384、H = 6、D = 64，是 589,824，2.10 节的参数表里还会再见到这个数。

原书 08 的前半段用 E = 16、H = 3、D = 8 做演示，这时 H\cdot D=24\ne E。这说明 H\cdot D 并不一定要等于 E，反正 W_o 会把它映射回 E 维；只是实践中通常取相等。

2.8.3 两个等价的公式

\mathrm{Concat}(\dots)\,W_o^\top 还有另一种写法。把 W_o 按列切成 H 块，第 h 块 W_o^{(h)} 是 E×D，与第 h 个头对应，那么

\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_H)\,W_o^\top=\sum_{h=1}^{H}\mathrm{head}_h\,W_o^{(h)\top}

这就是分块矩阵的乘法：[L_1\;\;L_2]\begin{bmatrix}R_1\\R_2\end{bmatrix}=L_1R_1+L_2R_2，其中 L_1、L_2 是左边按列切出的两块，R_1、R_2 是右边按行切出的两块。用标量手算：[1\;\;2]\begin{bmatrix}3\\4\end{bmatrix}=1\times3+2\times4=11。左边的写法是“先拼接、再变换”，计算效率高；右边的写法是“每个头各自变换、再相加”，更容易理解：每个头独立地把自己的结果写回 E 维的表示，头与头之间只是相加。

2.8.4 多头 Attention 的实现

原书 08 的前半段把多头 Attention 拆成了一步一步的代码。开头 5 行定义了演示用的尺寸：B = 2、C = 4、E = 16、H = 3、D = 8。后面的日文注释是各步的小标题，翻译过来是：输入张量，把所有头的权重合并成一个矩阵（这样更高效），形状变换（拆头），掩码处理，注意力权重，形状变换（合并），输出变换。

def split_heads(t, H):
    *lead, C, HD = t.shape
    return np.swapaxes(t.reshape(*lead, C, H, HD // H), -3, -2)   # (..., C, H*D) -> (..., C, H, D) -> (..., H, C, D)

def merge_heads(t):
    *lead, H, C, D = t.shape
    return np.swapaxes(t, -3, -2).reshape(*lead, C, H * D)          # (..., H, C, D) -> (..., C, H, D) -> (..., C, H*D)

def mha(x, W_q, W_k, W_v, W_o, H):

    return merge_heads(causal_attention(q, k, v)) @ W_o.T           # (..., C, H*D) @ (H*D, E) -> (..., C, E)

你可能会困惑拆头时，为什么 view 之后还要 transpose，不能一步 view 成 (B, H, C, D)？

Q.view(B, C, H, D).transpose(1, 2) 与 Q.view(B, H, C, D) 得到的形状都是 (B, H, C, D)，后者还少写一步。为什么不能直接这样写？

因为形状只描述“怎么数”，不描述“谁是谁”。在内存里，Q 是按位置一行一行存放的：先是位置 0 的全部 H·D 个数，再是位置 1 的，以此类推。view(B, C, H, D) 只是把每一行切成 H 段，位置还是那个位置；transpose(1, 2) 再把头换到前面。而 view(B, H, C, D) 会把这串数直接重新解读成“头 0 的 C 个位置、头 1 的 C 个位置……”：所谓“头 0 的第 1 个位置”，其实是位置 0 的第二段数据，而“头 1 的第 0 个位置”可能装着位置 1 甚至更靠后的数据。代码不报任何错误，因果掩码遮住的却只是“名义上”的未来，真正的未来就这样漏进了过去。

合并时还有一个坑：transpose 之后的张量在内存里不再连续，PyTorch 的 view 会直接报 RuntimeError，所以原书写成 .contiguous().view(...)；改用 reshape 也可以，它会在需要时自动复制。NumPy 的 reshape 总会在需要时复制，所以在 NumPy 里只会遇到前一个坑。下面的验证和图 2-6 演示前一个坑，本地测试则在 PyTorch 里把两个坑都复现了一遍。

可以带走的口诀：拆头，先 view 再 transpose；合并，先 transpose、contiguous，再 view。两步的顺序正好相反。

2.9.1 LayerNorm 的机制

直观上，在深层网络里，每一层输出的数值范围会在训练中漂移，下一层就得不停地适应。LayerNorm（层归一化）的做法是：对每个 token 的向量单独做标准化，减去它自己 E 个分量的均值、除以标准差，再乘以可学习的缩放 \boldsymbol\gamma，加上可学习的平移 \boldsymbol\beta：

\mathrm{LN}(\mathbf{x})=\boldsymbol\gamma\odot\frac{\mathbf{x}-\mu}{\sqrt{\sigma^2+\epsilon}}+\boldsymbol\beta,\qquad \mu=\frac{1}{E}\sum_{i=1}^{E}x_i,\qquad \sigma^2=\frac{1}{E}\sum_{i=1}^{E}(x_i-\mu)^2

这里，\epsilon 是防止除以 0 的小常数（原书取 10^{-5}），\odot 表示逐元素相乘。注意方差除以的是 E，不是 E−1。

手算一个例子：\mathbf{x}=(1,2,3,6)，\mu=3，\sigma^2=(4+1+0+9)/4=3.5，\sigma=1.871，标准化之后是 (-1.069,\,-0.535,\,0,\,1.604)，均值为 0，方差为 1。

如果你读过《深度学习入门：基于Python的理论与实现》6.3 节，会记得 Batch Normalization：它对每个特征在 batch 维度上标准化，所以训练时，一个样本的结果会受同一 batch 里其他样本的影响；推理时，它改用训练中累计下来的均值和方差。LayerNorm 换了一个方向，对每个 token 在特征维度上标准化，只看自己。所以它在训练和推理时是同一套计算，也不会受同一 batch 里其他序列（包括 padding）的影响。

验证 2.9-aLayerNorm：每个 token 均值 0、方差 1；误除以 E-1 会整体缩小
def layer_norm(x, gamma, beta, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)              # (..., 1)：每个 token 自己的均值
    var = x.var(axis=-1, keepdims=True)              # (..., 1)：np.var 默认除以 E（ddof=0）
    return gamma * (x - mu) / np.sqrt(var + eps) + beta

2.9.3 FFN 的实现

Transformer 块里的另一个子层是 FFN（feed-forward network，前馈网络）：两层全连接，中间夹一个激活函数，对每个位置单独计算。中间层通常是 E 的 4 倍宽：CodeBot 的 E = 384，中间层是 1536 维。

\mathrm{FFN}(\mathbf{x})=\mathrm{GELU}(\mathbf{x}W_1^\top+\mathbf{b}_1)\,W_2^\top+\mathbf{b}_2

激活函数用的是 GELU（Gaussian Error Linear Unit）。它的定义是 \mathrm{GELU}(x)=x\,\Phi(x)，其中 \Phi 是标准正态分布的累积分布函数：输入越大，越接近“原样通过”；输入越小，越接近“关掉”。如果你读过《深度学习入门：基于Python的理论与实现》3.2 节，可以把它看成平滑版的 ReLU：ReLU 在 0 处硬生生地拐弯，GELU 则在负半轴留下一个小小的凹陷，最低点约为 −0.17。手算两个点：\Phi(1)=0.8413，所以 \mathrm{GELU}(1)=0.8413；\Phi(-1)=0.1587，所以 \mathrm{GELU}(-1)=-0.1587，而 ReLU 在这里是 0。

\Phi 要用误差函数 erf 来算：\Phi(x)=\frac{1}{2}\bigl(1+\mathrm{erf}(x/\sqrt{2})\bigr)。GELU 的论文（Hendrycks & Gimpel, 2016）同时给出了一个用 tanh 的近似式，原版 GPT-2 用的就是这个近似（openai/gpt-2 的 model.py）：

\mathrm{GELU}(x)\approx\frac{1}{2}x\left(1+\tanh\!\left[\sqrt{2/\pi}\,\bigl(x+0.044715x^3\bigr)\right]\right)

2.9.4 Transformer 块的实现

有了 Attention、LayerNorm 和 FFN，就可以组装 Transformer 块了：

forward 只有两行，每行都是同样的模式：先用 LayerNorm 规范化，送进子层，再把子层的输出加回原来的 x。这种“加回去”的连接叫作残差连接（residual connection）；先规范化、再进子层的排法叫作 Pre-LN。

可以这样理解残差连接：有一股贯穿所有块的数据流 x，常被称为残差流（residual stream）。每个子层都从中读取信息（经过 LayerNorm），再把自己算出的结果加进去，而不是替换掉它；2.7 节说 W_o 把 Attention 的结果“写回”，写回的就是这股残差流。如果你读过《深度学习入门：基于Python的理论与实现》5.3 节，会记得加法节点在反向传播时把梯度原样传给每一个输入；所以无论叠多少层，梯度都能沿着这条加法的“捷径”直达底层，同书 8.2.4 节的 ResNet 也是这个道理。

一个直接的推论是：如果两个子层的输出恰好都是 0，这个块就什么也不做，输出等于输入。我们用 NumPy 搭一个块来确认。参数按 codebot/model.py 的 state_dict 命名，2.10 节会直接复用：

2.10.2 改进模型

在 2.9 节的积木之外，GPT 类还有两处值得单独拿出来说的改进：

第一处是权重共享（weight tying，注释“重み共有”）。self.embed.weight = self.unembed.weight 让输入端的 embed 和输出端的 unembed 共用同一个 1000×384 的矩阵。直观上，输入时 token w 被表示成矩阵的第 w 行；输出时，logits 的第 w 个分量是最后的向量与同一行的点积，也就是说，“像 w 的向量”会给 w 打高分。一个矩阵身兼二职，省下了 384,000 个参数。如果你读过《深度学习进阶：自然语言处理》6.5.3 节，会认出这个技巧；6.5.4 节的 BetterRnnlm 用的正是它。注意 CodeBot 的 unembed 还带一个长度为 1000 的偏置，而原版 GPT-2 的输出层没有偏置，直接乘以 embedding 矩阵的转置。

第二处是权重初始化（注释“重みの初期化”）。所有 Linear 和 Embedding 的权重都从均值 0、标准差 0.02 的正态分布里取，偏置置 0；nn.LayerNorm 保持默认的 \gamma=1、\beta=0。有一个细节：共享的矩阵会被初始化两次，apply 先访问 embed，后访问 unembed，最后生效的是 Linear 的那一次。好在两者都是 N(0, 0.02²)，结果没有区别（本地测试用一个把两种初始化设成不同常数的子类确认了这个顺序）。

0.02 这个数从哪来？它不是推导出来的，而是与 GPT-2 的设置相同：Hugging Face 的 GPT2Config 里，initializer_range 的默认值就是 0.02（configuration_gpt2.py）。GPT-2 的论文还多做了一步：残差分支里的权重在初始化时再乘以 1/\sqrt{N}，N 是残差层的个数（Radford et al., 2019 2.3 节）。nanoGPT 把它写作输出投影的 std=0.02/math.sqrt(2 * config.n_layer)（model.py）。CodeBot 没有这一步，所有权重一律是 0.02。本章有两处估算直接来自这个 0.02：2.3.3 节初始化时分数的标准差，以及下面的初始 loss。

参数数清楚了，再来预测一个数：刚初始化、还没训练的模型，loss 是多少？2.4 节说过，均匀地瞎猜，交叉熵是 \ln V=6.9078。实际测出来却是 6.98 左右，略高一些。差的这 0.08 从哪里来？

原因是初始化后的 logits 并不全是 0，而是带着一点随机的起伏。设 logits z_1,\dots,z_V 相互独立，都服从 N(0,\sigma^2)，正确答案的 logit 与其他的没有区别，那么交叉熵的期望约为

\mathrm{E}\Bigl[\ln\sum_{j}e^{z_j}-z_{\text{答案}}\Bigr]\approx\ln\bigl(V\,\mathrm{E}[e^{z}]\bigr)-0=\ln V+\frac{\sigma^2}{2}

式中的约等号把期望移进了对数。1000 个 e^{z_j} 相加，和几乎总是等于它的期望 V\,\mathrm{E}[e^z]（大数定律），所以 \ln\sum_je^{z_j} 几乎是个常数，约等于 \ln\bigl(V\,\mathrm{E}[e^z]\bigr)。正确答案的 logit 与其他 logit 同分布，期望是 0。这里还用到了正态分布的性质 \mathrm{E}[e^z]=e^{\sigma^2/2}。

那么 \sigma 是多少呢？最终 LayerNorm 的输出每个分量方差约为 1，unembed 的每个权重标准差是 0.02，每个 logit 是 384 项之和，所以 \sigma^2\approx384\times0.02^2=0.154，\sigma\approx0.392。代入得 \ln1000+0.154/2=6.908+0.077=6.985。如果把初始化的标准差改成 0.04，\sigma^2 就变成 384\times0.04^2=0.614，初始 loss 约为 6.908+0.307=7.215。

def dropout(a, p, rng):
    keep = rng.random(a.shape) >= p                 # 以概率 p 置 0
    return np.where(keep, a / (1 - p), 0.0)         # 留下的放大 1/(1-p)，期望不变

def gpt_forward(ids, P, n_layer, n_head):
    C = len(ids)
    x = P["embed.weight"][ids] + P["pos_embed.weight"][:C]       # (C, E)：token embedding + 位置 embedding
    for i in range(n_layer):
        x = block_forward(x, P, i, n_head)                        # (C, E) -> (C, E)
    x = layer_norm(x, P["norm.weight"], P["norm.bias"])           # 最终 LayerNorm
    return x @ P["unembed.weight"].T + P["unembed.bias"]          # (C, E) @ (E, V) + (V,) -> (C, V)

小结

本章从 Python 的字典出发，把“完全相等才能取值”放宽成“按相似度加权混合”，得到了软字典；写成矩阵就是 Attention，再除以 \sqrt{d}，让 softmax 的温度不随维度漂移。接着，我们给 Attention 补上了它天生缺少的两样东西：位置信息和因果掩码；用低秩分解给值矩阵减负，用多头让模型同时从几个角度看前文。最后，LayerNorm、FFN 和残差连接把这些零件装成 Transformer 块，6 个块叠起来，加上 embedding 和输出层，就是 CodeBot 的 GPT-2：11,121,640 个参数，每一个都有来处。

这个模型现在还什么都不会：它的 loss 在 6.98 左右，相当于在 1000 个 token 里瞎猜。

本章所学的内容

  • 软字典用点积衡量相似度、用 softmax 把相似度变成权重、用加权和混合各个值；点积偏爱长的键，所以 T→0 时用一个键去查，不一定取回它自己的值：遇到并列时平分，遇到方向相近而更长的键时被抢走（验证 2.1-c、验证 2.1-d）
  • 随机查询与键的点积方差约为 d；除以 √d 让 softmax 的有效温度与 d 无关，不缩放时 d 越大越容易饱和（验证 2.3-b、验证 2.3-c）
  • 语言模型按链式法则给句子打分，交叉熵是平均负对数概率，单位是 nats；均匀瞎猜的 loss 是 ln V = 6.9078（验证 2.4-b、验证 2.4-c）
  • 没有位置信息的 Attention 对顺序视而不见；CodeBot 的可学习位置表只有 256 行（行号 0–255），第 257 个 token 的位置编号 256 查不到，在 CPU 上直接报 IndexError（验证 2.5-a、验证 2.5-d，真实模型见 2.5.4 节的本地测试）
  • 因果掩码必须在 softmax 之前施加，并沿最后一维归一化；遮错轴、先 softmax 后遮挡，都会让未来漏进过去（验证 2.6-e）
  • 拆分多头要先 view 再 transpose（合并时顺序相反）；省掉 transpose 不会报错，却破坏因果性（验证 2.8-e）
  • CodeBot 的 GPT 有 11,121,640 个参数，初始 loss 约为 ln V + σ²/2 ≈ 6.98，第 3 章的实测是 6.9843；本章的 NumPy 零件拼成的 GPT 与 PyTorch 版逐个 logit 对齐（验证 2.10-a、验证 2.10-c、验证 2.10-g、验证 2.10-f）
