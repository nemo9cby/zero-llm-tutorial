第 I 部 基础篇：制作 CodeBot

第一台机器人 CodeBot 是一个会写 Python 的小语言模型。它能打招呼、按指令写几行代码、做个位数加法。动手之前，我们先看它完成后的样子，再看要把它做出来，需要哪些步骤和数据。

从这里开始，我们制作第一台机器人 CodeBot。它只有 1,112 万个参数，训练数据是 6.5 MB 的 Python 小程序，但它已经具备了 LLM 的全部要素：能续写代码，能按对话模板回答问题，还用强化学习专门练过个位数加法。

先来看结果。下面是原书作者在 Hugging Face 上发布的三个 CodeBot checkpoint 的真实回答，由本书在 CPU 上重新生成。我们用的是贪心解码（greedy decoding），也就是每一步都取概率最大的 token，所以在同样的环境下重跑，会得到同样的回答。可以在三个训练阶段之间切换。

完成后的 CodeBot 会打招呼，知道自己叫 CodeBot，能写出一个带 else 的 for 循环。可是 7+8= 它答成了 16。原书第 I 部开头展示的对话里，CodeBot 对这道题答出了 15（原书第 I 部扉页的试读，2026-10-12 查证）；我们用官方发布的 SFT 和强化学习两个 checkpoint 贪心解码，得到的都是 16。原书的对话脚本 ch03/04_chat.py 用 temperature 1.0 采样，训练本身也有随机性，书中那段对话未必能用这份 checkpoint、以贪心解码复现。这件事提醒我们：小模型的能力要用数据说话，不能只看一两段对话。I.4 节会把 81 道个位数加法全部测一遍。

I.1 开发流程

CodeBot 的开发分三步，每一步占一章：

章 主题 做什么
第 1 章 分词器 实现 BPE，把 Python 代码变成 token 的 id 序列，词表 1,000
第 2 章 模型 从 Attention 的原理出发，实现一个小型的 GPT-2
第 3 章 训练 依次做预训练、SFT、强化学习，看模型一步步变“聪明”

每章的代码最后都整理进 codebot/ 这个包：tokenizer.py、model.py、utils.py，后面的章节直接 import 它们。数据和产物在这三章之间这样流动：

I.2 预训练

预训练用的数据集叫 TinyCodes，文件是 codebot/tiny_codes.txt。它由 Hugging Face 上的数据集 flytech/python-codes-25k（MIT 许可）修改而来，原书作者在数据集 koki0702/zero-llm-data 的说明里写明了“Modified and used in the book”。整份文件 6,487,033 字节，是 21,836 个 Python 小程序，程序之间用特殊记号 <|endoftext|> 隔开（共 21,835 个），全部是 ASCII 字符。

import warnings

def parses(src):
    try:
        ast.parse(src)
        return True
    except SyntaxError:
        return False

with warnings.catch_warnings():

    import numpy as np
    import torch
    from torch.utils.data import Dataset
    src = (pp.DLFS6 / "ch03/01_pretrain.py").read_text(encoding="utf-8")
    node = next(n for n in ast.parse(src).body if isinstance(n, ast.ClassDef) and n.name == "TokenDataset")
    ns = {"torch": torch, "Dataset": Dataset}
    exec(compile(ast.Module(body=[node], type_ignores=[]), "ch03/01_pretrain.py:TokenDataset", "exec"), ns)

I.3 SFT（监督微调）

预训练之后的模型只会续写。给它 def，它接着写出一个排序函数；把问题套进对话模板交给它，它却多半一开口就输出结束记号，什么也不说。上面对话图里“只做了预训练”那一栏就是这个样子：6 个问题里有 4 个空着，剩下两个续写出了不相干的代码。

验证 I.3-a只做了预训练的模型：会续写代码，不会接话

要让它像助手一样作答，需要用“指令 → 回答”的成对数据再训练一次，这就是 SFT（Supervised Fine-Tuning，监督微调）。CodeBot 的 SFT 数据是 codebot/tiny_codes_sft.json，共 1,092 条（原书仓库没有注明来源）。内容大致有四类：寒暄和自我介绍，“写一个变量 / 循环 / 函数”这样的编程指令，“什么是左移”这样的概念问答，以及最后 81 条个位数加法。我们把整份文件附在 data/part1/ 里，在浏览器里数一数：

验证 I.3-b1,092 条 SFT 数据，最后 81 条是 1+1= 到 9+9=
sft = json.load(open("data/part1/tiny_codes_sft.json", encoding="utf-8"))
for k in (0, 360, 540, 1091):
    print(f"#{k:<5} {sft[k]['instruction']!r:30} → {sft[k]['response'].splitlines()[0]!r}")
print(f"共 {len(sft):,} 条；回答长度的中位数 {np.median([len(x['response']) for x in sft]):.0f} 个字符；"
      f"多行的回答（通常是代码）{sum(chr(10) in x['response'] for x in sft)} 条")
full, rest = divmod(len(sft), 32)                     # DataLoader 不丢弃最后不满的 batch

def test_sft_and_grpo_batches_follow_dataloader_cycle(dlfs6_path):
    """ch03/03_sft.py 与 09_grpo.py 都用 cycle(DataLoader(dataset, batch_size=32, shuffle=True))：
    DataLoader 不丢弃最后不满的 batch，cycle 从第二个 epoch 起按第一个 epoch 的顺序原样重放。"""
    from collections import Counter
    from itertools import cycle
    import torch
    from torch.utils.data import DataLoader
    for rel in ("ch03/03_sft.py", "ch03/09_grpo.py"):
        src = (pp.DLFS6 / rel).read_text(encoding="utf-8")
        assert "DataLoader(dataset, batch_size=batch_size, shuffle=True)" in src and "cycle(dataloader)" in src, rel
        assert "drop_last" not in src, rel
        h = pp.script_hparams(rel)
        assert (h["batch_size"], h["max_iters"]) == (32, 500), rel
    n_sft = len(json.loads((pp.DLFS6 / "codebot/tiny_codes_sft.json").read_text(encoding="utf-8")))

    def batches(n):
        torch.manual_seed(0)
        it = cycle(DataLoader(list(range(n)), batch_size=32, shuffle=True))
        return [next(it) for _ in range(500)]

    sft = batches(n_sft)                                         # 1,092 = 34 × 32 + 4：每个 epoch 35 个 batch

    grpo = batches(81)                                           # 81 = 32 + 32 + 17：每三轮过一遍
    assert [len(b) for b in grpo[:6]] == [32, 32, 17, 32, 32, 17]
    assert Counter(len(b) for b in grpo) == {32: 334, 17: 166} and sum(len(b) for b in grpo) == 13_510

I.4 强化学习

有意思的是，那 81 道加法题明明都在 SFT 数据里，SFT 把每道题都看了十四五遍，之后的 CodeBot 却只答对了其中 44 道（54.3%）。为什么连练过的题都答不对？3.4.2 节会给出答案。光照着标准答案模仿还不够，第 3 章用强化学习（reinforcement learning）继续训练：每道题让模型自己回答 8 次，答对得 1 分、答错得 0 分；比同一道题的平均分高的回答被鼓励，低的被抑制。打分规则就是下面这个函数，它取回答里最后一个整数，和正确答案比较：

这个算法叫 GRPO（Group Relative Policy Optimization，组相对策略优化），“组”指的就是同一道题的 8 个回答。训练按“轮”进行：每一轮先为一个 batch 的题目生成回答，再用这批回答更新两次参数，一共 500 轮。超参数写在脚本里：

import re

def calculate_reward(ground_truth, response):     # 与 ch03/09_grpo.py 第 64–72 行的判定相同
    matches = re.findall(r"(-?\d+)", response)
    return 1.0 if matches and int(matches[-1]) == ground_truth else 0.0

correct = {}
for name in ("sft", "grpo"):
    answers = rec["models"][name]["addition_greedy"]
    correct[name] = {q for q, a in answers.items() if calculate_reward(int(q[0]) + int(q[2]), a) > 0}
    print(f"{name:4} 答对 {len(correct[name])} / 81（{len(correct[name]) / 81:.1%}）")
fixed, broke = correct["grpo"] - correct["sft"], correct["sft"] - correct["grpo"]
print(f"强化学习修好了 {len(fixed)} 道，弄坏了 {len(broke)} 道：{sorted(broke)}")
assert (len(correct["sft"]), len(correct["grpo"])) == (44, 67)
assert (len(fixed), len(broke)) == (29, 6) and "7+8" not in correct["grpo"]

这还不是 GRPO 的上限。本书在本机的 RTX 3060 Ti 上原样重跑了原书的强化学习脚本（运行记录 codebot-3060ti），500 轮后是 86.4%。原书脚本在每轮更新时，让模型停在开着 dropout 的训练模式，而用来对比的旧模型是关着 dropout 的。我们只在更新之前加了一行 model.eval()，让两边都关掉 dropout，从同一次运行的 SFT checkpoint 出发重跑（运行记录 codebot-grpo-evalfix-3060ti）：第 51 轮就到了 98.8%，从第 131 轮起 81 道全对。

注意这 81 道题既是训练题，也是考试题

原书的 GRPO 脚本每 10 轮测一次准确率，用的正是训练时的这 81 道题（上图也是）。所以 82.7% 是训练集上的成绩，不能说明模型学会了“加法”这件事本身；100% 也只说明它把这 81 道题练熟了。对于一个只有 81 道题、可以穷举的玩具任务，这样做可以理解；但读论文或自己做实验时，要分清“训练中看到的分数”和“在留出数据上的评测”。

本部要点

CodeBot 是全书的基本功。它的数据只有 6.5 MB，模型只有 1,112 万个参数，却完整地走过了分词器、模型、预训练、SFT、强化学习这条路。完成后的 CodeBot 会打招呼、会写简单的代码，个位数加法也练到了八成以上的正确率；修掉一个 dropout 的问题后，81 道全对。但这些都是在训练题上测出来的。

本部所学的内容

  • 官方 CodeBot checkpoint 会自我介绍、会写循环，但两个 checkpoint 都把 7+8= 答成 16（验证 I-a）。
  • TinyCodes 有 21,836 个程序；开头 500 个里有 85 个不是合法的 Python，整份语料是 11.1%（验证 I.2-a、验证 I.2-b）。
  • 九成程序不超过上下文长度 256 个 token，但训练窗口是从首尾相连的语料里任意截取的，平均跨过两个多程序边界；预训练把 267.7 万 token 的语料看了 61 遍（验证 I.2-c、验证 I.2-d）。
  • 只做预训练的模型会续写代码，却不会接话；SFT 数据有 1,092 条，最后 81 条正是 1+1= 到 9+9=；500 步共读 15,608 条，约 14.3 遍（验证 I.3-a、验证 I.3-b）。
  • 强化学习把加法的正确数从 44 提高到 67，修好 29 道、弄坏 6 道，而且是在训练题上测的（验证 I.4-a）。
  • 原书脚本更新时开着 dropout；加一行 model.eval() 重跑，第 51 轮的正确率从 60.5% 变成 98.8%，第 131 轮起 81 道全对（验证 I.4-b）。
